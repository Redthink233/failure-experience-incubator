# 01 产品定义（PRODUCT DEFINITION）

> 本文档为 S00-02 阶段待填写主文档。下方标注「已锁定」的内容来自 S00-01 人工关键决策（见 DECISIONS.md），已在 2026-09-17 收口，后续不得重开；标注「待填写」的内容仍待 S00-02 完成。

## 1. 一句话定位

> 待填写（2026-09-16 历史提案，已被 D1 校正）：面向大学生科研 / 创新比赛 / 项目团队，把零散的失败尝试转化为可积累、可检索、可关联、可复用的知识资产。

- **已锁定（D1 / R5 / R6）**：面向**高校科研与创新项目中的个人执行者**（以大学生为主要用户），将失败尝试低成本结构化沉淀，并利用历史尝试进行相似经验检索、证据化经验提炼和下一步可验证假设孵化。
- 对外口径要求（R5）：不得表述为"全新产品品类"；统一表述为"围绕失败尝试建立『结构化沉淀—跨记录复用—证据约束—下一轮假设孵化』的完整闭环"。
- 注：原文中"项目团队"不再是 V1 第一用户（D1）；团队能力不属于 V1（D3）。

## 2. 要解决的问题

- **已锁定（正式锁定的核心问题定义，2026-09-17）**：高校科研与创新项目执行者在一次尝试未达到预期后，缺少低成本的方法，把当时的目标、条件、方案、结果与判断依据转化为可复用经验；即使曾经记录过，后续面对新问题时也很难判断旧经验是否适用，最终导致重复试错，并且难以利用过去的失败决定下一步值得验证的方向。
- 待填写：失败经验通常以什么形式散落（聊天记录、记忆、草稿纸），为什么难以复用
- 待填写：当前用户失败后的典型行为路径与痛点

## 3. 目标用户

- **已锁定（D1）**：主要用户 = 高校科研与创新项目中的个人执行者。典型包括：科研训练项目成员、大学生创新项目成员、科研/创新竞赛中的实际执行者、毕业设计或课题中的实验执行者、需要持续进行实验/调参/方案验证与迭代的个人。
- **核心判断标准（D1）**：不是其是否属于某个团队，而是**他本人是否正在直接执行实验、方案、参数调整、技术尝试或验证任务**。
- 待填写（历史）：主要用户画像（大学生科研团队 / 比赛团队等）——"项目团队负责人"与"整个团队"不作为 V1 第一用户（D1）。

## 4. 核心价值

- **已锁定（D4）价值分层**：
  - **即时价值** —— 帮助用户快速复盘当前未达到预期的尝试，并判断下一步应该验证什么。
  - **长期价值** —— 将一次次失败尝试逐渐沉淀为可检索、可比较、可复用的个人经验资产。
- **已锁定（D9）核心闭环**：用户自然语言输入 → AI 结构化解析 → 用户确认 → 候选原因 → 保存 → 检索相关历史 Attempt → 展示相似点与差异点 → 提炼可复用经验 → 生成可验证新假设 → 假设可追溯到历史证据。
- 待填写：可积累 —— 经验结构化沉淀
- 待填写：可检索 —— 相似失败可被找到
- 待填写：可关联 —— 失败与失败之间建立联系
- 待填写：可复用 —— 指导下一步验证方向

## 5. 与竞品 / 替代方案的差异

- **状态：`TO_VALIDATE`（R4）**。以下内容不得作为客观事实使用，需进行实际竞品调研并提供依据后方可进入对外材料：
  - 待验证：笔记软件（Notion / 语雀）、AI 聊天记录、实验室例会为什么没解决这个问题
  - 待验证：各通用 AI 助手/RAG 产品"做不到什么""有什么缺陷"
- **已锁定（R6）产品创新来源**：V1 优先保证完整闭环成立；创新性来自——历史失败真实参与下一轮推理、跨 Attempt 比较、事实与 AI 推断分离、候选经验有证据来源、新假设可追溯、失败经验真正参与下一轮行动。**不得以堆叠 Agent / 模型数量 / 知识图谱 / 向量数据库 / 多模型架构 / 炫技技术替代产品价值**。

### 1. 交互成本口径（D-016 / D-017 / D-018 / D-023）

- **产品的提问是"按需发生"的，不是流程的一部分**：信息已经说清楚的用户**不会被追问**（**0 个追问问题为正常且期望的结果**）；追问**最多 3 个关键追问问题**（**总量上限；计数单位是"问题数"，不是对话轮次** —— **2026-09-19 口径校正**，见 `DECISIONS.md`《第二批定向校正》），**每个关键追问问题只针对一个真正影响后续机制的高价值缺口**，用户可随时「跳过 / 不知道 / 就这样继续」。
- 与 §4 即时价值的关系：这是 [D4]「不以填写档案为心智 + 低成本复盘」在交互层的具体兑现。

### 2. 可信度口径（D-019 / D-020 / D-024 / D-025）

- **不给"伪精确"**：相关性以**可解释的匹配理由**呈现，**不显示数字相似度**。
- **不臆测**：字段为「未知 / 未提供」时**不参与相关性判断**，并明确标注"该维度未比对"；**不得因双方都未知而判为相似**。
- **不混淆来源**：用户的原始回答与 AI 的归纳**分别标记**（`Fact` / `Extraction`），不互相冒充。
- 与 §5 产品承诺的关系：这是 [D7]「事实与 AI 推断分离」在交互层的具体兑现。

### 3. 经验成立口径（D-021 / D-022 / D-026）

- **"被保存"与"成为可复用经验"是两件事**：一次尝试可以低成本保存；但一条经验要成立，必须具备**明确命题 + 已知适用范围 + 可追溯证据 + 用户显式接受**。
- **经验只在用户读对照结果的当下提炼**（第 ⑧ 步），**不后台堆积候选**。
- **`accepted` 不等于"已被证实"**：§4 / §5 的对外表述**不得暗示"系统验证过该结论"**。

### 4. 未变更项（明确记账）

- §1 定位口径（R5）**未变**；§3 目标用户（D1）**未变**；§5 竞品比对仍为 **`TO_VALIDATE`（R4）**，**未因本批获得任何新证据**。

### 1. 孵化输出口径（D-027 / D-028 / D-029 / D-030）

- **孵化产物是有依据的、可核对的、可拒绝的**：下一轮方向以**结构化信息结构**给出（依据 / 引用的历史记录 / 改变什么 / 保持什么 / 观察什么 / 支持与反驳条件），**每条必须能挂到用户自己的历史记录**，并且**用户可逐条接受或拒绝**。
- **数量由证据说话，不凑数**：一次给出 **1–2 条**；**证据只支持一个方向就只给一条**；**不给"看起来丰富"的空方向**。
- **没有依据就不假装有依据**：若历史无法真正锚定当前判断，输出会被明确定位为「**模型通用建议 / 非你的历史经验依据**」，**不进入"基于你的历史"的口径**，也不计入验收结果。
- 与 §4 / §5 的关系：这是 [D7]「推断不得伪装成事实」+ R6「闭环优先」在孵化层的具体兑现。

### 2. 可信度口径补充：不设"证据等级"（D-035 / D-036 / D-037）

- **不向用户输出伪精确的"证据强度"**：不出现「证据强度」及低 / 中 / 高等级、分数、星级、百分比；只如实呈现 **实际证据条数**、**条件是否完整（含未比对维度）**、**是否存在冲突**、**哪些支持、哪些反驳**。
- **档位不是等级**：`N_检索` 三档（0 / 1 / ≥2）只表示"结构上可不可能产出某类输出"，**不代表可信度高低**；**证据条数与条件完整度是两个独立维度**。
- **不设"攒够多少条才解锁"的机制**：**不存在"补录 3 次即可""N 条后解锁""还差 N 条"及进度式表达**；补录**不是**使用产品的前置条件。
- 与 §5 产品承诺的关系：这是 [D7] 与 [R1]「不做价值量化」在展示层的具体兑现。

### 3. 承诺边界口径（D-029 / D-034）

- **"存下历史才有输出"不是产品承诺**：没有相关历史时，产品仍提供完整的**记录与复盘价值**（理解这次没达到预期的原因、明确下一步要观察什么），并**明确说明这次为什么给不出"基于你历史"的方向**；**该状态不是故障**。
- **"基于你的历史"是有条件的**：只有在**存在真实、可追溯的历史锚定**时，产品才会使用该口径；**"有 1 条相关记录"只是最低来源条件，不是产出保证**。
- 对外演示与验收**使用明确标注的示例数据**，**不以"临时补录"凑出效果**。

## S00-02 第四批决策同步（2026-09-19，`CONFIRMED`，**仅必要同步**）

### 1. 经验成立口径补充：晋升条件不可被用户操作绕过（`D-039` / `D-040`）

- **"接受"是用户的权利，"满足条件"不是用户的选项**：用户可以**接受、修改、拒绝、撤销接受**一条候选经验；但**只有已满足 `E1`–`E4` 的候选经验**，用户显式接受后**才能满足 `E5`** 并成为可复用经验。**不存在"手动晋升 / 强制晋升"这类机制。**
- **改过内容就要重新确认**：一条经验的内容（结论 / 适用范围 / 引用清单 / 判断依据）被修改后，**回到候选状态并重新检查条件**，需要用户**再次显式接受**；**只做展示性 / 元信息修改不触发退回**。
- **撤销 ≠ 否定**：撤销接受表示"**我暂时不再把它当作可复用经验**"，**不表示"这条结论不成立"**；撤销后**不删除内容**、**不改来源类型**。

### 2. 承诺边界口径：假设不是经验（`D-041` / `D-042`）

- **"下一步方向"与"可复用经验"是两类东西**：产品给出的**下一轮待验证方向**（`History-grounded Hypothesis` / `Model Suggestion`）**指向未来**，**永远不会直接变成"你的经验"**；**只有用户真的去执行、产生一次新的正式尝试、并被后续主链提炼后**，才可能形成经验。
- **"保存一条模型建议"不等于"接受它"**：模型建议**可以保存以便回看**，但**保存 ≠ 接受 ≠ 采纳 ≠ 确认**；它**始终不是你的历史经验依据**、**不计入证据数量**、**不被追溯为历史证据**。
- 与 §4 / §5 的关系：这是 [D7]「推断不得伪装成事实」+ R6「闭环优先」在**对象生命周期**上的兑现。

### 3. 数据管理口径：可归档、不删除（`D-043`）

- **产品提供"归档"而不是"删除"**：归档是**用户主动、可撤销**的动作；**归档后的记录仍然存在、只读可查看**。
- **历史结论不会因归档而失效**：**归档不静默断裂证据链、不追溯撤销既有结论、不自动改写历史**；旧引用**继续存在并明确标注「来源已归档」**。
- **系统不会替你判定"这条不值得留"**：**不会因记录被认为低价值 / 普通错误 / 时间久远而自动归档或删除**；**归档也不构成任何价值判断或质量信号**。
- 与 §4 长期价值的关系：这是"**可积累**"承诺的必要前提 —— **积累的前提是不可静默丢失**。

### 4. 体验口径：检索按需自动发生，时间不决定相关性（`D-044`–`D-048`）

- **"刚记录完就自动帮你看历史"**：一次正式尝试**保存成功后自动检索**相关历史（**这是主链首次自动触发**）；**用户不需要知道要点击"查找相关历史"**。记录被修改时，产品**明确提示"先前的历史比较结果可能不再适用"**，并**由用户显式发起重新检索**。
- **"新的"不等于"更相关"**：**时间不会影响"这条记录是否相关"**；**不存在"最近一次"被默认选中**；时间**只在相关性已经接近时**辅助排序。
- **"先看到 3 条"不等于"只有 3 条证据"**：首屏默认展示 3 条**只是阅读负荷控制**；**可以展开看到全部**；**内部相关记录集合不因首屏显示数量而截断**；**展示条数不代表证据质量或可信度**。
- **"随便说一句也能记"**：第 ① 步唯一门槛是**存在非空、非纯空白的输入** —— **不设最小字符数**（`"失败了"`、`"还是不行"` 都是有效的开始）；**解析或保存的技术性失败可重试，不以次数或时间设门槛**。
- **"没有依据就不编"**：当无法推断失败原因时，产品**明确说"当前依据不足，暂不推断原因"**，而**不会为了凑数生成低置信的原因**；**未处理的候选原因只以"候选"存在，不会被当作已确认的判断复用**。
- 与 §4 即时价值的关系：这是 [D4]「低成本复盘 + 不伪装」在**记录与检索入口**上的具体兑现。
