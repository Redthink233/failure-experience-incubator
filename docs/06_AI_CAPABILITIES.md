## S00-01 决策同步（2026-09-17）

> 本节仅记录已被人工决策锁定的 AI 能力边界，不构成完整能力设计。详细定义进入 S00-02。

### 1. 三层内容边界（D7，最高优先级约束）

系统必须严格区分以下三类内容，任何 AI 能力设计都不得违反：

| 层级 | 定义 | AI 权限 | 示例 |
|---|---|---|---|
| `Fact｜用户事实` | 用户明确提供的信息 | AI **不得修改其事实含义** | 验证集准确率为 72% |
| `Extraction｜AI 结构化解析` | AI 基于原始输入做的整理、归纳、字段抽取 | 可自动生成，**必须允许用户修改** | 实际结果：模型未达到预设的 80% 准确率目标 |
| `Inference｜AI 推断` | 可能失败原因、跨记录规律、因果判断、经验结论、新假设、下一步方案 | 可生成，但**必须标记为 AI 推断 / 候选结论 / 待确认 / 待验证，不得伪装成用户事实** | 可能因为数据分布偏移 |

补充约束：

- **所有跨记录产生的新判断统一属于 `Candidate Insight`，不是 Fact**。合法链路：`多条 Attempt → AI 比较 → Candidate Insight → 用户确认 / 后续验证`；**禁止**：`多条记录 → AI 判断 → 直接变成事实`。
- **N = 1 的单次失败不支持得出"一般性无效"结论**；单条 Attempt 最多支持"在当前记录的具体条件下，该方案没有达到预期"，不得自动扩大为"方法 X 无效"。

### 1. `Inference` 确认边界（D-014 / Q08，正式记录）

S00-01 的"三层内容边界"在本批被精确化：**`Inference` 必须再分为两类**，确认要求不同。

| 类别 | 范围 | 确认要求 | 升级限制 |
|---|---|---|---|
| **A｜展示型 `Inference`** | 相关性判断、相似点、差异点、检索排序理由、对照价值判断、置信提示、比较维度判断 | **不要求用户逐条显式确认**；必须标记为 AI 判断；用户可反馈"不相关 / 不同意"；**未反馈不得视为已确认** | **不得伪装为 `Fact`**；**不得自动升级为 Experience Asset**；**不改变持久化业务状态** |
| **B｜决策型 / 持久化 `Inference`** | 结果状态、候选失败原因、`Candidate Insight` 是否被接受、Experience Asset、`History-grounded Hypothesis`、其他会被后续作为正式决策依据复用的判断 | **必须由用户显式接受或拒绝** | 接受后状态可为 `accepted`，但**来源仍为 `Inference`，不得升级为 `Fact`**；**不得使用"已证实"等措辞** |

**核心判断原则**：是否需要用户显式确认，**不只取决于"是不是 AI 推断"**，而取决于该推断 ① 是否改变持久化业务状态；② 是否会被后续作为决策依据复用。

**禁止表述**：文档与实现中不得出现"所有 `Inference` 都必须由用户确认"这类一刀切规则（与 [D9] 第 ⑦ 步冲突）。

### 3. `Insight` 与 Experience Asset（D-015）

- AI 产生的判断由 **`Insight`** 对象承载，状态至少 `candidate` / `accepted` / `rejected`（未来可扩展 `superseded` / `invalidated`）。
- **`accepted` 只表示"用户接受该 Insight 作为当前可复用经验"，不表示"该结论已被客观证实"。**
- **Experience Asset = accepted Insight 的产品视图**，**不是独立实体**；其来源类型恒为 `Inference`，**不得转为 `Fact`**。
- AI 能力的输出格式与文案必须与上述状态一致，**不得出现"已确认 = 已证实"的暗示**。

### 4. 录入范式对 AI 能力的要求（D-011）

- 入口为**自然语言输入**；AI 必须先做结构化解析，再由用户修改 / 确认，**不得要求用户先填表单**。
- 解析输出必须按 D-013 的 5 组字段框架组织（含"重要但允许未知"组，缺省时显式表达为「未知 / 未提供」）。

| **生成数量** | **1–2 条**，数量 = 独立可验证方向数（**不由 `N_检索` 决定**）；**禁止凑数 / 近义改写 / 固定两条 / 3 条及以上** | **D-028** |
| **0 条输出** | 必须给出原因类别：**A `evidence-insufficient` / B `not-verifiable` / C `not-formable`**；**不得把 B / C 写成"历史证据不足"** | **D-028**、**D-029** |
| **证据条数** | 判档用 `N_检索`；**显示与 ⑩ 追溯用 `N_引用`**（只计 grounding / 支持 / 反驳；**纯上下文不计入**；**G4 计入**；**`Unknown` 不得单独承担支持 / 反驳方向**） | **D-035** |
| **N=1** | 必须表达「单来源（`N_引用 = 1`），证据有限」+ 限定当前具体条件 + **禁止一般化** | **D-029** |
| **冲突证据** | **不得择一**（不选多数 / 最近 / 条件更全者）→ **并列 + 定位差异条件 + 可转化为条件区分型方向**；无法定位时**允许为空但须显式说明** | **D-029** |
| **条件缺失** | 允许生成但**强制收窄表述** + 标注"该维度未比对" + **不得编造条件**；证据条数与条件完整度**不得相互替代** | **D-029** |
| **`Model Suggestion`** | **整体标注**「模型通用建议 / 非你的历史经验依据」；**独立区域、不得占据历史依据型输出的位置**；**可选、数量另计、不计入 ⑨⑩ 验收**；**不得升级为 `History-grounded`** | **D-030**、**D-028** |

### 2. A5 的判据能力（D-032 / D-033 / D-031）

- **不强制数值阈值**；优先顺序：引用用户已有阈值 → 使用**可区分的定性判据** → **AI 可提候选阈值 / 判据（须标 `Inference`）** → **用户显式接受后生效**（**接受后仍为 `Inference`**）。
- **可验证性判定依据 = 是否存在可观察、可区分的支持 / 反驳判据**（**与是否有数字无关**）；「效果更好」类**不合格判据等同缺判据**。
- **候选指标 / 判据必须与用户提供的信息分列**；未接受前**不得**显示为"已确定判据"、**不得**作为后续依据复用；用户可自行定义 / 修改 / 拒绝 / **跳过且不阻断**。
- **可达性护栏**：候选指标须落在用户已有数据 / 能力可及范围内；需要用户不具备的测量条件时必须给出替代观察方式或标注"需确认是否可测量"。
- **成本**：只作可选上下文；只来自"用户历史已记录 / 用户当前提供"；**无数据标"未提供"**；**不得估算为事实**。

### 3. A4 / A6（经验与冷启动）的正式行为要求

- **E2 / E3 不满足**（**D-038**）：`Insight` **保持 `candidate`** + 「当前还不足以成为可复用经验」+ **缺什么 / 为什么重要 / 如何补充**；**不得静默丢弃 / 隐藏 / 自动补字段 / 自动改写结论 / 自动晋升**；「如何补充」属**展示型 `Inference`**，**不得绕过 E5**。
- **冷启动**（**D-034**）：按 `N_检索` 决定可产出对象；`N_检索 = 0` 时**第 ①②③④⑤ 步必须完整可用**；**补录不得成为使用前置条件**、**不得有进度条 / 解锁式 / 固定数量门槛**；**"≥1 条相关且可引用"只是必要条件**，真正生成仍须满足 grounding、可验证判据、不属 `not-verifiable` / `not-formable`、N=1 不一般化。
- **档位语义**（**D-035**）：`N_检索` 三档 = **结构可及性 / 来源结构档位**，**不是可信度等级**；`N` 是**必要条件不是充分条件**；`N ≥ 2` 只表示跨记录比较"**可能出现**"。
- **空态**（**D-036**）：`N_检索 = 0` 必须区分"历史库为空"与"本次无相关"，**不得共用同一文案**、**不得说"你没有历史记录"**、**不得呈现为系统错误**。

### 4. 本批确立的 AI 行为红线（第三批）

- **不得**在第 ⑨ 步输出中使用 `Candidate Insight` 命名，或把 `Model Suggestion` 当 `Candidate Insight`（D-027 / D-022）
