## §A Retrieval 总览

### A.1 检索在 `D9` 十步中的位置与边界

```
① NL 输入 → ② AI 解析 + 缺口检测 + 追问 → ③ 用户整体确认 → ④ AI 候选原因（0..n）
      → ⑤ 用户确认后保存 ──────────────┐
                                        │ ★ 保存成功 = ⑥ 的唯一自动触发条件（同步、幂等）
                                        ▼
        ┌───────────────────────────────────────────────────────────────┐
        │ ⑥ 检索（Retrieval）—— 本文件核心                              │
        │   · 单点过滤 → 候选池                                          │
        │   · 逐候选 × 逐 Level A 维度 三态判定                          │
        │   · 命中集合 / 未比对集合                                      │
        │   · Level C 辅助排序 → 全序                                    │
        │   · N_检索（集合大小）                                          │
        │   · 落为「当前有效 Retrieval Derivation」（至多 1 条）          │
        └───────────────────────────────────────────────────────────────┘
                                        │
        ┌───────────────────────────────▼───────────────────────────────┐
        │ ⑦ 比较解释 —— 只解释，不判定                                   │
        │   · 相似点 / 差异点（dimension_key 必须落在 Level A 四维度内）  │
        │   · 「为什么相关」可解释理由（不得出现数值）                    │
        │   · 未比对维度清单（**真源 = ⑥，⑦ 只透传呈现**）               │
        │   · 首屏 3 条 / 可展开（阅读负荷控制）                          │
        └───────────────────────────────────────────────────────────────┘
                                        │
       ⑧ Candidate Insight（`candidate`，`Inference｜decision`）
       ⑨ Hypothesis（`grounded` / `model`，`Inference｜decision`）
       ⑩ 证据追溯（`EvidenceRef` 单一集合 → 清单 + `N_引用`）
```

### B.2 明确**不纳入** Level A 的字段（防误用清单）

| 逻辑字段路径 | 归类 | 理由 |
|---|---|---|
| `result_status` | **不参与准入** | 四态枚举（`Failed` / `Partial` / `Success` / `Unknown`），来源恒为 `Inference｜decision`。**若参与准入会与 `TC-48` 冲突**（`Unknown` 记录必须仍可承担 `grounding` / `context`、**不得从证据清单中删除**）；且把"都没成功"当作相关问题，正是 `D-019` 想避免的"平铺维度污染"变体。其合法用途 = ⑨ 的 `support` / `contradict` 角色判定（§G.5）+ 出口路由输入 |
| `expected_result` | **不参与准入** | 与 `goal` 语义重叠；且属"允许缺省"高频 `unknown` 字段，纳入会使该维度大量落入"未比对"，**不增加可解释性**（保守纳入更少字段 = 更强的"不得凭空制造相关性"保证，`D-025` 精神） |
| `judgment_basis` | **不参与准入** | `D-019` Level A 未列入；属 ⑧ / ⑨ 的依据材料与 P2 缺口 |
| `key_parameter` | **不参与准入** | 同上（属"重要但允许未知"，非"问题—方案—条件—现象"四要素之一） |
| `version_env`（版本·环境） | **Level B** | `D-019` 明列为 Level B |
| `failure_tag`（用户标签） | **Level B** | `D-019` 明列为 Level B（用户标签） |
| `project_id`（`Project`） | **Level B** | `D-019` Level B；**尤其不得作准入过滤**（`TC-84` / `AC-20`） |
| 「语义相似」 | **Level B（仅解释措辞）** | `D-019` Level B 明列；**其任何数值化表达一律禁止**（`D-020` / `TC-41`） |
| `candidate_cause` | **不参与** | 决策型 `Inference`，且 `decision_state = unresolved` 项**不得进入比较输入**（`TC-13`） |
| `insight_*` / `hypothesis_*` | **不参与** | 属 `Insight` / `Hypothesis` 对象的内容条目；`Insight` 即使 `accepted` **也不得承担 grounding**（`TC-51`） |
| `followup_question` | **不参与** | 系统生成的 `Inference｜display` 问题条目 |
| `followup_user_answer` / `followup_ai_extraction` / `occurred_at` / `note` / `cost` / `raw_text` | **不直接参与准入** | 见 B.2.1 的**归属依赖** |

#### B.2.1 🔴 追问产物与"条件"维度的归属依赖（必须由 Integrator 明确）

追问答案按 `D-024` **双层落库**（用户原话 → `Fact`；AI 归纳 → `Extraction`）。若该答案在语义上补齐的是"条件"缺口，则它属于 `level_a.condition` 的**比较输入**。

⚠️ **风险点**：若 `TQ18` 的"字段组 ↔ 条目映射表"把追问答案**仅**登记在 `followup_user_answer` / `followup_ai_extraction`，而**不归入 `condition` 字段组**，则 **`level_a.condition` 维度会漏检追问补齐的条件值**，导致命中维度被低估、`N_检索` 与"为什么相关"理由失真。

✅ **本文件对 `TQ18` 的接口要求（`PROPOSED`）**：**凡语义上属于某一 Level A 维度的内容条目（不论其由原文抽取、追问回答、用户校正或用户补录产生），都必须通过 `TQ18` 映射表归入该维度的比较输入**。若 Integrator 采用其它归属方案，**必须同时给出"该维度的比较输入取值规则"**，否则 §B.1 的映射不可实现。

### B.3 判定所用的 `presence_state` 语义（与 `result_status = Unknown` 严格区分）

| 记法 | 含义 | 性质 | 对 Level A 的作用 |
|---|---|---|---|
| `presence_state = unknown` | **该维度未提供 / 未知** | **值的存在性状态** | ❌ **不参与比对**；进入未比对集合；**双方都 unknown 不得判为相似** |
| `result_status = Unknown` | **结果尚未确定**（`D10` 四态之一） | **一个已由用户确认的取值**（决策型 `Inference`） | ✅ 参与（可 `grounding` / `context`；**不得单独**承担 `support` / `contradict`） |

> 🔴 二者**命名相近、语义正交**；**不得合并为一个字段、不得互相推导**（S03-B §H.2）。
> 🔴 物理表示（哨兵值 / `NULL` + 标记位 / 其他）**不在本文件锁定** → `TQ08`（Integrator）；本文件只依赖 §B.3 前两列语义。

## §C 命中集合 / 未比对集合的结构（检索派生结果）

### C.1 派生结果的逻辑结构（`PROPOSED` → 与 `S03-B` §C.10 对齐）

```
RetrievalDerivation（当前有效 · 每 Formal Attempt 至多 1 条）
│
├── derivation_id
├── source_attempt_id            ← 唯一键（一个 Attempt 至多一条"当前有效"）
├── generated_at                 ← 技术元数据：用于覆盖替换的次序；不出界面、不可选择
│
├── n_retrieval                  ← N_检索：命中集合大小（不受首屏截断）
├── hit_level_a_dimensions[]     ← 命中维度集合（全局 = 各候选命中子集的并集）
├── uncompared_dimensions[]      ← 未比对维度集合（全局：源侧 presence_state = unknown 的维度）
│
├── candidate_entries[]          ← 候选条目（每条 = 一条相关历史 Formal Attempt）
│     └── 每条携带：
│           ├── attempt_ref                        ← Formal Attempt ID（禁止指向 Draft）
│           ├── matched_level_a_dimensions[]       ← 该候选命中的 Level A 维度子集（非空）
│           ├── dimension_states[]                 ← 该候选 × 四维度的三态（见 C.3）
│           ├── level_b_context                    ← Level B 解释上下文（只解释）
│           ├── explanation_input                  ← ⑦ 的比较解释输入（投影，非新对象）
│           └── order_key                          ← Level C 辅助排序键（可空）
│
├── fold_hint                    ← 首屏呈现参数：首屏条数 + 「界面中可继续查看的记录条数」
│
└── (子结构，与主记录同生命周期，整体替换)
      ├── comparison_points[]     ← ⑦ 产物：attempt_ref / point_kind(similar|different) / dimension_key / text
      ├── relevance_reasons[]     ← ⑦ 产物：attempt_ref / reason_text
      └── pair_feedback[]         ← ⑦ 产物的展示型反馈（同 S03-B §C.4.5 硬规则）
```

**关于 `uncompared_dimensions` 的粒度（重要对齐项）**

| 层 | 内容 | 真源 |
|---|---|---|
| **全局**（派生结果字段） | 源 `Attempt` 侧 `presence_state = unknown` 的维度 —— 对**全部**候选都不可比对 | **⑥** |
| **每候选**（`candidate_entries[].dimension_states`） | 源侧 unknown ∪ **该候选侧** unknown | **⑥** |
| **呈现**（⑦ / UI） | 逐候选标「该维度未比对」；全局清单同时可见 | ⑦ **只透传**，**不得重算** |

> 🔴 **不得出现第二个口径**：未比对维度集合的**唯一计算点 = ⑥**；⑦ 与 UI 只在派生结果基础上呈现（否则会产生"两处判定分叉"）。
> 🔴 **`uncompared` 既不贡献命中，也不取消候选资格**：它只表示"该维度未比对"（`TC-40` / `AC-22`）。

### C.2 命中集合（hit set）

- **全局 `hit_level_a_dimensions`** = 全部候选命中子集的并集（对应契约 §9 第 ⑥ 步"命中的 Level A 维度集合"）。
- **每候选 `matched_level_a_dimensions`** ≠ ∅ —— 这是该候选进入集合的**充分且必要**条件（§D.1）。
- **同名维度在不同候选下状态可不同**（例如维度 D 对候选 1 是 `matched`、对候选 2 是 `uncompared`）—— 因此**必须逐候选记录**。
- **不得**把命中集合表述为"相关度排序依据"或"证据强度"（`TC-49` / `D-037`）。

### C.3 维度三态（唯一 → 见 §D.2 判定规则）

| 状态 | 语义 | 是否发布 | 用途 |
|---|---|---|---|
| `matched` | 双方均 `present`，且判定为**构成可比对重叠** | ✅ 进入 `matched_level_a_dimensions` / 全局 `hit_level_a_dimensions` | 准入判据 + ⑦「为什么相关」材料 |
| `compared_not_matched` | 双方均 `present`，但**明确不重叠** | ❌ **不发布** | 仅供 ⑦ 生成 `point_kind = different` 的差异点；**不得计入任何数字、不得进入理由、不得作为相关依据** |
| `uncompared` | **任一方** `presence_state = unknown` | ✅ 进入未比对集合 | 「该维度未比对」标注；**不得**参与命中判定；**双方都 unknown 不得判为相似** |

> 🔴 **`compared_not_matched` 是纯内部中间量**：它**不新增产品机制**，只是"双方都有值但不重叠"这一事实的表示；对外只暴露 `TC-37` 要求的**两份集合**。

### C.4 与证据体系的关系（防越界红线）

| # | 红线 | 依据 |
|---|---|---|
| C-1 | **派生结果不属于证据**：`Retrieval Derivation` **永不**成为 `EvidenceRef.target`；**不进 ⑩**；**不计入 `N_引用`**；**不得**作为 grounding | 契约 §5.1 / `TC-51` / S03-B §C.10 R-3 |
| C-2 | `Insight.comparison_ref`（指向派生结果）**只是 `E4` 的条件项**，**非硬门槛、不计入 `N_引用`、不进 ⑩** | `D-021 E4` / S03-B §C.6 |
| C-3 | **不建第二套引用体系**：不新增引用对象 / 引用表 / 引用集合 / 第五个 `role`；`reasoning_input_refs` **不得**被实现为 `EvidenceRef` 的第五个 `role` | 契约 §5.2 第 12 条 / S03-B §E.5 / S03-C §C.4 |
| C-4 | 派生结果**不得携带**任何数值化相似度 / 分数 / 星级 / 百分比（含内部列） | `TC-41` / S03-B §C.10 R-4 |
| C-5 | 派生结果**不得**引入版本 / 序号列（**含技术层隐性版本列** —— 即使不出界面，也会诱导"版本选择 / 回滚"实现） | `D-040` / S03-B §H.3 第 5 条 |

## §D Level A / Level B / Level C 规则

### D.1 准入判据（唯一，`PROPOSED`）

```
某候选 Attempt c 相关  ⇔  matched_level_a_dimensions(c) ≠ ∅
```

**为什么"命中维度集合非空"是唯一符合 canonical 的读法**

| # | 论据 |
|---|---|
| ① | `D-019` 只说"**只有 Level A 可以用于判断某条历史 Attempt 是否值得进入主要比较集合**"，**未定义"需要几个维度命中"** |
| ② | 若引入 **"≥2 个维度命中"** ⇒ 这是一个**未由 canonical 定义的计数式门槛**，且会**凭空收窄**集合（使相关记录被判为不相关），**属新增产品机制** → Worker 不得引入 |
| ③ | 若引入 **"必须命中某个特定维度"**（如必须命中"目标"）⇒ 同样是**未定义的额外准入条件** → Worker 不得引入 |
| ④ | 若引入 **加权 / 分数 / 排序阈值** ⇒ 直接命中 `D-020` / `D-037` / `TC-41` / `TC-49`（禁止隐性门槛与内部加权） |
| ⑤ | 因此**唯一不新增任何机制的读法** = **结构性二值判据**：`∅ ⇒ 不相关`；`非 ∅ ⇒ 相关`。**这是结构判定，不含计数式门槛、不含权重、不含排序** |

**准入判据本身不得被呈现为强度**：界面**不得**出现"命中 2 个维度比 1 个更相关"类表述；命中维度**只用于可解释理由**（`AC-23` / `TC-49`）。

**Level B / Level C 不得参与准入**

| 级别 | 允许 | 禁止 |
|---|---|---|
| Level B | 解释 / 丰富比较说明（⑦ 的上下文材料） | ❌ 单独使记录成为相关；❌ 成为检索准入过滤条件；❌ 作为"为什么相关"的**独立成立依据**（`TC-38` / `AC-20`） |
| Level C | 辅助排序（§D.3） | ❌ 改变"是否相关"；❌ 把不相关记录拉入集合；❌ 作主排序键；❌ 默认选中"最近一次"（`TC-39` / `AC-21`） |

### D.2 维度级三态判定规则（`PROPOSED`；技术手段属 `TQ04`，见 §J）

**判定顺序（固定，不得跳步）**

```
对 (源 Attempt s, 候选 c, 维度 d)：
  第 0 步｜可及性检查
     s 或 c 在该维度任一相关条目 presence_state = unknown
        ⇒ 状态 = uncompared（进入未比对集合；结束该维度判定）
     （双方都 present 才继续）
  第 1 步｜来源合法性检查
     参与比对的条目 source_type ∈ {Fact, Extraction}
        出现 Inference ⇒ 该维度不得判为 matched（并记录为判定错误，属实现缺陷）
     presence_state = unknown 且值域非空 / present 且值域为空 ⇒ 写入侧契约违约（W-3-a 双向断言）
  第 2 步｜重叠判定
     判定"是否构成可比对重叠"（布尔结果 + 一句可解释理由）
        ├─ 是 ⇒ matched
        └─ 否 ⇒ compared_not_matched
```

**判定输出契约（无论 §J 选哪条路线，必须满足）**

| # | 要求 | 依据 |
|---|---|---|
| D-2-1 | 输出为**布尔 + 一句可解释理由**（人工可读、无数字、无等级） | `D-020` / `TC-41` |
| D-2-2 | **不得输出任何相似度 / 分数 / 概率 / 置信度 / 等级措辞** | `TC-41` / `TC-49` / `TC-64` |
| D-2-3 | **不得**在双方均 `unknown` 时输出 `matched` | `TC-40` / `AC-22` |
| D-2-4 | **不得**引入 Level B 维度作为该判定的输入 | `TC-38` |
| D-2-5 | **不得**引入时间作为该判定的输入 | `TC-39` |
| D-2-6 | 判定产物若由 AI 参与，**来源类型 = `Inference｜display`**（不要求逐条确认；可反馈"不相关"；未反馈 ≠ 已确认） | `D-014` / `D-019` / `TC-14` |
| D-2-7 | **不得**用标题匹配 / 列表位置 / 文本相似度数值作为判定依据 | 契约 §3.2 第 2 条 |
| D-2-8 | 判定**不得**改变任何内容条目的 `source_type` / 值 / `presence_state`（只读） | `TC-12` / `ADJ-01` |

### D.3 Level B 规则（只解释）

## §E `Draft` / 归档 / 当前 Attempt 的单点过滤

### E.1 单点过滤定义（唯一，禁止分叉）

```
eligible_attempts(workspace_id, source_attempt_id)        ← 路径 ①「可参与新链条」单点
   =  attempt_status = Formal
      ∧ archive_state = active
      ∧ attempt_id ≠ source_attempt_id
      ∧ workspace_id = 当前工作空间

traceable_attempt(attempt_id)                             ← 路径 ②「可追溯展示」单点
   =  按 ID 解析（**允许 archived**，只读）
```

| 路径 | 用途（穷尽） | 明确禁止 |
|---|---|---|
| **①** `eligible_attempts` | ⑥ 检索候选池｜新 grounding 来源判定｜新 `N_检索` 计数｜新 `E1` 来源判定｜默认跨记录比较 | ❌ 不得用于 ⑩ 追溯展示（会使既有引用静默消失，违反 `AC-74` / `AC-100`） |
| **②** `traceable_attempt` | ⑩ 追溯清单｜既有引用展示｜归档记录查看｜记录详情只读视图 | ❌ 不得用于路径 ① 的任何用途 |

**硬规则**

| # | 规则 | 依据 |
|---|---|---|
| E-1 | **过滤只注入一次**（单点）；**调用方不得自行拼装过滤条件**（含"顺手加一个 `status != 'Draft'`"这类局部条件） | 契约 §12 第 9 项 / `TC-57` / S03-A §5 纪律 2 |
| E-2 | **UI / AI / 各 Route 不得各自重新实现过滤**：UI 不筛、AI 不筛（⑥ 判定输入已是过滤后集合）、每个 Route 只调用单点 | 契约 §12 第 9 项 |
| E-3 | **检索模块自身也不得重建过滤**：它只**消费**单点输出的集合，并对该集合做维度判定 | 本文件 `PROPOSED`（防"第二个过滤实现"） |
| E-4 | **所有新检索必须统一排除 `Draft` 与 archived**；**漏一处即产生越权参与** | `TC-03` / `TC-57` / `AC-71` |

### E.2 归档 × 既有引用的处理（不追溯、不撤销、不失效）

| **新检索** | 已归档记录**被排除**（不计入新 `N_检索`、不可作新 grounding / 新 `E1` 来源、不参与默认跨记录比较） | `TC-57` / `AC-71` |

| **已有派生结果的 `candidate_entries` 指向后来归档的 `Attempt`** | **不自动剔除**（归档不触发检索）；展示时按 `target` **当前** `archive_state` **动态**标「来源已归档」；**不追溯改变 `n_retrieval`**（见 §F.4 口径） | `TC-25` / `TC-58` / 契约 §7.4（详见 §O.2 的 Integrator 确认项） |

| 标注 | 语义 | V1 是否适用 |
|---|---|---|
| 「来源已归档」 | **记录当前状态**（由 `target` 的当前 `archive_state` 动态派生） | ✅ 适用 |
| 「引用失效」 | 引用失效 | ❌ **V1 不适用** |
| 「上下文」 | **证据角色**（`role = context`） | ✅ 适用 |

### E.3 不该被顺手排除的东西（反向清单）

| 记录 | 是否可参与新检索 | 说明 |
|---|---|---|
| `result_status = Unknown` 的 `Formal Attempt` | ✅ **可以** | `Unknown` 是**已确认取值**，不是"未知维度"；**不得从证据清单删除**（`TC-48` / `AC-40`） |
| 维度全为 `unknown` 的 `Formal Attempt` | ✅ 进入候选池，但**不会被判定为相关**（因为 `matched = ∅`） | 正确行为 = 不进入命中集合，而非"被过滤掉"；**不得**在准入前静态排除（否则会掩盖"未比对"的真实原因） |
| `data_source_nature = Demo 示例数据` 的 `Formal Attempt` | ✅ **同等触发 / 同等参与** | `TC-83`：数据来源性质**不得**作为能力门控 |
| `Project` 缺失（未归属）的 `Formal Attempt` | ✅ **可以** | `Project` **不得**作准入过滤；缺失 **不得**以"默认项目"兜底（`TC-84` / S03-B §B.1） |

### E.4 🔴 三种"看起来像 0 条"的状态必须区分

| 状态 | 判定条件 | 用户可见语义 | 是否技术失败 |
|---|---|---|---|
| **① 检索未完成** | `Formal Attempt` 已保存，但**不存在**当前有效派生结果（检索 `RUNTIME` 失败 / 未执行） | "历史比较尚未完成，可重试" | ✅ `RUNTIME`（可恢复、可重试、不设次数上限） |
| **② `N_检索 = 0`（合法冷启动降级）** | **存在**派生结果且 `n_retrieval = 0`，且**历史库非空** | "有历史记录，但本次没有找到相关的历史尝试" | ❌ 合法产物，**不得呈现为错误 / 功能缺失** |
| **③ 历史库为空** | **不存在**任何 `Formal Attempt` | "你还没有历史记录" | ❌ 合法 |

> 🔴 **三者不得共用同一文案 / 同一状态码**（`TC-28` / `TC-61` / `TC-63` / `TC-66` / `AC-55` / `AC-89`；②③ 的分属 `TC-66` 的"两种空态"，① 为 `TC-61` 的 `RUNTIME` 与合法空态的区分）。
> 🔴 **不得**用"①"伪装成"②"（技术失败**不得**伪造为合法 0 条）；**不得**用"②"渲染成"出错"。

### F.1 `N_检索`（唯一算法，`PROPOSED`）

```
N_检索 = | { a | a ∈ eligible_attempts(workspace_id, source_attempt_id)
              ∧  matched_level_a_dimensions(a) ≠ ∅ } |
```

**必须排除（逐条落到实现）**

| 排除项 | 依据 |
|---|---|

> 契约 §6.1 的"可被引用" = 该记录具备**新引用来源资格**；其判定与 `eligible_attempts` 完全同集（`Formal` ∧ `active` ∧ ≠ 源自身）。⇒ **`N_检索` 的计数集合与 `eligible_attempts` 的交集口径是同一个集合**，**不引入第二个资格判定**。

### F.3 计算时机（事件驱动 + 读取时派生；**无后台任务**）

### F.4 归档对既有 `n_retrieval` 的口径（`PROPOSED`，需 Integrator 确认）

**本文件口径**：**归档不追溯改变已定稿的 `n_retrieval`**；展示时对相关候选**动态**标「来源已归档」。

**推理链**：`TC-25` / `AC-73`（归档不触发检索）⇒ 不重算 ⇒ 数值不变；且若允许追溯减少，将导致"档位变化 → 既有 `Insight` / `Hypothesis` 的依据被削弱"，**与 `AC-74` / `AC-100`（不追溯减少既有引用、不自动改写历史结论）的同源逻辑冲突**。

⚠️ 契约 §7.2 / §6.2 的措辞是"**新** `N_检索`"（即"下次检索时不计入"），**未显式定义"已定稿值是否追溯变化"** ⇒ 登记为 **Integrator 收敛项**（§O.2 `O-2-1`），**本文件不自行扩展语义**。

### F.5 数据层 / 响应体禁止字段（断言级）

> `similarity` / `score` / `match_score` / `rank_score` / `confidence` / `weight` / `star` / `percent` / 任何等价命名与计算列 —— **在任何存储面与任何接口响应体中都不允许存在**（含错误对象、含调试模式）。
> **建议以 schema 断言 + 响应体契约测试双向断言其不存在**（`TC-41` / `AC-23` / `TC-71` / `AC-78`）。

### G.2 首次自动检索：同步触发实现要点

```
保存流程（同一调用链，客户端等待）
  1) ⑤ 校验保存门槛（P1 四条 + 用户显式确认）→ 持久化 Formal Attempt（事务提交）
  2) ★ 触发 ⑥（**同一调用链内同步执行**）
       2.1 候选池 = eligible_attempts(workspace_id, source_attempt_id)     ← 单点过滤（§E）
       2.2 对每个候选 × 每个 Level A 维度执行三态判定（§D.2）
       2.3 组装命中集合 / 未比对集合 / 候选条目 / Level C 辅助排序 / n_retrieval
       2.4 **同键覆盖写入**当前有效派生结果（source_attempt_id 唯一键）
  3) ⑦ 比较解释（详见 §M.3 的往返粒度）
  4) ⑧ / ⑨（可选独立往返；仍由客户端顺序驱动）
```

**硬要求**

| # | 要求 | 依据 |
|---|---|---|
| G-2-1 | **同步**：⑥ 必须在"保存成功"的那一刻**同一次调用链内完成**；**唯一不可拆的边界 = 不得把 ⑥ 移出"保存成功"的调用链** | `TC-21` / S03-C §J.5 |

### G.3 幂等设计（`PROPOSED`）

| 层 | 手段 | 效果 |
|---|---|---|
| **对象层** | 派生结果以 `source_attempt_id` 为**唯一键**（每 `Formal Attempt` 至多 1 条"当前有效"） | 重复触发 ⇒ **同键覆盖写**，**天然不可能产生第二份** |
| **请求层** | 保存请求携带**请求级幂等键**（同一保存流程的重复提交映射到同一键） | 同一保存流程只产生一次 ⑥ 执行（`TC-23` / `AC-79`） |
| **判定层** | 维度判定为**纯函数式**（输入相同 ⇒ 输出相同；无随机、无时间依赖） | 重复执行不产生"结果抖动"，不产生"多份不同结果" |
| **替换层** | 显式「重新检索」= **同键覆盖替换**（子结构同事务整体替换，先清理后写入） | 不出现"半新半旧"，不堆积历史版本（`TQ11`） |

> ⚠️ **`generated_at` 只作覆盖顺序的技术元数据**：**不出界面、不可选择、不得被读作"检索新鲜度"**（`D-045 TR-11`）。

### G.4 重跑：显式「重新检索」

| 项 | 设计与规则 |
|---|---|
| **入口** | **由用户显式发起**（记录被修改后提示内置入口）；**不自动**（`TC-24`） |
| **触发提示条件** | `Formal` 内容性修改请求**成功后**，且该 `Attempt` **存在当前有效派生结果** → 在**同一次请求的响应**中携带提示 + 「重新检索」入口。**不比较任何时间戳、不存储任何"是否已检索 / 是否陈旧"标志**（S03-B §G.3） |
| **提示文案（语义，措辞归 UI）** | 「该记录已被修改，先前的历史比较结果可能不再适用」 |
| **范围** | 默认范围 = **全部历史**，与首次一致（`D-045 TR-10`） |
| **效果** | 重跑 ⑥（若 ⑦ 解释随行则一并重算）→ **替换**当前有效派生结果 |
| **不级联** | **不自动重建** ⑧ / ⑨ 产物；**不改** 既有 `Insight` / `Hypothesis` 的持久化状态；**不改写** 既有 `EvidenceRef`；**不自动退回**任何既有状态（`D-045 TR-7` / `TQ11` 第 7 条 / S03-C §N.2 SD-8） |
| **不保留历史** | 替换后**不保留**被替换结果；**不建历史表、不软删除、不加 `is_current` 多行标记、不加版本号**（`TQ11` / `D-040`） |
| **用户可见** | **没有任何**版本列表 / 版本对比 / 回滚 / 版本号选择 / 新旧比较结果并存（`TQ11` 红线） |
| **幂等** | 同一次「重新检索」动作重复提交只产生**一次**替换 |
| **失败** | `RUNTIME`（可恢复、可重试、不设上限）；**替换失败时保留原有的当前有效派生结果**（不得留下"已被清空"的中间态） |

### G.5 检索失败与结果的三种状态

见 **§E.4**（① 检索未完成 / ② `N_检索 = 0` / ③ 历史库为空）。补充：

- ⑥ 失败时，**⑤ 已保存的 `Formal Attempt` 不回滚**，⑦ / ⑧ / ⑨ **不得**以"无候选"为由伪造成"依据不足的 0 条"（`TC-63` 精神 / `AC-89`）。
- 重试**不改变已保存数据、不覆盖用户已修改内容**（`TC-62` / `AC-89`）。

### G.6 与 `ADJ-01` 的回归一致性（重跑路径）

| 场景（`ADJ-01` 读法 ③） | 本设计的支持方式 |
|---|---|

### J.3 embedding（`R-B`）对 V1 是否有足够收益 —— **明确结论**

> **结论：`embedding` 对 V1 没有足够收益。**（依任务要求明确说明）

| # | 论据 |
|---|---|
| ① | **准入只能由 Level A 决定**（`TC-37` / `D-019`）。而 embedding 的产物是"语义相似"，canonical 已把「语义相似」明确划入 **Level B**（**只能增强或解释、不得单独使记录成为相关、不得作为准入过滤**）⇒ embedding **不可能**改善"哪些记录进入集合"这一最关键的产品行为 |
| ② | **排序只允许 Level C（时间）+ 稳定兜底**（`TC-39` / Q16 派生关闭）⇒ embedding 排序**不能**用于展示顺序 |
| ③ | **任何数值相似度不得输出 / 存储 / 传输 / 展示**（`D-020` / `TC-41` / `AC-23`）⇒ embedding 的输出形式在**产品层被整体禁止** |
| ④ | 因此其**合法作用面仅剩"技术层的候选处理顺序"**（契约 §11.2 允许但**不参与任何产品判定**）—— **对用户可感知行为零收益**，而代价为：新依赖（向量存储 / provider embedding 能力）、provider 锁定、测试难度上升、10 天窗口风险上升 |
| ⑤ | **数据规模不需要它**：V1 为个人工作空间场景；Demo 为 5–10 条 + 现场新增 1 条；全量判定完全可行 |
| ⑥ | **若未来规模需要**：应先由**人工决策**把"语义相似"从 Level B 的"仅解释"地位改变（这本身就是产品决策），**不能靠技术路线偷偷改变准入** |

**若 Gate B 仍选择 `R-B` / `R-C`，以下防线为硬要求（`PROPOSED`）**

1. **不得引入独立 Vector DB**（可用托管 PG 的内嵌能力或轻量内存方案）；**不得引入 Graph DB**；
2. **不得输出 / 存储 / 传输 / 展示 / 记录任何 similarity score**（含内部列、含错误对象、含调试模式）；
3. **embedding 结果不得作为准入依据**（只能落 Level B 的解释位置）；
4. ⑥ 的输出**仍必须**满足 S03-C §B.7（两份集合、无数值、不得以向量相似度替代 Level A 判定）；
5. 技术层若存在内部检索分数，**建议不落库（进程内即弃）**（S03-B §C.12 的收紧建议，不改变契约语义）。

## §L `TQ13` / `TQ14`｜"是否必须引入"证明

> 🔴 **默认处置 = 不引入**（契约 §13.3 / `S00-03` 启动文档 §5.4）。
> 🔴 **升级条件（两者必须同时满足）**：**"必须引入" AND "会产生用户可感知行为"** → 才可升级 Gate B；且**升级前须先建立独立 `Decision ID`**。
> 🔴 **本文件不创建 `Decision ID`、不自行选择、不升级产品机制。**

### L.1 `TQ13`｜`created_at` 是否允许作纯展示层 fallback

| 检查项（任务 §十一 A/B/C） | 结论 | 证明 |
|---|---|---|
| **A. 不引入是否足以完成检索 / 排序？** | ✅ **足以** | ① **检索不需要时间**：准入只由 Level A 决定，时间**不得**参与（`TC-39`）。② **排序在全部分支下都有确定性顺序**：`occurred_at` 存在 → 按用户提供的实际发生时间；`occurred_at` 缺失 → `attempt_id` 稳定序兜底。两者合起来构成**全序**，且**可复现**（§I.2）。③ **呈现不需要绝对时间戳**：界面呈现"顺序 + Level A 理由"，`order_key` 本身**不出界面**（S03-B §C.10.1）。④ **空态不需要默认项**：`N_检索 = 0` 时进入合法空态（§E.4），**不得**用"最近一次"补位（`AC-83` / Q16 派生关闭 ①） |
| **B. 是否存在技术上不可实现的情况？** | ❌ **不存在** | 无任何实现路径依赖 `created_at` 参与排序：候选集合有界（单点过滤后），任何元素都有稳定唯一 ID（`attempt_id`）；`order_key` 构造为分支覆盖完备（有 / 无 `occurred_at`）。**技术可行性 100% 成立** |
| **C. 若引入，是否会产生用户可感知行为？** | ⚠️ **会**（但这**不构成升级理由**，因 A 已成立） | ① 把 `created_at` 当发生时间展示 ⇒ **直接违反 `TC-17` / `AC-78`**（`created_at` 不得冒充发生时间）；② 用户会把"系统创建时间"读作"事情发生的时间"，产生**事实性误读**；③ 与"不得默认选中最近一次"（`AC-21`）组合后，会让用户产生"最新的一条更相关"的错觉 |
| **是否满足升级条件（必须引入 AND 用户可感知）** | ❌ **不满足** | **"必须引入"= 不成立**（A 已证明不引入足以完成全部功能）⇒ 即便 C 为"会"，也不满足 AND |

```
TQ13 结论（PROPOSED）= 不引入 —— 成立
· 不引入足以完成检索 / 排序 / 呈现 / 空态（A 成立）
· 技术无不实现情形（B 不成立）
· "必须引入"不成立 ⇒ 不升级 Gate B、不创建 Decision ID、不引入 created_at fallback
· `occurred_at` 缺失时：该记录进入"无时间键组"，以 attempt_id 稳定序兜底；**不得**用 created_at 填充
```

### L.2 `TQ14`｜是否引入「并列判定」技术判据

> 背景：`Q16` 移出的原候选"两条命中的 Level A 维度集合相同 = 并列"**已删除**，**不属 `D-019` 直接推出**，归 `S00-03` 的检索实现 / 排序规则设计（`DECISIONS.md` `Q16` §「不在 S00-02 固化的两项」）。

| 检查项（任务 §十一 A/B/C） | 结论 | 证明 |
|---|---|---|
| **A. 不引入是否足以完成检索 / 排序？** | ✅ **足以** | ① **检索不需要"并列"**：准入判据是"命中集合非空"（§D.1），与"多个候选之间是否并列"无关。② **排序不需要"并列"作为判据**：`order_key` 三元组（`time_group`, `occurred_at`, `attempt_id`）在 `attempt_id` 层**必然唯一** ⇒ **全序成立，不存在真正的"并列"**。③ 即便两个候选的 `time_group` 与 `occurred_at` 完全相同，也由 `attempt_id` 定序 —— 这是**纯技术稳定性需求**，不是产品语义。④ **呈现不需要"并列"**：界面呈现"顺序 + 各自命中的 Level A 维度 + Level A 理由"，**不呈现任何相对关系强度** |
| **B. 是否存在技术上不可实现的情况？** | ❌ **不存在** | 所谓"并列"在实现层**等价于 `order_key` 相等的技术等值判断** —— 该判断**必然可实现**（等值比较），且由 `attempt_id` 兜底后**不影响输出**。即：**系统在任何输入下都能产出确定性顺序** |
| **C. 若引入，是否会产生用户可感知行为？** | ⚠️ **会产生**（但这**不构成升级理由**，因 A 已成立） | 若把"并列"**呈现**给用户（如"以下 2 条与本次并列"），用户必然把它读作"**同等相关度 / 同等评分 / 同等证据强度**" ⇒ 与 `D-020`（不显示数值相似度，且一个数值无法表达分级）、`D-035`（档位不是可信度等级）、`D-037` / `TC-49`（合法数字仅三类）**冲突**；且"并列"必须由某个**判据**产生 ⇒ 必然引入 `TC-41` 所禁的内部判据 |

**实现层的合法边界（关键澄清，防"偷换"）**

| 允许（纯技术，无用户可感知） | 禁止（产品机制） |
|---|---|
| 因 `attempt_id` 兜底，`order_key` 在实现层**必然唯一**；若某实现把"`time_group` + `occurred_at` 相同"视为同一排序组并用稳定序展开 —— **属纯技术等值处理**，**不产生任何用户可感知行为** | ❌ 把该情形**命名为"并列"**；❌ 在响应体中输出"并列"语义字段；❌ 在界面上标注"并列 / 同等相关"；❌ 以"并列"作为任何判定 / 计数 / 排序 / 呈现的**产品判据**；❌ 由"命中的 Level A 维度集合相同"推导并列 |

```
TQ14 结论（PROPOSED）= 不引入 —— 成立
· 不引入足以完成检索 / 排序 / 呈现（A 成立；order_key 由 attempt_id 天然全序）
· 技术无不实现情形（B 不成立）
· "必须引入"不成立 ⇒ 不升级 Gate B、不创建 Decision ID、不引入"并列判定"产品机制
· 实现层允许"order_key 等值"这一纯技术处理，但**不得命名为"并列"、不得呈现、不得作为产品判据**
```
