# 04 用户流程（USER FLOW）

> 本文档为 S00-02 阶段待填写主文档。标注「已锁定」的内容来自 S00-01 人工关键决策（D2、D4、D5、D7、D9），2026-09-17 收口后不得重开。

## 1. 核心流程总览

原始流程（2026-09-16 历史提案）：

```
失败经历记录 → AI 结构化解析 → 失败原因分析
      → 相似历史经验检索 → 可复用经验提炼 → 下一步方向孵化
```

**已锁定为 V1 P0 验收主链（D9）**：

```
① 用户自然语言输入一次失败尝试
      ↓
② AI 进行结构化解析
      ↓
③ 用户可以修改 / 确认解析结果
      ↓
④ AI 生成候选失败原因
      ↓
⑤ 用户确认后保存
      ↓
⑥ 系统检索相关历史 Attempt
      ↓
⑦ 展示相似点与差异点
      ↓
⑧ AI 提炼可复用经验
      ↓
⑨ AI 生成至少一个可验证的新假设
      ↓
⑩ 新假设能够追溯到历史记录证据
```

> 任一环节无法正常完成，V1 即视为尚未完成（D9）。

## 2. 主流程细化

### 2.1 失败经历记录
- **已确认（D-011 / Q01）**：用户录入方式 = **自然语言输入 + AI 结构化确认**。用户首先用自然语言描述一次未达到预期的尝试，AI 再进行结构化解析，用户可以修改 / 确认解析结果。**不得把结构化表单作为第一入口**（原"待填写：自由文本 / 表单 / 引导式对话"由此关闭）。
- **已锁定（D2）**：记录单位为 `Attempt`——一次围绕明确目标、在特定条件下实施某个方案、并产生可观察结果的行动单元；项目/课题不得直接等同于一条 Attempt。
- **已锁定（D4）**：入口心智为"**刚刚哪里没有达到你的预期？**"，随后由 AI 完成结构化整理；产品不以"填写档案"为主要心智。
- **已确认（D-012 / Q02）**：记录存在两级状态——
  - `Attempt Draft`：**只要用户产生了原始输入即可暂存**；可字段不完整；可中断后继续；**不进入正式历史比较 / 不参与经验资产晋升 / 不参与正式 E4 历史孵化**。
  - `Formal Attempt`：至少具备 **目标、实际尝试、实际结果、用户确认后的结果状态**；其中结果状态属 `Inference`，**必须由用户显式确认**；允许缺省 条件 / 判定依据 / 版本·环境，缺省时必须显式保存为「未知 / 未提供」；**不得因为缺少可选字段自动删除 Draft**。
- **已确认（D-013 / Q03）**：必填与可选字段划分见 `05_DATA_MODEL.md`；**"失败类型"不作为 P0 必填字段**，如出现仅为 optional tag。

### 2.2 AI 结构化解析
- **已确认（D-013 / Q03）**：解析输出字段按 5 组呈现——原始信息 / Formal Attempt 必备（目标、实际尝试、实际结果、结果状态）/ 重要但允许未知（条件、预期结果、判断依据、关键参数·用户主动提及的关键变化）/ 系统自动（创建时间、数据来源、AI 内容来源标记）/ 可选（Project、版本·环境、用户备注、成本、失败类型标签）。
- **已锁定（D7）**：解析产物属 `Extraction｜AI 结构化解析`——允许 AI 自动生成，但**必须允许用户修改**，且不得改动 `Fact｜用户事实` 的含义。
- **已确认（D-011 / Q01）**：解析结果必须经用户**修改 / 确认**后方可进入下一步；这是 P0 主链第 ③ 步的固定环节。
- **已确认（D-014 / Q08）**：`Extraction` 可由用户**一次整体校正 / 确认**，不要求逐字段点选。
- **已确认（D-016 / D-017 / D-018 / D-023）动态追问机制**：
  - **先检查缺口，再决定是否追问**；采用**动态缺口优先级**，**不设固定问题清单**：
    - **P1｜`Formal Attempt` 必备事实缺口**：**目标 / 实际尝试 / 实际结果** —— 无法从原文获得时**优先追问**；
    - **P2｜高影响但允许未知**：**条件 / 判断依据** —— **应尽量补齐**，但用户可「不知道 / 跳过」，**缺失不得阻断 `Formal Attempt` 保存**；
    - **P3｜必要时才追问**：**关键参数 / 用户主动提到但表达不清楚的关键变化** —— **仅当真正影响当前 Attempt 理解时**；
  - 🚩 **追问预算 = 关键追问问题总量，不是对话轮次**（**2026-09-19 口径校正**，D-017 / D-023）：**最多 3 个关键追问问题（TOTAL）**；**计数单位 = AI 实际提出的"关键追问问题数"**；**无关键缺口时为 0 个追问问题**，直接进入结构化确认；**问题可以逐个对话呈现**；**每个关键追问问题原则上只针对一个主要高价值缺口**；**禁止在一个"问题"里打包多个字段以规避总预算**；**达到 3 个后不得再提出第 4 个关键追问问题**；用户始终可选择「**跳过 / 不知道 / 就这样继续**」，且**不得因此阻断流程**；**用户主动补充的信息不计入 AI 的问题预算**；
  - **停止条件（满足任一即停止追问并进入结构化确认）**：**A** 当前不存在仍值得继续追问的 P1 / P2 关键缺口；**B** **已达到 3 个关键追问问题总量**；**C** 用户选择「跳过 / 不知道 / 就这样继续」；
  - **特别规则**：① **P2 允许未知** —— 用户已明确选择「不知道 / 跳过」的 P2，**不得再次追问同一缺口**，**不得阻断保存**；② **P2 / P3 未解决** → 记为「**Unknown / 未提供**」，**不阻断 `Formal`**；③ 🔴 **若 P1（目标 / 实际尝试 / 实际结果）仍未建立，即使问题预算已用完，也只能进入确认 / 暂存，`Attempt` 保持 `Draft`，不得伪装成 `Formal`**；④ **结果状态仍由「AI 给候选 + 用户在结构化确认阶段显式接受 / 修改」确定**，**不得把结果状态算成"通过追问补齐 P1"**；
  - **M2 阶段固定禁止追问**：与历史 Attempt 的差异、"上一次做了什么"、最近一次相似 Attempt、其他历史对照类问题 —— 统一留到 §2.4 / P0 第 ⑥⑦ 步；
  - **结果状态不由追问替代**：由 **AI 提出候选状态**（属**决策型 `Inference`**），在结构化确认阶段由**用户显式接受 / 修改**；
  - **追问答案的来源分层（D-024 / 新-4）**：**用户原始回答 = `Fact`；AI 对回答的结构化归纳 = `Extraction`（用户可修改）**；**不得**把用户原话标成 `Inference`，**不得**把 AI 归纳标成 `Fact`。
- **已确认（D-026 / 新-6）保存门槛与晋升门槛分层**：条件缺省**不影响** `Formal Attempt` 保存；但关键条件缺失导致适用范围无法明确时，`Insight` **保持 `candidate`**（属 §2.5 的晋升门槛，不回推为保存门槛）。
- **已确认（D-047 / Q27）解析失败 / 技术失败的处理**（原"待填写"由此关闭）：
  - **第 ① 步唯一门槛 = 存在非空、非纯空白的输入** → 创建 `Attempt Draft`；**不设字符数阈值、不设语义判定、不设 AI 前置判断**（**"语义是否可解析"下沉到第 ② 步的解析质量判断输入**，**不得作为 ① 的阻断条件**）；**"≥ 8 字符"正式废止**。
  - **超长输入不阻断**：只提供降级表达方式（分段 / 放入"补充备注"），**仍创建 `Draft`**；**产品层不锁具体字符上限**。
  - **AI 调用失败 / 超时 = Runtime 技术失败（可恢复）**：**允许"仅保存原文"**，`Draft` 保留并标「尚未解析」；**不得伪造解析结果**；**显式提供"重新解析"，不设次数门槛；不覆盖用户已修改内容**。
  - 🚩 **禁止等级化措辞**：解析质量 / 完整度一律用**状态描述**（已抽取 / 未抽取 / 抽取失败 / 待用户确认）；**不得使用"高 / 低置信""完成度"等分级表述**；该状态**不得成为门槛、不得作为用户可见的可信度判断**（原"置信度低"表述**正式废止**）。
  - **区分三层语义**：**A 对象门槛未满足**（如 `Draft` 不升级 `Formal`）**只影响升级 / 输出资格**，不删产物、不渲染为系统错误、不锁死继续操作；**B Runtime 技术失败**可保留数据 + 提示 + 重试 + 恢复；**C P0 Acceptance** —— **Runtime 可降级 ≠ 验收可跳过步骤**。

### 2.3 失败原因分析
- **已确认（D-048 / Q28）候选失败原因的数量与处理**（原"AI 如何归因（单原因 / 多原因 / 分层）"待填写项由此关闭）：
  - **数量**：**允许输出 0 条**；**不设产品层数量上限**（由 AI 按实际依据给出）；**禁止为凑数生成低质量 / 低置信候选原因**；**不得为它引入任何新数字**。
  - **0 条时的处理**：证据不足时**必须明确表达「当前依据不足，暂不推断原因」或等价语义**，随后**正常进入第 ⑤ 步（保存）**，**不阻断**。
  - **逐条处理**：**保存 `Formal Attempt` 不要求用户逐条处理全部候选原因** —— 允许 0 条 / 部分处理 / 全部未处理即保存；**未处理原因以 `candidate` 状态保存**。
  - **未处理项不得复用**：**不得作为已接受依据进入后续复用链路**（不得进入 ⑧ 步"已确认经验"、不得作为 grounding、**不计入 `N_引用`**）；**只有 `accepted` 的决策型 `Inference` 才可以作为已确认判断复用**。
  - **禁止"默认已接受"**：未被用户显式操作的原因**永远处于 `candidate`**，**不得**因"保存了 / 离开了页面 / 超过了某时间"而变成 `accepted`。
  - **状态必须可见且持久**：**不得**把"未处理"渲染成"已记录 = 已确认"；**"0 条"（没有候选，依据不足）与"全部未处理"（有候选但尚未处理）必须区分，不得共用同一文案**。
- **已锁定（D7）**：候选原因属 `Inference｜AI 推断`，必须标记为 AI 推断 / 候选结论 / 待确认 / 待验证，**不得伪装成用户事实**；用户须确认后方可保存。
- **已确认（`D-048` 承载的 `AC-10` 精度修正）**：**未经显式接受或拒绝的决策型 `Inference`，不得被作为『已确认依据』进入后续复用链路**（依据 / 门槛 / 版本来源 / 比较输入 / 后续决策依据）；**结果状态显式确认仍是 `Formal Attempt` 成立的必要条件**；**候选失败原因"逐条处理"不是保存的前置条件，但"被复用前必须已处理"是硬要求**。该修正**不改变 `D-014` 本体**。

### 2.4 相似历史经验检索
- **已确认（D-045 / Q29）检索触发时机**（原"待填写：触发时机"由此关闭）：**检索触发分两层** ——
  - **① 首次自动检索**：**`Formal Attempt` 保存成功 = 第 ⑥ 步的唯一自动触发条件 = 主链首次自动触发条件**；**不设"用户发起"前置**；**不得在 ⑤ 与 ⑥ 之间插入任何未在 D9 中列出的用户动作**（**"用户手动点击查找相关历史"被否决**）。
  - **② 后续重新检索**：`Formal Attempt` 内容被修改后 —— **不自动重跑检索**；**必须显式提示**「该记录已被修改，先前的历史比较结果可能不再适用」；**提供由用户显式发起的"重新检索"**（**属后续重跑动作，不是 `D9` ⑤→⑥ 之间的新步骤**）。
  - **不触发的情形**：`Draft` 保存 / 仅编辑 `Draft` / 解析 / 追问 / 中途离开 / 续写 **均不触发**；**保存失败不触发**；**归档 / 取消归档亦不触发**；**重复保存幂等**（同一次保存流程内只产生一次检索）。
  - **触发与「数据来源」字段无关**：现场记录 / 事后补录 / Demo 示例数据**同等触发**；**不得以来源字段作为能力门控**；**不产生后台 / 异步 / 批量 / 定时任务**；**不改变第 ⑧ 步的生成时机**（D-022）；**不引入「已检索过」产品层字段**，**不得把"检索新鲜度"做成门槛 / 评分 / 用户可见结论**。
  - **默认检索范围 = 全部历史**；`Project` **只作 Level B 解释维度，不作预筛选、不作准入判据**；范围调整**只能是用户显式选择**。
- **已确认（D-046 / Q14）主对照展示数量**：**首屏默认 3 条**；**实际不足 3 条则如实展示实际数量**；**可就地展开查看更多且展开必须可达**；**S00-02 不锁「展开上限 10」**（降级为 `08_UI_SPEC.md` / 实现参数）；**`N_检索` 不因首屏显示数量被截断**（归档记录不计入 `N_检索`，`Draft` 不计入）。
- **已确认（Q16 派生关闭，规则源 = D-019 Level C）"最近一次"的默认地位**：**不设「最近一次默认比较对象」**（既不是默认比较对象，也不是默认展开对象，也不是空态默认项）；**比较集合仍由 Level A 决定**；**时间不得改变"是否相关"、不得把不相关记录拉入集合**；**时间只在「已经相关、且 Level A 无法进一步区分」时作辅助排序维度**；**不得以「最新」作主排序键**。
- **已锁定（D9）**：必须检索相关历史 Attempt，并**展示相似点与差异点**（第 ⑥⑦ 步）。
- **已确认（D-019 / Q13）三级相关性机制**：
  - **Level A｜核心相关性**：**目标 / 实际尝试·方案·技术对象 / 条件 / 结果·现象** —— **只有 Level A 可以用于判断某条历史 Attempt 是否值得进入主要比较集合**；
  - **Level B｜辅助相关性**：**Project / 用户标签 / 版本·环境 / 语义相似** —— **只能增强或解释**，**不得单独决定"这是一条相关经验"**；
  - **Level C｜排序辅助**：**时间** —— **只能在相关性已经接近的情况下辅助排序**；**不得**默认选择"最近一次"，**不得**因时间近而把不相关 Attempt 排到前面。
- **已确认（D-020 / Q15）呈现形式**：**不显示任何形式的数字相似度**（百分比 / 0–1 分数 / 星级 / 综合相似分），改为展示**可解释的匹配理由**（目标相近 / 方案相同 / 条件不同 / 结果表现相似 / 同属一个 Project（辅助））。
- **已确认（D-025 / 新-5）未知字段处理**：字段值为「**未知 / 未提供**」时 —— **不参与相关性判断**；**双方都未知也不得判为相似**；**比较结果中必须明确标记"该维度未比对"**，**不得静默当作相同 / 不同 / 相似**。
- **已确认（D-014 / Q08 不变）**：以上相关性判断、相似点、差异点、排序理由均属 **`展示型 Inference`** —— 必须标记为 AI 判断、**不要求逐条确认**、可反馈"不相关 / 不同意"、**未反馈不等于已确认**、**不得自动升级为 Experience Asset**。

### 2.5 可复用经验提炼
- **已确认（D-022 / Q11）生成时机**：**V1 只在 P0 主链第 ⑧ 步正式生成 `Candidate Insight`**，并在**同一步**让用户 **接受 / 修改 / 拒绝** → `accepted` → Experience Asset。**V1 不做**后台自动生成、保存后自动生成、异步批量生成、定期知识挖掘、Candidate 待办池。
- **已确认（D-021 / Q10）晋升硬条件 E1–E5**：
  - **E1｜有效来源**：至少关联 **≥ 1 条 `Formal Attempt`**；`Draft` 不得直接成为 Experience Asset 的来源；
  - **E2｜结论明确**：必须能形成**明确、可理解的经验命题**（不得是"感觉有问题 / 可能不太好"）；
  - **E3｜适用范围明确**：至少说明"在当前已知哪些条件下观察到了该经验"；**关键条件完全缺失时保持 `candidate`**；
  - **E4｜证据可追溯**：① 哪些 `Formal Attempt`；② 哪些事实字段；③ **若存在跨记录比较**，则使用了哪些比较结果（**跨记录比较不是硬门槛**）；
  - **E5｜用户显式接受**：必须 `Insight.status = accepted`。
  - **C4′ / C5′ 仅作增强信息**（不作硬门槛、不打分、不设高 / 中 / 低经验等级）；**C6**：单条普通操作错误**默认不得自动晋升**，但**多条普通操作错误可参与跨 Attempt 分析并生成新的 `Candidate Insight`**。
- **已确认（D-026 / 新-6）保存门槛 ≠ 晋升门槛**：条件允许缺省**不影响** `Formal Attempt` 保存（§2.1）；但**关键条件缺失导致适用范围无法明确时，`Insight` 保持 `candidate`，不能成为 Experience Asset** —— 二者**不冲突**。
- **已锁定（D7）**：跨记录产生的新判断统一属 `Candidate Insight`，不是 Fact；**N=1 的单次失败最多支持"在当前记录的具体条件下该方案没有达到预期"，不得扩大为"方法 X 无效"**（**N=1 仍可形成局部经验，但不得产生一般性规律**）。
- **已确认（D-015 / Q09 不变）**：`Experience Asset = accepted Insight 的产品视图`，**不是第三个独立事实对象**；**来源仍为 `Inference`**；`accepted` **不等于客观证实**。
- **已确认（D-039 / Q12）用户对第 ⑧ 步 `Insight` 的合法动作 = 四个**：**接受**（**仅当 E1–E4 已满足**；作用等价于 **E5**）、**修改**（见 D-040）、**拒绝**（`candidate → rejected`，**不要求 E1–E4 满足**）、**撤销接受**（`accepted → candidate`）。

- **已确认（D-040 / 新-2）`accepted Insight` 被修改后的状态机**：

- **已锁定（D7）**：跨记录产生的新判断统一属 `Candidate Insight`，不是 Fact；**N=1 的单次失败最多支持"在当前记录的具体条件下该方案没有达到预期"，不得扩大为"方法 X 无效"**。

- **已确认（D-038 / 新-3）E2 / E3 不满足时的呈现**：`Insight` **保持 `candidate`**（不晋升、不隐藏），并同屏出现「**当前还不足以成为可复用经验**」+ **三段式说明**：

- **已确认（D-028 / D-029）三类"输出不可达"必须分别处理（三类出口不得混用）**：
  - **A｜`evidence-insufficient`（历史证据不足）**：`N_检索 = 0`（或虽有相关记录但不满足 grounding 判据）→ 不产出 `History-grounded Hypothesis`；**显式说明证据状态并区分两种空态**（历史库为空 / 有历史但本次无相关）；可选 `Model Suggestion`；提供"仅保存本次尝试"；**不阻断**；
  - **B｜`not-verifiable`（条件不可达）**：**存在 grounding**，但**当前没有可区分、可观察的验证判据** → **显式说明"当前无法形成可验证的观察方式"**、**不得编造**、该条**不计入 [D9] ⑨ 的"可验证假设"**；**不得默认归入冷启动降级而免于验收**；
  - **C｜`not-formable`（命题不可达）**：**连明确的候选命题都无法形成** → **显式说明"当前不足以形成明确的可复用命题"**；**允许为空并通过**。
  **统一原则**：说明原因 / 不编造 / 不阻断 / **不呈现为错误** / 提供可选的下一步；**三类均属合法 Runtime 出口，但"合法" ≠ "免于测试"**。
- **已确认（D-034 / D-036）空态区分**：`N_检索 = 0` 时**必须区分**"用户整个历史库为空"与"用户有历史但本次没有相关历史"，**不得使用同一空态文案**（后者**不得说"你没有历史记录"**）；**不得把冷启动显示为系统错误 / 生成失败 / 功能缺失**。
- **已锁定（D8）+ 已确认（D-034）Demo 场景**：使用"**预置 5~10 条示例 Attempt + 现场新增 1 条真实 Attempt**"；**MUST** = 预置数据中**至少 1 条 `Formal Attempt` 与现场新增的 Attempt Level A 命中**（保证 ⑥→⑦→⑧→⑨→⑩ 可完整走通）；**SHOULD** = 建议 ≥2 条彼此相关（演示跨记录比较）；条件缺失 / 冲突 / `Unknown` 案例作为**可选回归夹具**（不必全进主演示路径）；预置数据必须明确标注为 **Demo / 示例数据**；**验收不得依赖临时人工补录来凑历史来源**。
- **已确认（D-047 / Q27）异常处理（原"待填写：解析超时、AI 调用失败等"由此关闭）**：
  - **Runtime 技术失败一律可恢复**：**保留已有数据 + 明确提示 + 允许重试 + 提供恢复路径**；**重试不设产品层门槛**（**不得**出现次数上限 / 冷却 / "已达重试上限"）。
  - **对象门槛未满足**（`Draft` 不升级 `Formal` / `Insight` 不晋升 / `History-grounded Hypothesis` 不生成）**只影响升级与输出资格** —— **不得删除已有产物、不得把正常状态渲染为系统错误、不得锁死用户继续处理**。
  - **「步骤未触发」 ≠ 「不可恢复终止」**：① 步空输入只给入口提示，**不得报错**。
  - **正式表述**：「**V1 不设计不可恢复的业务终止；未来若新增会阻止用户继续完成主链的业务条件，必须重新经过产品决策**」。
  - 🔴 **Runtime resilience ≠ P0 Acceptance**：**正式验收必须在 Acceptance fixture 下 ①→②→③→④→⑤→⑥→⑦→⑧→⑨→⑩ 完整成功执行**；**不得依赖临时人工补录凑验收**。
- **已确认（D-043 / Q31）`Attempt` 归档流程**：
  - **V1 只提供「归档」，不提供永久删除**；归档是**用户主动**动作，**可撤销**（取消归档后恢复为正常参与状态），**归档后不可编辑**（可先取消归档再编辑）。
  - **归档后**：**不参与新的默认检索**、**不作为新的 grounding 来源**、**不计入新的 `N_检索`**；**`N_引用` 不因归档追溯减少**；**不得作为新的 `E1` 来源**（**新建立不成立**；既有引用保留）。
  - **既有证据链必须继续存在**：第 ⑩ 步的旧引用**继续显示该记录（只读可查看）**，并**显式标注「来源已归档」**；**不得静默断裂、不得自动删除引用、不得自动撤销旧 `Insight` / 旧 Hypothesis、不得自动改写历史结论**。
  - **「已归档」 ≠ 「引用失效」**：**两种状态、两种标注，不得共用**；**「引用失效」仅在允许删除时适用（V1 不适用）**。
  - **归档状态必须用户可见且可识别**；**不作为价值判断 / 质量信号 / 完成度信号**；**不触发第 ⑥ 步检索**；**不是内容性修改、不触发 `accepted → candidate`**。
  - **系统不得因低价值 / 普通错误 / 时间久远自动归档 `Attempt`**。
