## §4 技术硬约束（TC-01 – TC-84）

> 每条 = 一条**可被实现层检查**的约束；来源为 `DECISIONS.md` 与 `docs/01–09` 的 `CONFIRMED` 内容。
> 违反任一条 = 违反已确认产品机制。

### G1｜对象与边界（`Attempt` / `Insight` / `Hypothesis` / `Model Suggestion`）

| ID | 技术硬约束 |
|---|---|
| **TC-01** | **对象分层必须区分三类，不得压平为一类**：① **产品核心事实 / 经验对象** = `Attempt` / `Insight`（承载事实记录与经验判断）；② **第 ⑨ 步独立输出对象** = `Hypothesis`（两类 `kind`：`History-grounded` / `Model Suggestion`，**有独立输出对象与独立裁决位**，见 `TC-07` / `TC-09`）；③ `Experience Asset` **仍不是独立对象** —— 它是 `accepted Insight` 的产品视图 / 业务称呼，**不得**实现为独立实体 / 表 / 集合 / 第三事实对象（`D-015` / `D-027` / `AC-13`） |
| **TC-02** | 层级固定 `User → Personal Workspace → Project → Attempt`；**不得**实现团队 / 成员 / 角色 / 权限 / 管理员 / 协同编辑（`D3`） |
| **TC-03** | `Attempt` 两级状态必须为**持久化状态位**；`Draft` 在检索 / 比较 / `E1` / grounding / `N_检索` **全部链路**上被排除（`D-012` / `AC-02`） |
| **TC-04** | `Formal` 成立条件 = 目标 + 实际尝试 + 实际结果 + **用户显式确认后的结果状态**；缺任一 → **保持 `Draft`**，**系统不得自动升级**（`D-012` / `AC-03`） |
| **TC-05** | 结果状态枚举四态 `Failed` / `Partial` / `Success` / `Unknown`；结果状态来源恒为 `Inference｜decision`，**必须**存在用户显式接受 / 修改动作（`D10` / `D-014`） |
| **TC-06** | 允许缺省的字段（条件 / 判定依据 / 版本·环境 / 关键参数）**必须"显式表达为「未知 / 未提供」"**（**不得以"留空 / 缺省即默认值"的方式隐式丢失**），且**不得被误判为相似**（见 `TC-40`）。**具体物理表示（哨兵值 / NULL + 标记位 / 其他）不在技术硬约束层锁定**，由 **Integrator 收敛**（`TQ08`）（`D-012` / `AC-04`） |
| **TC-07** | 第 ⑨ 步两类 Hypothesis **不得共用 `Insight` 三状态机**；`candidate` 一词不得用于任何 Hypothesis；只有 `undecided` / `accepted` / `rejected` 裁决位（`D-027` / `AC-33`） |
| **TC-08** | `Hypothesis` 与 `Experience Asset` **不得存在直接对象引用**；唯一合法路径必须经「新 `Formal Attempt` → ⑥⑦ → ⑧ → `E1`–`E5`」（`D-041` / `AC-66`） |
| **TC-09** | `Model Suggestion` 的**保存位**与**裁决位必须为两个独立字段**；保存位为真 ≠ 裁决位为 `accepted`（`D-042` / `AC-68`） |

### G2｜`Fact` / `Extraction` / `Inference`

| ID | 技术硬约束 |
|---|---|
| **TC-10** | 每条内容条目**必须**携带 `source_type` ∈ {`Fact`, `Extraction`, `Inference`}；**不可缺省**（`D7` / `D-013`） |

| **TC-13** | **决策型复用门禁**：`decision_state = unresolved` 的决策型 `Inference` **不得**进入依据 / 门槛 / 版本来源 / 比较输入 / 后续决策依据链路（`AC-10` 校准口径 / `AC-96`） |
