## 1. 必须处理的 M6 历史残留："补录 3 次"

### 1.1 残留原文定位

主文档 **§7.2 推荐（Q24）** 的推荐理由末段保留了如下表述：

> 方案 6-1 虽然首屏显得克制，但配合方案 6-3 的补录引导（"**补录 3 次过去的尝试，就能开始生成有依据的假设**"）既诚实又有动力。

**该表述属于 S00-02 首轮稿的历史残留，与修正 G 直接冲突。**

### 1.2 两处问题（不止是数字问题）

| 编号 | 问题 | 说明 |
|---|---|---|
| **P1** | **魔法数字** | "3 次"是未经证据支持的固定阈值，与修正 G（取消 ≥5、不得重新引入 N=3/N=5/N=10）**直接冲突** |
| **P2** | **解锁式语义** | "**就能**开始生成有依据的假设"隐含"**达到该数量即解锁一项能力**"的语义 —— 即使把 3 换成任意数字，**该语义本身仍然错误**：能力不是"攒够条数后被解锁"，而是"**存在相关且可引用的历史来源时即可使用，其质量随相关性与条件完整度变化**" |

> **结论（本会话明确）**：
> **"补录 3 次"作为产品规则 —— 正式废止。**
> 废止对象**不只是数字 3**，还包括**"达到某个数量即解锁能力"的整个语义模式**。任何后续文档、界面文案、Prompt、验收点中，**不得再出现该表述或其等价变体**（如"补录 3 条即可""攒满 3 条解锁""还差 2 条"）。

### 1.3 正确逻辑（替换表述，需人工确认）

> **替换候选（建议直接采用为正式表述）：**
>
> **补录与当前问题相关的历史尝试，可以逐步获得"基于你个人历史"的输出能力。若存在至少 1 条真正相关且可被引用的 `Formal Attempt`，即满足 `History-grounded Hypothesis` 的最低历史来源要求；但仍必须逐项检查：① 相关性；② 条件完整度；③ 证据冲突（是否互相矛盾）；④ N=1 的一般化限制。不得以"补录 3 次"或任何固定数量作为门槛。**

拆解为四条不可违反的规则：

| 编号 | 规则 |
|---|---|
| **R-a** | **最低来源要求 = ≥1 条**真正相关且可引用的 `Formal Attempt` —— 这是**存在性下界**（来源的必要条件），**不是"够多了"的充分性判断** |

### 2.2 子问题：功能入口"可见但标注"还是"完全隐藏"？

> **本子问题只决定产品能力边界，不做最终 UI 视觉（不定义组件、布局、配色、动效）。**

| 方案 | 机制 | 优点 | 风险 |
|---|---|---|---|
| **H-1 完全隐藏** | 证据不足时相关能力入口不出现 | 界面最干净，绝无误导可能 | ① 用户不知道产品有这些能力（长期价值不可见，[D4] 的"长期价值"层无法传达）；② 补录引导失去自然挂点（6-3 无处安放）；③ 会强化 6-1 的"首屏能力少"风险 |
| **H-2 可见但标注为不可用** | 能力入口可见，但显式标注"当前缺少历史来源"及原因，**不作为可用动作呈现** | ① 长期价值可见；② 补录引导自然；③ 不误导 | 需要清晰表达，否则用户会反复点击 |
| **H-3 可见且可点击、点击后输出降级内容** | 即 6-2 的变体 | 交互最"顺畅" | **等价于 6-2，直接违反修正 F**（用 Model Suggestion 填充 History 位置） |

> **推荐（候选）：H-2。**
>
> 关键区分必须写死：
> - **"显示为不可用" ≠ "显示为降级输出"** —— 前者是诚实的状态说明，后者是以模型建议冒充历史依据。
> - **不得用 `Model Suggestion` 填充 `History-grounded Hypothesis` 的位置**；`Model Suggestion` 若要出现，必须在**独立区域 / 独立容器**中以整体标记呈现（见 §4）。
> - **不得把入口渲染为可触发的空动作**（点了没反应或返回"系统错误"），必须给出**状态 + 原因 + 可选下一步**。

## 3. Q25｜N = 0 / N = 1 / N ≥ 2 的能力边界

### 3.1 三档结构差异性论证（为什么三档不是任意切分）

三档的**唯一正当性**在于：三者在**结构上可及的输出类型不同**，而不是"证据质量不同"。

| 档位 | 结构事实 | 因此**结构上不可能**出现的输出 | 因此**结构上可能**出现的输出 |
|---|---|---|---|
| **N = 0** | **不存在任何可引用的历史来源对象** | 任何"引用历史"的输出（`History-grounded Hypothesis`）、任何对照（相似点 / 差异点） | 当前 Attempt 的分析、候选原因、下一步观察什么、可选 `Model Suggestion` |
| **N = 1** | 存在 **1 条**历史来源 | **跨记录比较**（只有一条历史，无第二方可比）、**冲突识别**（无冲突对象） | "当前 Attempt vs 该 1 条"的**两方对照**、**限定在当前具体条件下的局部经验**、**低证据强度的 `History-grounded Hypothesis`** |
| **N ≥ 2** | 存在 **≥2 条**历史来源 | （无结构性封锁） | **可能出现**跨记录对照、**可能出现**冲突识别、`History-grounded Hypothesis` 可引用多条来源 |

> ⚠️ **关键限定**：N ≥ 2 只表示跨记录比较与冲突识别"**可能出现**"，**不表示"已经出现"** —— 若这 2 条历史彼此**不相关**（Level A 无命中），实际仍退化为单条对照。**"结构许可" ≠ "必然行为"。**

### 3.2 逐档能力清单（允许 / 必须 / 禁止）

#### N = 0

| 类别 | 内容 |
|---|---|
| **允许** | 当前 Attempt 分析（①②③④⑤ 步完整）；候选失败原因；`Model Suggestion`（**可选**，须整体标记） |
| **必须** | 明确说明"**当前没有可用于历史 grounding 的记录**"；说明本次为何不产出历史依据型输出；提供**可选**补录路径（§7） |
| **禁止** | `History-grounded Hypothesis`；历史比较（相似点 / 差异点）；**"根据你之前的记录"**类表述；虚构相似 Attempt；把"无历史"呈现为"系统错误"（见 §6） |

#### N = 1

| 类别 | 内容 |
|---|---|
| **允许** | 当前 Attempt 与这 1 条的对照；**低证据强度**的 `History-grounded Hypothesis`；**限定在当前具体条件下**的局部经验表述 |
| **必须** | **显示实际 N = 1**；**标注证据有限**；在依据中说明"未进行比较 / 不存在跨记录对照" |
| **禁止** | 一般性规律；"**方法 X 无效**"；未经证据支持的**适用范围扩张**；把 N=1 表述为"已具备可复用经验的充分证据" |

#### N ≥ 2

| 类别 | 内容 |
|---|---|
| **允许** | 多记录对照；冲突识别（并列呈现矛盾双方，不下结论，§6.5 已定）；`History-grounded Hypothesis` |
| **必须** | 仍**显示实际证据条数 N**；若存在冲突须**显式并列呈现且不下结论** |
| **禁止** | **因 N ≥ 2 就自动声称"规律稳定"**；**自动升级为 `Fact`**；因数量增加而**自动提升可信度表述** |

### 3.3 核心问题的回答：能力该不该"绑定 N"？

> **回答：N 是"结构必要条件"，不是"可信度等级"。**

| 表达式 | 是否成立 | 理由 |
|---|---|---|
| "N 决定**能否**产出某类输出" | ✅ 成立 | 结构可及性判断（§3.1）—— 没有来源对象，就不可能产出引用来源的结论 |
| "N 决定**输出有多可信**" | ❌ **不成立** | 可信度由 **相关性（Level A 命中情况）+ 条件完整度（对应 E3 方向）+ 证据一致性（是否冲突）** 决定；N 只决定"**可以谈论哪些东西**" |

**因此推荐采用的表达方式**：

> **N = 最低结构条件（决定"能谈什么"）；输出质量 = 相关性 × 条件完整度 × 证据一致性（决定"谈得有多可靠"）。**

**必要性证据（一个反例即可证明 N 不是质量指标）**：
N = 3 但三条历史**彼此都不相关**（Level A 无命中）→ 有效证据实际上仍是 **0 条**；反之 N = 1 但该条历史**目标、方案、条件、结果四项高度对应** → 其对照质量高于前者的"3 条不相关记录"。**因此把 N 当可信度等级，会在两个方向上同时出错。**

### 3.4 N 的统计口径（本会话新发现，见 §10 新-T3C-1）

主文档 §7.1 使用 N 时**未定义"是什么的条数"**，存在两种可读法：

| 读法 | 定义 | 问题 |
|---|---|---|
| **读法 A｜库总量** | 用户工作空间内全部 `Formal Attempt` 条数 | 若用户有 20 条历史但**没有一条与当前 Attempt 相关**，读法 A 会得出"N ≥ 2 → 允许跨记录比较"，而实际**无对照可言** |
| **读法 B｜本次相关且可引用量** | 与当前 Attempt **相关（Level A 命中）且可被引用**的 `Formal Attempt` 条数 | 与 §7.1 表格里"能提供 / 不能提供"的实际语义一致 |

> **推荐：采用读法 B。**
>
> **`N_检索`（能力档位口径）≡ 与当前 Attempt 相关（Level A 命中）且可被引用的 `Formal Attempt` 条数** —— 这是**能力边界判定的唯一口径**。
>
> ⚠️ **命名对齐（见 §8.1.2）**：本会话原以"N（本次证据量）"表述该量。**跨会话核对后确认**：该量必须与"**界面实际显示的引用条数**"（`N_引用`，修正 G 的"始终显示实际证据条数"）**区分命名**，否则"检索到 3 条但只引用 1 条"时档位与显示值无法自洽。**canonical 记法 = `N_检索` / `N_引用`**（与 T3-B §5.3 / 新-13 一致）。
>
> 同时，为区分两种不同的空态（**文案与机制需求不同**），另设一个独立状态：
>
> **历史库状态 = 用户是否已存在任何 `Formal Attempt`（空 / 非空）**
> - 历史库**为空** → "你还没有历史尝试记录"
> - 历史库**非空但本次 `N_检索 = 0`** → "**本次未找到相关历史尝试**"（**不得说"你还没有历史记录"**，否则与用户实际所见矛盾）
>
> 该区分**直接决定 §4 的 N=0 语义要求**，属本会话必须闭环的一处。成本：无新增对象、无新增字段（复用既有检索结果），仅需在空态判定中多一个分支。

### 3.5 Q25 最终候选（单一）

> ### **Q25 候选**
>
> **确认 `N = 0 / N = 1 / N ≥ 2` 三档用于"能力边界"，但必须同时锁定三条解释规则与一条口径规则：**
>
> | 编号 | 规则 |
> |---|---|

## 4. Q26｜标注规则：只锁语义要求，不锁 UI 文案

### 4.1 两种做法的比较

| 维度 | **方案 C-1：现在就固定全文案** | **方案 C-2：只锁定语义标签规则（候选）** |
|---|---|---|
| 机制 | 把 §7.3 的三段文案定稿为正式文案，写入机制文档 | 只锁定"必须表达什么语义 / 不得表达什么"，exact wording 留 `08_UI_SPEC.md` |
| 好处 | 实现与验收有唯一字符串可比对 | ① **机制与界面解耦**：机制变更不会让文案成为伪约束；② 文案可以在 UI Spec 阶段结合视觉层级打磨（"整体显著"如何实现是视觉问题）；③ 避免"用界面话术替代机制"（R6 明确反对） |
| 风险 | ① 现在无法判断"整体显著"能否达成（那是视觉问题）；② 文案迭代会与机制文档产生版本分叉；③ 容易让验收退化为"字符串匹配"而非"语义正确" | 需要把语义要求写得足够可判定，否则实现会自由发挥 |
| 与既有约定的一致性 | 与 §2 阶段边界"**不做 UI 视觉**"存在张力 | **一致** —— `08_UI_SPEC.md` 已确立"仅界面约束、不做 UI 设计"的分工 |

> **推荐（候选）：C-2。**
> 理由：**"必须向用户表达什么"是产品机制，"用哪些字表达"是界面规格。** 前者不锁死，机制就无法验收；后者现在锁死，则越过了本阶段边界（S00-02 不做 UI 设计），且会把易变的字符串变成跨阶段约束。

> **术语要求（锁定）**：三类输出的**名称本身**即为语义标签，必须能被用户区分 —— 建议固定使用可区分的中文表述（如"基于你的历史记录" / "模型通用建议" / 空态说明），**但具体用词不锁**。

## 5. Q30｜禁止固定历史数量阈值

### 5.1 候选结论

> **Q30 候选**：**V1 不设置任何"历史够多"的固定 N。** 系统**始终显示实际证据条数 N**。决定能否产生某项能力时，只考虑：**① 是否存在真实相关的历史来源；② 相关性；③ 条件是否足够；④ 证据是否冲突；⑤ N=1 的一般化限制**。
>
> **明确禁止**以下机制及其一切等价变体：
> - 「5 条以上才算完整孵化」
> - 「3 条后解锁」
> - 「10 条才可信」
> - 任何**进度式解锁**表达（进度条、"还差 N 条"、"完成度"）
> - 任何**按数量自动提升**可信度 / 结论强度 / 输出数量的规则

### 5.2 三档与"不设固定阈值"是否矛盾？

> **结论：不矛盾 —— 前提是把二者的"语义类型"区分清楚。**

| | **三档（N = 0 / 1 / ≥2）** | **固定数量阈值（已禁止）** |
|---|---|---|
| 语义类型 | **存在性 / 结构性边界**（possibility boundary） | **充分性门槛**（sufficiency gate） |
| 回答的问题 | "**结构上可不可能**产出这类输出？" | "**够不够好 / 够不够可信 / 够不够完整**？" |
| 跨越边界的含义 | **解除一种结构性不可能**（如：从"不可能出现多源比较"变为"可能出现"） | **达到"证据充足"的认定** |
| 跨越后的系统行为 | 只是**不再封锁**该类输出；**不自动提升**任何结论强度 | **自动解锁**能力 / **自动提升**可信度 / **自动增加**输出数量 |
| 举例 | N=1 → N≥2：从"不可能识别冲突"变为"可能出现冲突" | "3 条后解锁完整孵化"、"5 条以上才算完整" |

### 5.3 判定规则（可操作的检验清单，交 T3-INTEGRATOR 复用）

> 遇到任何"N = 某数字"的规则时，用以下三问判断其合法性 —— **三问全部为"否"才合法**：

| 检验 | 若答案为"是" | 判定 |
|---|---|---|
| **Q-1** 跨越该数字是否会**自动解锁更强的结论类型**或**新能力**？ | 是 | ❌ **属充分性门槛，禁止** |
| **Q-2** 跨越该数字是否会**自动提升可信度表述**（"已充分""更可信""稳定规律"）？ | 是 | ❌ **属充分性门槛，禁止** |
| **Q-3** 该数字是否**绑定输出内容量**（如"解锁 N 张卡片""生成 N 条经验"）？ | 是 | ❌ **属充分性门槛，禁止** |

**应用到本会话三档的检验结果**：

| 边界 | Q-1 | Q-2 | Q-3 | 判定 |
|---|---|---|---|---|
| N=0 → N=1 | 否（只是**解除"无来源"**） | 否（反而**必须标注"证据有限"**） | 否 | ✅ **结构边界，允许** |
| N=1 → N≥2 | 否（只是**解除"不可能多源比较"**） | 否（**不得**自动声称规律稳定） | 否 | ✅ **结构边界，允许** |

### 5.4 与界面相关的禁止项（补充）

- **不得**把 N 渲染为**星级 / 等级 / 分数 / 百分比**（与 [D-020] 同一治理逻辑：不得把 AI / 结构判断伪装成客观度量）；
- **不得**出现"经验库规模"目标、成就、排行榜（[R1]）；
- **不得**用"证据充足 / 证据不足"这类**二元结论**替代"实际条数 + 相关性理由 + 未比对维度"的呈现（§7.1 修订提示已要求"始终显示实际证据条数 N，不得用模糊词替代"）；
- **不得**因 N 较小而**阻断**任何第 ①②③④⑤ 步的动作（§2.3）。

### 5.5 Q30 最终候选（单一）

> ### **Q30 候选**
>
> **不设置"历史够多"的固定 N；始终显示实际证据条数 N；能力判定只依据"是否有真实相关历史 + 相关性 + 条件是否足够 + 证据是否冲突 + N=1 的一般化限制"。**
>
> 同时明确：
> 1. **N = 0 / N = 1 / N ≥ 2 三档与"不设固定较多历史阈值"不矛盾** —— 三档是**存在性 / 结构性边界**，不是**充分性门槛**；
> 2. 合法与非法边界值以 **§5.3 三问检验**判定（三问全"否"才合法）；

> 4. 界面**不得**把 N 渲染为星级 / 等级 / 分数，**不得**用"证据充足 / 不足"替代实际条数与相关性说明。

## 6. Runtime / Demo / Acceptance 区分（本会话必须形成的集成规则）

### 6.1 问题

真实用户在首次使用时 **N = 0 是正常状态**（对 [D4] 的"刚发生一次失败"用户而言，甚至是最常见的首用状态）。系统此时**必须诚实降级**：说明"当前没有可用于历史 grounding 的记录"，并**不产出** `History-grounded Hypothesis`。

但 **[D9] 是 V1 完整闭环的验收口径**（十步任一环节无法完成即 V1 未完成），而第 ⑨ 步要求"至少生成 1 条可验证的新假设"（§8.9）且第 ⑩ 步要求其可追溯（§8.10）。

**若不作区分，就会出现两类可预见错误**：

| 错误方向 | 表现 | 后果 |
|---|---|---|
| **E-1（Runtime 侧）** | 真实 N=0 时第 ⑨ 步无法产出历史依据型输出 → 界面声称"**系统错误 / 生成失败 / 功能不可用**" | 用户把**正常的诚实降级**理解为**产品缺陷**；同时诱导实现者用 `Model Suggestion` 冒充历史依据（违反修正 F） |
| **E-2（验收侧）** | 为了"保证演示能过"，把**没有历史依据的模型建议**计入 ⑨⑩ 验收 | 验收结论虚假；违反修正 F"两条硬边界" |

### 6.2 三方区分（本会话正式提出）

| 场景 | 历史来源 | 第 ⑨ 步应产出 | 是否计入 P0 验收 |
|---|---|---|---|
| **Runtime（真实用户，N=0）** | 无相关且可引用的 `Formal Attempt` | **不产出** `History-grounded Hypothesis`；**诚实说明**原因；可选 `Model Suggestion`（独立标注） | **不计入**（因为本场景**不承担 ⑨⑩ 的验收职责**） |
| **Demo（[D8] 预置 + 现场新增）** | **必须保证**至少 1 条**相关且可引用**的 `Formal Attempt`（来源须标注为示例数据） | **必须产出** `History-grounded Hypothesis`，其引用的历史为 Demo 数据 | 演示用；**其历史来源须标注为示例数据** |
| **Acceptance（正式验收，D9）** | **使用 [D8] 的预置 Demo Attempts** | **必须完整走通 ⑥ → ⑦ → ⑧ → ⑨ → ⑩**，且 ⑨ 产出 `History-grounded Hypothesis`、⑩ 证据可点开核对 | **计入**（唯一验收口径） |

### 6.3 集成规则（**直接交给 T3-INTEGRATOR，建议原文收编**）

> ### 规则 T3C-INT-1｜Runtime 冷启动降级 ≠ P0 功能实现不完整
>
> 1. **真实用户 N = 0 是正常状态。** 系统必须**诚实降级**：明确说明"当前没有可用于历史 grounding 的记录"，并**不产出** `History-grounded Hypothesis`。
> 2. **不得**因为第 ⑨ 步无法产生 `History-grounded Hypothesis` 而在产品界面声称"**系统错误 / 生成失败 / 功能异常**"。该状态是**产品设计的一部分**，不是故障。
> 3. **[D9] 是 V1 完整闭环的验收口径。** 因此**正式验收场景使用 [D8] 的预置 Demo Attempts**，**保证至少存在 1 条相关且可引用的历史记录**，从而完整走通 ⑥ → ⑦ → ⑧ → ⑨ → ⑩。
> 4. **Runtime cold-start degradation ≠ P0 feature implementation incomplete。** 二者是**不同层面**的判断：
>    - **P0 实现完整性** = 在**具备相关历史来源**的条件下，⑥⑦⑧⑨⑩ **能否**被完整执行（由 Acceptance 场景验证）；
>    - **Runtime 冷启动降级** = 在**不具备相关历史来源**时，系统**能否诚实、可用、不误导地降级**（属产品正确性，需**单独的**冷启动验收点，见 §6.5）。
> 5. **验收不得依赖"用户先补录"** —— 不得要求演示 / 验收前由人工补录数据来"凑出"历史来源；历史来源必须由 [D8] 预置数据提供。
> 6. **不得**用 `Model Suggestion` 填入 ⑨⑩ 的验收结果（修正 F 两条硬边界不变）。
> 7. **不得反向推论**："Demo 能走通 ⑨⑩" **不等于** "真实用户在任意 N 下都能走通 ⑨⑩"。

## 7. 补录历史机制（正确表达）

### 7.1 两种表达的比较

| 维度 | **A.「补录一条相关历史尝试即可开始获得基于历史的能力」** | **B.「补录过去相关尝试，历史越完整，系统越能给出有依据的比较」** |
|---|---|---|
| 优点 | ① 给出**明确的起点动作**（知道第一步做什么）；② 与"最低来源要求 ≥1 条"（修正 F）**同源**；③ 与 [D4] 低成本一致 | ① 不会暗示"单条即充分"；② 表达**边际价值**（越用越强） |
| 风险 | **可能被读成"1 条就够了 / 1 条证据就充分"** → 逼近 [D7] N=1 限制的边界 | ① **"越完整"是一个滑向"数量"的措辞** —— 与 §5 禁止的阈值思维形态相近；② 缺少"最低起点"，用户可能觉得"要做很多才有效"，与 [D4] 冲突 |
| 与修正 G 关系 | 不引入数字，**合法** | 不引入数字，**合法**（但措辞需收紧） |

> **两者单独使用都不完整**：A 缺"质量随什么变化"，B 缺"最低起点"，且 B 的"完整"措辞会把锚点滑向数量。

### 7.2 推荐候选：A + B 组合，并把质量锚点从"数量"改为"相关性 + 条件完整度"

> **补录机制表述候选（需人工确认）：**
>
> > **补录与当前问题相关的历史尝试，可以逐步获得"基于你个人历史"的输出能力。**
> > **补录的历史越相关、条件记录得越清楚，系统能给出的比较就越有依据。**
>
> 并且必须**同时说明**（避免暗示"1 条已充分"）：
>
> 1. 仅有 **1 条** 相关历史时，系统能给出的只是**限定在当前具体条件下的局部结论**，并会**明确标注证据有限**；
> 2. 当存在 **≥2 条相关**历史时，系统才**可能**做跨记录对照与冲突识别（**仍不自动声称规律稳定**）；
> 3. 补录是**可选路径**，**不补录也能使用**当前的即时能力（[D4]）。

**关键修正点**：把 B 中的"**历史越完整**"改为"**历史越相关、条件记录得越清楚**"。
理由：**把质量锚点从"数量"移到"相关性与条件完整度"**，与 §3.5 R2 完全一致；否则"越完整"会被实现为"条数越多越好"，重新滑回被禁止的阈值思维。

### 7.3 补录数据的来源属性（本会话新发现，见 §10 新-T3C-2）

**补录的尝试通常是"事后回忆"录入**，其字段精度（尤其"条件""发生时间"）低于现场记录。若不区分，会污染第 ⑥⑦ 步的比较结果。

| 规则（候选） | 内容 |
|---|---|
| **补录不得降低门槛** | 补录记录仍须满足 `Formal Attempt` 四项门槛（[D-012]）才能进入检索与孵化；**不得为补录设置更宽的门槛**（否则污染比较集合） |
| **须标注来源** | 补录记录须标注其来源性质（现场记录 / 事后补录）。**复用 [D-013] 既有「系统自动 → 数据来源」字段表达，不新增字段类别**（Q03 字段框架不得扩张） |
| **时间字段须区分** | 需分别保留"**记录时间**"与"**发生时间**"（§2.2 已含 `created_at` + 可选"发生时间"，**正好可用，无需新增**） |
| **"补录"不得作为相关性维度** | 不得因"两条都是补录"判为相关 —— 它既非 Level A 也非 Level B（[D-019]），**不得进入相关性判断** |
| **补录不改变 N 的口径** | 补录产生的 `Formal Attempt` 与现场记录**同等计入 N**（N 按"相关且可引用"计），但**其时间精度差异须在界面可说明** |

### 7.4 补录入口的时机（候选，不做 UI 设计）

| 时机 | 是否建议 | 说明 |
|---|---|---|
| **N=0 空态旁**（说明当前无历史来源时） | ✅ 建议 | 与 6-3 的落点一致；此时用户最可能理解"为什么要补录" |

#### 8.1.2 `N` 的口径必须拆成两个（T3-C ↔ T3-B ↔ T3-A 的合并项，**三方已独立收敛**）

T3-B **M-2 / §5.3** 定义 `N` = 假设**实际引用且可作为证据**的条数；T3-C **§3.4** 定义 `N` = **与当前 Attempt 相关且可引用**的条数。**二者不是同一个量。**

若都记作 `N`，必然出现两种无法自洽的场合：
- **检索到 3 条相关记录，但只引用 1 条作为证据时，档位是 `N ≥ 2` 还是 `N = 1`？**
- **用检索量显示** → 用户看到"引用 3 条"，而 [D9] ⑩ 的追溯清单只有 1 条 → **破坏可核对性**。

> ✅ **已收敛**：T3-B 在收尾交叉核对中**独立**得出同一结论（其 §5.3 与 **新-13**），并已采用 **`N_检索` / `N_引用`** 作为记法。**本会话采纳该记法为 canonical**，不再新造名称（`N_gate` / `N_cite` 仅作本文件内的等价别名，**不得**在合并版本中保留）。

| 记法（**canonical**） | 等价别名（**仅本文件内**） | 定义 | 用途 | 归属 |
|---|---|---|---|---|
| **`N_检索`** | `N_gate` | 与当前 Attempt **相关（Level A 命中）且可被引用**的 `Formal Attempt` 条数 | 判定 **`N = 0 / 1 / ≥2` 的能力边界档位**（"结构上可不可能"） | T3-C §3.4 / Q25-R3 |
| **`N_引用`** | `N_cite` | 该输出**实际引用**并作为证据（支持 / 反驳 / 上下文）的 `Formal Attempt` 条数（**须标角色**） | **界面显示给用户的"实际证据条数"**（修正 G）+ [D9] ⑩ 追溯清单 | T3-B M-2 / §5.3；与 T3-A §2.3.1 一致 |

**四条关键规则（候选）**：

1. **界面显示给用户的是 `N_引用`**；**能力档位由 `N_检索` 决定**。
2. 当 `N_检索 ≥ 1` 时恒有 `1 ≤ N_引用 ≤ N_检索`；`N_检索 = 0` 时**不存在 `N_引用`**（无历史证据）。
3. `N_检索 ≥ 2` 但 `N_引用 = 1` 时：档位仍为 `N ≥ 2`（**结构上允许**跨记录比较），但 **不得**因此声称"多源一致 / 规律稳定"（与 T3-B P3 / M-8 一致）；界面如实显示"引用 1 条"。
4. **`Draft` 不计入任何一层**；**`Model Suggestion` 没有 N**（与 T3-B §5.3 一致）。
