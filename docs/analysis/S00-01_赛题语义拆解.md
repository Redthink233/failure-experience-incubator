## A.「失败尝试」的边界

**先给一句可操作的定义：**

> **失败尝试 = 有明确目标 G + 实际采取了方案 M + 在可描述的条件 C 下产生了可判定的结果 R，且 R 与 G 不符。**

四个要素：**目标、动作、条件、可判定结果**。这个定义的价值在于它能同时挡住两边的偏差——

- **定义过窄**（只把"跑不通/彻底崩了"算失败）会丢掉最有价值的两类：*效果未达预期* 和 *成本不可接受*；
- **定义过宽**（把任何不顺利都算失败）会让噪声淹没信号，用户也会因为"什么都要记"而直接放弃记录。

### A1. 什么可以称为"失败尝试"

| 类型 | 大学生科研/竞赛场景下的例子 | 沉淀价值（AI 判断） |
|---|---|---|
| 完全不可行 | 方案跑不通；核心假设不成立 | 高：排除一整条路线 |
| 效果未达预期 | 能跑，但精度/效率/体验明显不够 | 高：产生"边界"信息 |
| 条件性失效 | 在特定数据、规模、环境下无效，换条件也许有效 | 最高：最典型的边界知识 |
| 成本不可接受 | 可行，但时间/算力/标注/人力超预算 | 高：最常被忽略的决策信息 |
| 假设被证伪 | 前提判断本身错了 | 最高：认知层修正 |
| 技术路线不适用 | "用 X 类方法解决 Y 类问题"整条路线不成立 | 高 |
| 不可复现/不可解释 | 结果出来了但说不清为什么、复现不了 | 中高：可信度信息 |
| 被外部否决 | 导师/评审/用户/合规否掉 | 中：非技术性失败，但真实存在 |
| 机会成本型取舍 | 因为做了 A 所以没做 B，A 无收益 | 中：需要额外上下文才成立 |
| 停滞/重复尝试未推进 | 试了很多轮，结论没变化 | 中 |

结论：**"失败"不等于"最终结果完全失败"。** 上述五种（效果未达预期、特定条件下无效、成本过高、假设被证伪、技术路线不适用）全部成立，其中"条件性失效"和"假设被证伪"的复用价值被认为最高——因为只有它们给出了**适用范围**。

### A2. 什么只是普通错误，不值得沉淀

判据是三条，只要满足第 1 条，基本就可以排除：

1. **修正它只需要一条已知的、确定的规则** → 笔误、路径写错、参数名写错、忘了设随机种子、环境配置、库版本冲突、API 用法错误、忘记申请算力。
2. **它是一个"操作"问题而不是"判断"问题** → 记录价值低，因为下次不会再犯，或者查一次文档就能解决。
3. **它不携带任何关于"什么条件/什么方案不行"的信息** → 一次性资源故障、网络超时、机器被占用。

一句话：**可以被"规则、文档、工具、规范"消除的叫错误；需要"权衡、经验、判断"才能避免的才叫失败尝试。**

### A3. 什么样的失败具有未来复用价值

满足以下条件越多，价值越高（这是一份**筛选标准**，不是评分表）：

- **目标可类比**：别人或未来的你大概率会遇到同类目标（而非极端个人化的需求）；
- **条件可描述**：能说清"在什么条件下失败"，而不是"就是不行"；
- **方案可复述**：能说清当时做了什么、关键参数是什么；
- **结果可判定**：能说清"怎么算失败、阈值多少、是否客观"；
- **具有排除力**：它能排除一整类做法，或对某类情形加约束；
- **不能从公开常识直接推出**：如果查资料就能知道，就不必作为个人经验沉淀。

反过来——**无法判定结果的尝试是低价值记录**：因为你不知道是方法错还是实现错，它会把错误结论传染给未来的自己。

### A4. 一次失败至少需要保留什么上下文

分成**必备 6 项**和**强烈建议 6 项**。这份清单的作用不是"叫用户填表"，而是**定义最低可复用信息集**。

必备（缺项会显著降低可用性）：

1. **目标与预期**（量化或明确的可判据）——同一个动作在不同目标下意义完全不同；
2. **条件 C**：任务领域、数据/素材、规模、环境与版本、时间与资源预算；
3. **方案 M**：做了什么、关键步骤、关键参数；
4. **实际结果 R**：可观测的证据（数值/日志/截图/反馈），不是印象；
5. **判定依据 J**：用什么指标判定失败、阈值、是客观还是主观；
6. **失败类型**：落在 A1 表格的哪一类（这决定了它将来怎么被复用）。

强烈建议：

7. **归因假设 + 置信度**——必须显式标注为"假设"而不是"原因"；
8. **排除项**：这次尝试顺便排除了什么；
9. **与最近一次相似尝试的差异点**——**这一项最关键也最容易被忽略**，没有差异点就无法判断是哪个条件导致的结果变化，也就无法形成边界；
10. **成本**：人时 / 算力 / 金钱；
11. **可复现性**：能否重复出现；
12. **来源**：谁、哪个项目、什么时间、什么版本。

### A5. 边界小结

**一次有目标的主动尝试，其可判定的结果与预期不符，且其中最关键的差异条件被记录下来了——这就是一条合格的失败尝试。**

## B.「失败经验累积」的含义

**本质区别：记录是"事件日志"，累积是"知识网络"。**（此为类比表述，描述逻辑层需求，不指向任何技术实现）

- 保存记录：以**时间**为主键，人和事是附属信息；每条独立；价值 = 记忆。
- 失败经验累积：以**问题/原因/方案/条件**为可对齐维度，新记录进入时能与旧记录产生关系；整个集合的能力随时间增长；价值 = 决策依据。

### B1. 为什么单独保存一条失败记录价值有限

- **无法区分偶然与规律**：一次失败可能只是那次的实现 bug；
- **无法判断普适性**：不知道是方法问题、环境问题还是人的问题；
- **无法被检索命中**：未来你描述当前场景的措辞，和当时记录里写的完全不一样（语义鸿沟）；
- **归因无法交叉验证**：单条记录里的原因只是一个人的主观判断；
- **只能给出"在这次不行"**：而复用需要的是"在什么条件下不行"。

### B2. 多条记录在什么情况下才真正形成"经验积累"

必须同时满足：

1. **存在共同的可对齐维度**（同一问题 / 同一方法 / 同一类数据 / 同一失败模式）——这正是"结构化解析"存在的理由：没有对齐维度，多条记录只是多条散文；
2. **失败之间具备可比性**：同一目标下的不同方案，或同一方案在不同条件下的表现；
3. **有对照**：失败与成功（或"部分成功"）成对出现才有说服力。只有失败、没有成功做对照，结论的可信度会明显下降【需人工确认：是否纳入成功/部分成功记录】；
4. **带时间与版本信息**：能看出结论的演化。失败经验被认为会过期——去年成立的结论今年可能已经失效；
5. **有来源与可信度**：谁记录的、证据强度如何；
6. **有收敛机制**：100 条"模型幻觉严重"应当收敛为少数几个真实原因，否则积累量越大越难用。

### B3. 时间 / 项目 / 人员 / 技术方案之间是否应该产生联系

**应该，但主张是"有目的的连接"，不是"全部互联"。** 这四个维度的存在意义被假设为回答四类具体问题：

| 维度 | 它唯一要回答的问题 |
|---|---|
| 时间 | 这个结论现在还成立吗？**先后尝试顺序**是怎样的？ |
| 项目 | 同样的坑在另一个项目会不会重演？ |
| 人员 | 是个人水平问题，还是**多人都会踩的系统性问题**？ |
| 技术方案 | 同一方法在什么条件下成功、什么条件下失败？ |

**反过来说：如果一个关联不服务于上面任何一个问题，就不建议连。** 这是不主动上大型知识图谱的论证方向之一（最终依据应为 `00_PROJECT_RULES.md` 规则 2）。

### B4. 用户积累之后真正想获得什么（候选，未选定）

1. 不要重复踩同一个坑（**避坑**）；
2. 当前问题一出，就能快速定位可能原因（**省时间**）；
3. 知道哪些方案已经被证伪，缩小搜索空间（**省成本**）；
4. 知道方法的适用边界，做出更好的取舍（**提高决策质量**）；
5. 得到下一步真正值得验证的方向（**孵化**）；
6. 把个人教训变成团队资产，让新人不必重走（**组织记忆**）；
7. 科研场景特有：形成"负面结果"部分——**负面结果本身就是科研产出**；
8. 一个主张：**价值不是"越久越值钱"，而是"越用越值钱"**。不参与决策的记录难以产生价值。

## C.「经验资产化」的含义

### C1. 一条失败经历何时算转化为知识资产

转化条件（候选）：

- **自包含**：脱离原始情境后仍能被理解，不需要去问原作者；
- **可独立引用**：有标识、有来源、有边界，能被当作一条"命题"引用；
- **有可判定的适用范围**：能说清"在什么条件下这条经验成立"；
- **至少能回答一个可复用的问句**："如果我要做 X，这条经验告诉我什么？"
- **被验证过或至少有明确的证据强度**（1 次 ≠ 5 次）；
- **能改变一个决策**（最终极的判据）。

### C2. 知识资产的特点

| 特点 | AI 判断的必要性 | 说明 |
|---|---|---|
| 可理解 | 必要（最低门槛） | 不理解就无法复用 |
| 可检索 | 必要 | 但**关键词检索不够**，需要按"失败模式 / 适用条件"检索 |
| 可比较 | **核心** | 资产化的核心被认为是可比性：不同记录必须能在同一维度上对齐 |
| 可复用 | 目的 | 复用的前提是适用条件清楚 |
| 有上下文 | 必要 | 缺上下文必然被误用 |
| 有来源 | 必要 | 可信度的基础 |
| 有适用范围 | **关键** | 被认为是"经验"与"偏见"的分界线 |
| （补）有证据强度/置信度 | 必要 | 1 次 vs 5 次，结论强度完全不同 |
| （补）有时效性 | 必要 | 版本 + 过期标记，技术迭代快 |
| （补）有成本信息 | 重要 | 避免重复投入高成本尝试 |
| （补）可溯源到原始证据 | 重要 | 结论一旦有错可以回退，否则无法纠错 |
| （补）可组合 | 加分 | 能与其它经验合并为更高层结论（网络效应的前提） |

### C3.「失败记录」与「失败知识资产」的本质区别

| | 失败记录 | 失败知识资产 |
|---|---|---|
| 中心 | "我做过什么" | "什么条件下什么做法不成立" |
| 视角 | 事件 | 命题 |
| 读者 | 作者本人 | 任何人（含未来的自己） |
| 结构 | 叙述 | 可对齐字段 |
| 置信度 | 隐含（读起来都很确定） | 显式（证据强度） |
| 价值 | 记忆 | 决策依据 |
| 失效 | 一般不失效 | 可能过期 |

一句话：**记录是"经历的存档"，资产是"可被引用的判断"。**

### C4. 为什么 AI 写出一段漂亮的总结还不算资产化

1. **只压缩、不结构化** → 十条总结仍是十段互不对齐的散文，无法比较；
2. **没有新增可判定信息** → 没有明确适用条件、没有证据强度，读完仍然不知道"什么条件下该照做"；
3. **会引入无依据推理** → 把"可能原因"写成"原因"，把猜测变成断言；
4. **不可按条件检索** → 一段流畅的散文匹配不上"当前场景"；
5. **不可累积** → 数量增长不会自动产生关系，只会更乱；
6. **不可追溯** → 丢了原始证据，总结一旦出错无法回退；
7. **判据**：**如果用户读完这段总结，做决策时不比读之前更有把握，那就不是资产化。**

## D.「知识挖掘」的含义

### D1. 单条失败记录内部的信息提取（A 层）

**做的事**：把叙述变成结构化要素——目标、条件、方案与参数、预期/实际、判定依据、失败类型、归因假设、排除范围、成本。

**定位**：信息抽取 + 归一化。**它不产生新判断**，只是让记录"可比"，其价值体现在为 B 层服务。

**风险特征**：风险是"抽错"（字段填错、条件漏抽），可检测、可回溯。

### D2. 多条失败记录之间的知识发现（B 层）

**做的事**：产生**单条记录里根本不存在的新命题**：

- 重复出现的**系统性模式**（同一原因跨项目出现 → 说明是流程问题，不是个人水平）；
- **条件-结论映射**（方法 M 在条件 C 下多次失败 → 得到适用边界）；
- **尝试历史**（M1→M2→M3 的顺序 → 已走过的路径与未探索的空隙）；
- **反例对照**（M 在 C1 失败、在 C2 成功 → 是边界，不是绝对结论）；
- **冲突检测**（两条经验互相矛盾 → 需人工裁决）；
- **时效失效**（结论因版本变化而过期）。

**风险特征**：风险是"推错"——把相关性当因果、样本太少形成伪模式、条件记录不全导致虚假边界。

### D3. 两者的本质区别

| | A：单条内提取 | B：跨记录发现 |
|---|---|---|
| 信息性质 | 无损搬移（文本→字段） | 有推理跳跃（字段→新命题） |
| 主要风险 | 抽错 | 推错 |
| 价值增长（推断） | 近似线性 | 非线性（有网络效应，错误也被放大） |
| 可自动化程度 | 高 | 需要保留人工确认环节 |
| 输出性质 | 可视为"记录内容"（可溯源到原文） | 应视为"候选结论" |
| 输出时机 | 录入后即可 | 需要足够样本量才有意义（**冷启动问题**） |

**关键判断（AI 提出）**：A 层输出可标成"记录内容"；**B 层输出应标成"待人工确认的候选结论"**，因为它一旦被当成事实使用，风险高于没有系统。

## E.「孵化」的 6 种候选解释

**先立一个判据（AI 提出，未确认）**：

> **孵化输出 = 一个可执行 + 可证伪 + 有历史失败证据支撑 + 此前不在用户认知内（或未明确）的下一步。**

- AI 总结：输出指向**过去**（压缩已有信息）；
- AI 聊天：输出等于**模型的先验知识**，与用户历史无关；
- **孵化：输出指向未来，且必须能挂到用户自己的历史上作为依据。**

以下每种均按 6 问回答，**全部为候选，未选定**。

### E1. 共性失败模式挖掘（从多条失败中发现共同规律）

1. **输入**：一批失败记录（≥N 条，N 待定）。
2. **利用的历史**：跨记录的原因字段与条件字段。
3. **给用户什么**：一条"系统性失败模式"陈述 + 支撑它的原始记录列表 + 出现频次 + 反例数。
4. **为什么算孵化**：单条记录只能得出"我犯了个错"；跨记录才能得出"我有一个系统性盲区"，它把改进对象从"某个点"提升到"做法/流程本身"。
5. **最大风险**：过度聚类（把不同原因硬拉到一起）、样本太少形成伪模式。
6. **防幻觉（方案层提议）**：无支撑记录不出结论；附反例列表；低于阈值只输出"疑似"并标注样本数；只从已有归因假设中归纳，不生成记录里从未出现过的原因。

### E2. 适用边界显式化（从失败中识别方案适用边界）

1. **输入**：用户想尝试的新方案/当前场景描述 + 相关历史记录。
2. **利用的历史**：同一或相似方法在不同条件下的成败。
3. **给用户什么**：一组边界陈述——"M 在条件 A / 规模 B / 资源 C 下已被证明无效；在条件 D 下尚未尝试"。
4. **为什么算孵化**：它把方案选择从"选最优"变成"选可行"，并顺带划出"未尝试区域"——那是后续孵化的原料。
5. **最大风险**：条件记录不全 → 得出虚假边界（"X 无效"可能只是那次实现有 bug）。
6. **防幻觉（方案层提议）**：需让用户确认"是方法失败还是实现失败"；边界只能由已有条件字段生成，缺失即标"条件未知，不可作为边界证据"；每条边界附反向查询结果。

### E3. 未探索组合生成（发现尚未尝试的可能组合）

1. **输入**：当前问题的候选方案集合 + 已尝试历史。
2. **利用的历史**：已尝试的"方案 × 条件"组合矩阵。
3. **给用户什么**：历史上未试过的组合，按预期收益/成本排序的少量候选。
4. **为什么算孵化**：这是输出"新东西"的形式之一，且其"新"不是模型凭空想的——是从"已尝试集合的补集"里定义的，有构造依据。
5. **最大风险**：空白 ≠ 有价值（空白组合是无穷多的），极易退化成随机脑暴。
6. **防幻觉（方案层提议）**：候选先过历史负例过滤；组合名必须由已出现过的方案 × 已出现过的条件交叉生成；数量设上限；每条说明"为什么这个空白值得填"。

### E4. 待验证假设生成（基于历史失败生成下一轮实验/尝试方向）

1. **输入**：当前问题 + 最相关的若干条历史失败。
2. **利用的历史**：相关失败记录及其排除范围。
3. **给用户什么**：1–3 张"假设卡"：如果做 X → 预期 Y → 若观察到 Z 则假设不成立，并附预期指标、判定阈值、成本估计、作废条件。
4. **为什么算孵化**：它不是建议，而是**一份可实验化的研究计划**；失败经验在这里变成了"设计下一次实验的约束条件"。
5. **最大风险**：假设不可证伪 / 成本超出用户能力 / 期望值其实早已被历史否定。
6. **防幻觉（方案层提议）**：强制结构（假设-预期-判定-反证条件-成本）；每条引用 ≥1 条历史记录，否则显式标注"依据为模型先验，低置信"；与历史失败冲突时显式提示并降级。

### E5. 尝试前历史碰撞预警（提醒某个新方案曾经失败过）

1. **输入**：用户即将/正在实施的一个方案。
2. **利用的历史**：相似场景下的失败记录。
3. **给用户什么**：提醒——"相似条件下曾失败过，当时的差异是 A/B/C，请自行判断是否适用"，同时给相似点与差异点。
4. **为什么算孵化**：时机在行动之前，改变的是行为而不是事后总结；它是"防止无效重复投入"较直接的价值。
5. **最大风险**：误报（把相似但不同的情况当成同一情况）→ 用户失去信任；过度提醒 → 用户不敢尝试。
6. **防幻觉（方案层提议）**：只提醒、不阻止；标注相似度依据；错误代价偏向"宁可漏报，不可误报"。

### E6. 尝试路径重构（把零散失败还原成研究路线）

1. **输入**：某课题的多轮失败记录（带时间）。
2. **利用的历史**：按时间排列的方案演进链。
3. **给用户什么**：该课题的尝试路径 + 哪个节点发生了方向性转折 + 当前处在路径的哪一步 + 尚未走过的分支。
4. **为什么算孵化**：它把"一堆尝试"变成"一条路线"，让用户看到自己是在前进还是在原地打转（识别停滞）。
5. **最大风险**：需要足够多记录才成立；早期用户（只有 2–3 条记录）不可用。
6. **防幻觉（方案层提议）**：只基于实际记录绘制，不推测未记录的尝试；标注"记录可能不完整"；不输出"你应该转向"这类结论。

### E7.（补充候选）归因反驳：挑战用户自己给出的失败原因

1. **输入**：一条失败记录 + 用户给出的原因。
2. **利用的历史**：出现相同表现、但被归因为别的原因的其他记录。
3. **给用户什么**："同一现象在另外 N 条记录中被归因为 X，也存在 Y 解释"，并列呈现。
4. **为什么算孵化**：它改变的是用户的认知模型本身，而不是行动清单。
5. **最大风险**：AI 推断冒充事实、越权否定用户判断。
6. **防幻觉（方案层提议）**：只提问、只并列解释、不下结论；引用"有相同现象的历史记录"作为依据。

### E8. 孵化形式共享的约束（AI 提议，未确认）

| 约束 | 含义 | 若违反的后果（推断） |
|---|---|---|
| 可追溯 | 每条结论必须能挂到原始记录 | 结论无法验证，等于幻觉 |
| 可证伪 | 必须说明"什么情况下这条结论不成立" | 变成不可反驳的鸡汤 |
| 可拒绝 | 必须给置信度，并提示"可能是错的" | 用户把候选当事实 |

另需注意：**零历史时无法孵化**，孵化能力随积累量增长（推断）。演示数据方案见《状态校正表》相关条目。

## F. 与普通 AI 聊天 / 笔记 / RAG / 复盘工具的区别

| 产品 | 已经能做什么（一般化描述，未实测） | 对本项目的缺口（AI 判断） |
|---|---|---|
| **AI 聊天机器人** | 就任意问题给通用建议（来自预训练先验）、流畅交互 | 与用户自己的历史无关、不积累、答案随措辞漂移、不可追溯。它给的是"人类一般经验"，不是"你已验证过的边界" |
| **AI 笔记工具** | 存储、搜索、摘要、标签 | 存储 ≠ 资产；标签是自由文本，难以按条件比较；摘要把内容变流畅但不产生可对齐结构；缺少"结论"和"置信度"概念 |
| **RAG 知识库问答** | 检索相关文档并回答 | 它回答"你文档里写了什么"（事实检索），不回答"这个条件组合下还没试过什么"（推理生成）；检索相似 ≠ 结论可比；且倾向把"最相似内容"当答案，可能无视条件差异直接复制旧结论 |
| **项目复盘工具** | 按模板记录"做了什么/好的/差的/改进" | 复盘是项目级、周期性、面向过程的；失败经验是跨项目、跨时间、面向结论的；模板文本不可计算；复盘产物通常是文档，不参与未来决策 |
| **普通知识库（Wiki）** | 分类、长期保存、多人编辑 | 需要人主动维护分类；失败信息天然跨维度，不适合主题分类；只有关键词检索；需要人主动去读 |
| **AI 总结工具** | 把长文本压缩成要点 | 只做信息压缩，不产生新命题；不可比较；可能平滑掉不确定性（把猜测写成断言） |

**统一主张（AI 提出）**：这些产品都以"内容"为中心（文档、消息、页面、相似度），本项目主张做到以「失败命题」为中心——一条命题 = 条件 + 方案 + 结论 + 证据强度 + 适用范围。

被主张需要多做到的四件事：

1. **结构化到可比**（让不同记录在同一维度上对齐）；
2. **跨记录产生新命题**（而不是检索已有内容）；
3. **输出是候选假设且可追溯**（而不是流畅的建议）；
4. **时机在行动之前**（预防性触达，而不是事后总结）。

**同时需注意（AI 判断，待确认）**：这四点是方向与程度上的差异，不是全新品类。

## G. 候选核心问题定义

格式：**用户虽然____，但是因为____，导致____。**

**候选 1（积累动机）**
用户虽然知道失败经验有价值，但**因为记录失败在当时没有任何即时回报、还要额外花时间**，导致失败经验在产生的那一刻就流失，事后无法重建。

**候选 2（复用失效）**
用户虽然存下了一些失败记录，但**因为记录是叙述性的、缺失当时的条件与差异点**，导致未来遇到相似问题时无法判断旧结论是否适用，只能重新试一遍。

**候选 3（归因失信）**
用户虽然在记录里写了失败原因，但**因为归因是主观猜测且没有证据分级**，导致后来的自己或他人把猜测当成事实，依据错误结论做决策——风险高于没有记录。

**候选 4（无法发现）**
用户虽然积累了很多条失败，但**因为记录之间没有共同的可比较维度**，导致无法看出重复模式与适用边界，积累量再大也不产生新认识。

**候选 5（无法外推）**
用户虽然清楚"什么不行"，但**因为系统只能回溯过去、不能外推**，导致在排除旧方案之后仍然停在原地，得不出下一步值得验证的方向。

**候选 6（跨人失效）**
用户虽然团队多人都踩过同类的坑，但**因为经验绑定在个人和单个项目上**，导致同一个坑在不同项目、不同人身上反复出现。

**候选 7（时机错位）**
用户虽然系统里确实存着相关的失败经验，但**因为经验只在被主动查询时才出现**，导致在做出关键决策的那一刻它没有出现，经验实际上从未参与决策。

## H. 当前最大的产品风险与歧义

### H1. 用户已列出的风险（AI 表示同意，不构成确认）

| 风险 | 表现形式 | AI 判断的后果 | 缓解方向（AI 提议） |
|---|---|---|---|
| 定义过宽 | 把任何不顺都算失败 | 记录质量崩坏，噪声淹没信号，用户弃用 | 明确纳入/排除清单 + 强制结构字段 |
| 场景过多 | 科研/竞赛/课程/创业都做 | 条件维度不统一，可比性失效 | 先限定一个场景下的一类失败 |
| AI 幻觉 | 编造原因、编造"没人试过" | 结论不可信，系统失去价值 | 证据绑定 + 无支撑不出结论 |
| 相关性误判因果 | 两条记录都提到 X 就归因为 X | 产出错误结论并被当真 | 只呈现共现，不下因果；因果陈述需人工确认 |
| AI 推断冒充事实 | 把"可能原因"写成"原因" | 用户依据错误结论做决策 | 字段级区分事实/推断，界面上视觉区分 |
| 孵化变成普通脑暴 | 输出 = 模型通用建议 | 与直接问 AI 没有区别，失去赛题价值 | 输出必须引用历史记录；无引用不得输出 |
| 做成普通知识库 | 只是能存能搜 | 无差异化，评分吃亏 | 验收标准应包含"跨记录产出新命题" |
| 为技术感上大型知识图谱 | 图很漂亮但没人用 | 成本极高、10 天做不完、无实际查询驱动 | 先用结构化关系字段满足需求；最终以规则 2 为准 |
| 10 天范围失控 | 什么都想做 | 闭环跑不通，无法演示 | 优先单条闭环，孵化只做 1 种 |

### H2. AI 补充的风险（全部未经验证）

| 风险 | 说明 |
|---|---|
| 冷启动 | 没有历史数据时产品无价值，演示时页面是空的 |
| 用户不愿写 | 记录成本 > 收益，核心流程断在第一步 |
| 垃圾进垃圾出 | 记录质量不一致、归因不可靠，垮在数据层 |
| N=1 不足以断言"无效" | 个人单次实验支持不了"证明 X 无效"这种强结论 |
| 时效性 | 技术迭代快，过去的失败结论可能已不成立 |
| 隐私与伦理 | 失败记录可能涉及导师、项目敏感信息、对他人工作的负面评价 |
| 心理负担 | 把自己的失败"资产化"对被记录者可能有压力 |
| 评价标准张力 | 赛事"技术创新性 30%"会诱导堆复杂度 |
| 规模化后退化 | 大量相似记录会让检索质量下降 |
| 协作价值难以演示 | 跨人复用的价值需要人多、时间长，10 天 Demo 难体现 |
