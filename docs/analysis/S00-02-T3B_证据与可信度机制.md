> Q22 的问题：**什么证据情况下允许生成 History-grounded Hypothesis，以及证据不足时怎么处理。**

| 维度 | **方案 Q22-A｜硬门控** | **方案 Q22-B｜分级降级 + 显著标注**（推荐） | 方案 Q22-C｜同强度输出 + 免责 | 方案 Q22-D｜模型先验补足证据 |

### 2.2 判定理由（要点）

1. **否决 Q22-A 的核心原因不是"太保守"，而是它用两种已被否定的手段达到保守**：① 固定数量阈值（修正 G 已取消）；② 把经验层的完整性要求回推到生成层（D-026 已明确禁止）。保守的正确实现方式是"**降低表述强度**"，而不是"**不输出**"。
2. **否决 Q22-C 的原因与 §7.2 方案 6-2 完全相同**：为了让输出"看起来饱满"而模糊"有依据 / 无依据"的边界，等于自毁本产品唯一的差异化根基（[D7] / R6）。"仅供参考"是通用免责，无法阻止用户把模型先验误读为自己的经验。
3. **否决 Q22-D 是底线**：它直接制造虚假依据，同时违反 [D7] 与修正 F。
4. **推荐 Q22-B** 的理由是：它与本阶段**全部已确认约束同时相容**——D-021（N=1 可有产出）、D-026（条件可缺省、不得回推）、D-025（缺什么就标什么）、D-020 / R1（不打分、不排序）、修正 G（不设阈值）。且它的"降级"是**可解释、可测试**的离散条件（N 是否为 0、有无 grounding、条件是否缺失、是否存在冲突），**不是加权分数**（见 §13）。

### 2.3 推荐方案 Q22-B 的机制骨架（候选）

```
第 ⑨ 步请求生成假设
        ↓
① 是否存在可引用的相关历史 Attempt？（Level A 命中，D-019）
   ├─ 否  → N = 0 → 不生成 History-grounded Hypothesis
   │           → 显式说明证据状态 → 可提供独立标记的 Model Suggestion
   │           → 提供"仅保存本次尝试"路径（不阻断）
   └─ 是  → ② 实际引用并作为证据的 Formal Attempt 条数 = N
              ├─ N = 1 → 允许生成，强制"当前具体条件"限定 + 显示 N = 1
              └─ N ≥ 2 → 允许跨 Attempt 对照 / 一致与冲突比较
        ↓
③ 条件完整度判定（定性，不打分）
   完整 / 部分缺失（列出缺失维度）/ 关键缺失
   → 决定表述可覆盖的范围（§7）
        ↓
④ 证据一致性判定
   一致 / 存在冲突 / 不可判定（因条件缺失）
   → 存在冲突 → 命题改写为"条件区分型"，冲突双方并置（§6）
        ↓
⑤ 组装输出（来源分列，§9）→ 用户显式接受 / 修改 / 拒绝（D-014 决策型）
```

### 2.4 与"绝不静默生成"的关系（候选 M-9）

§6.5 的硬约束是"**任何情况下都不得静默生成**——要么不生成，要么显著标注证据来源与强度"。本任务据 §8.9 补一条**降级通过规则**（候选，需人工确认）：

- **N = 0 时，第 ⑨ 步不得视为"未完成 / 阻断"**；应输出：**"当前没有可引用的历史证据"** + 可选的独立标记 Model Suggestion + "仅保存本次尝试"。
- 该"允许为空"**不违反** §8.9 的"进入下一步条件 = 至少 1 条 History-grounded Hypothesis"，因为 §8.9 自身已给出"否则明确输出'历史证据不足'"的分支。
- **但必须回归禁止**：不得把 N=0 的降级**实现为能力缺失**（第 ⑥–⑩ 步的代码路径与界面必须存在且可运行，只是在证据不足时给出明确说明而非编造）—— 见 §10。

## 3. N = 0

### 3.1 结论（候选）

**不允许生成 `History-grounded Hypothesis`。**

依据链（全部为已确认约束，非本任务新造）：

1. 修正 F：History-grounded Hypothesis **必须至少引用 1 条真实历史 Attempt**；N = 0 时该条件**逻辑上不可能满足**；
2. [D7]：不得把 AI 推断伪装成基于用户事实；
3. §7.1 明确列出 N = 0 **不能提供** History-grounded Hypothesis；
4. [D9] 第 ⑩ 步要求每条假设至少能挂到 1 条历史 Attempt，挂不上者**必须显示为 `模型先验` 或不予输出**（§8.10）。

**允许**的输出：`Model Suggestion`（独立对象、整体标识）。
**允许**的其它路径：仅保存本次尝试、引导补录（补录相关机制归 T3-C）。

### 3.2 N = 0 应区分为两种子情形（候选 M-4，需人工确认）

| 子情形 | 定义 | 系统必须说什么 | 系统**不得**说什么 |
|---|---|---|---|
| **N = 0(a)｜冷启动** | 用户**没有任何** `Formal Attempt`（历史为空） | "你现在还没有历史尝试记录。我可以先帮你把这次复盘清楚；等你积累几条之后，我再基于它们给出可验证的方向。"（文案本体属 Q26 / T3-C） | 不得暗示已有历史依据 |
| **N = 0(b)｜有历史但无相关** | 存在 ≥ 1 条 `Formal Attempt`，但按 **D-019** 无 **Level A** 命中，未进入主要比较集合 | "你已有 N_total 条记录，但**这次没有找到足够相关的记录**"，并给出**可解释的原因**（哪些 Level A 维度未命中 / 哪些维度因字段为「未知」而未比对，依 D-025） | **不得**说"你没有历史记录"（与事实不符）；**不得**把"同 Project / 时间最近 / 语义相近"的记录强行当作证据（**Level B 不得单独成立**，D-019；时间仅排序，Level C） |

> **理由**：两种情形对用户的含义完全不同 —— (a) 是"我还没积累"，(b) 是"我积累了但这次用不上"。混淆会同时损害可信度（虚假陈述）与用户动力（已有记录却被告知"没有记录"）。

### 3.3 N = 0 硬规则清单（候选，需人工确认）

| 编号 | 规则 | 推导来源 |
|---|---|---|
| **H1** | **N = 0 ⇒ 不得输出 `History-grounded Hypothesis`**（对象资格问题，不是措辞问题） | 修正 F / [D7] / §8.10 |
| **H2** | `Model Suggestion` 必须**整体**标识「模型通用建议 / 非你的历史经验依据」；**与 History-grounded 输出对象分离** | 修正 F |
| **H3** | `Model Suggestion` 中**不得**出现"依据你的过去记录 / 你此前的尝试显示 / 根据你的历史"等任何暗示历史依据的表述 | 修正 F |
| **H4** | `Model Suggestion` **不计入** [D9] 第 ⑨⑩ 步正式验收；**不得**替代 History-grounded Hypothesis 作为验收结果 | 修正 F |
| **H5** | N = 0 时**不得静默跳过** ⑥–⑩ 步；必须**显式说明**当前证据状态（属 §6.5 硬约束） | §6.5 |
| **H6** | N = 0 时**不得**因证据不足阻断用户流程；必须提供"仅保存本次尝试"的路径 | §8.9 |
| **H7** | **不得**把 N = 0 的降级表述为"产品不具备该能力 / 该功能未实现" | §10 |
| **H8** | `Model Suggestion` **不得在后续流程中被升级为** `History-grounded Hypothesis`；也不得因用户接受而改变来源性质 | §6.7 回归项 |

## 4. N = 1

### 4.1 结论（候选）

**允许生成"低证据强度"的 `History-grounded Hypothesis`**，但必须满足以下全部表述约束：

| 编号 | 约束 | 依据 |
|---|---|---|
| **O1** | 必须**显示 `N = 1`**（实际证据条数），不得用"证据较少 / 证据一般"等模糊词替代 | 修正 G（始终显示实际证据条数） |
| **O2** | 必须明确提示**证据有限**（定性表述，**不得**使用分数 / 百分比 / 等级） | [D7]、§13 |
| **O3** | 命题必须**限定在当前记录的具体条件**下（"在当前记录的条件下观察到……"） | [D7]、D-021 E4 特别确认 |
| **O4** | **禁止**"方法 X 无效""该方案普遍失败""这类做法不可行"等**一般性 / 普遍性**结论 | [D7] |
| **O5** | 必须能指出**引用的是哪一条** Attempt，并说明它被用于哪一项（目标 / 方案 / 条件 / 结果） | D-021 E4、[D9] ⑩ |
| **O6** | 若该条历史记录的结果状态为 `Success` / `Partial`，则它只能作为**对照证据**，**不得**被表述为"你曾经失败过 X" | [D10] |
| **O7** | **不得**因为"N = 1"就自动降低其它约束；也**不得**因为"条件看起来完整"就自动允许外推 | 见 §4.2 |
| **O8** | 必须在依据中**说明"本次未进行比较 / 不存在跨记录对照"**（避免用户以为 1 条证据已经完成了跨记录分析） | 与 T3-C §3.2「N = 1 必须」项同源，**建议合并为一条**（见 §12.6） |

### 4.2 关键澄清：**证据条数 ≠ 条件完整度**（候选 M-8，需人工确认）

任务要求"不要因为 N=1 就自动认为 E3 适用范围完整，仍需检查条件信息"。本任务把这条扩成一条**双向**规则：

- **证据条数（N）** 与 **条件完整度** 是**两个独立维度**，**不得相互替代**：
  - N = 1 **不自动**意味着适用范围完整 → 仍须检查条件（缺失则按 §7 收窄表述）；
  - N ≥ 2 **不自动**意味着适用范围可放宽 → 若这些记录的条件集合本身残缺，表述仍不得覆盖缺失维度；
  - 条件完整 **不自动**意味着 N = 1 的结论可以外推 → 单条证据的**样本意义**不因条件齐全而改变。
- 因此**允许生成**与**允许声称适用边界**是**两件事**：
  - **生成资格**：只要 N ≥ 1（且 grounding 成立，见 §9.4），即可生成 → 由本任务 §4.1 规定；
  - **适用范围声称资格**：需要条件信息支撑 → 由 §7 规定，并保持**与 D-021 E3 / D-026 同一口径**。

### 4.3 表述对照（候选，供 T3-A 落文案时使用）

| 允许 | 禁止 |
|---|---|
| "你在【Attempt #x】中做过相近尝试，当时【条件 / 方案 / 结果】是……" | "根据你的历史经验，X 是无效的" |
| "在【本次记录的条件下】，观察到【结果 Y】" | "X 一定不能解决问题" |
| "本次记录共引用 **1** 条历史尝试，证据有限" | "证据强度：低（2/10）" |
| "下一步可以验证：只改变【Z】是否会【改善 R】" | "建议以后不要再用 X" |

## 5. N ≥ 2

### 5.1 结论（候选）

**允许**：

- 跨 Attempt 对照（横向比较）；
- **一致证据**的集合与**冲突证据**的识别；
- 生成 `History-grounded Hypothesis`；
- 在**条件集合可界定**时，把这些记录共同的条件作为假设的适用域描述。

**仍须遵守**：

| 编号 | 规则 | 依据 |
|---|---|---|
| **P1** | 必须**显示实际证据条数 N**（不是"证据充足"） | 修正 G |
| **P2** | **N 增加不得自动升为 `Fact`**；任何情况下最高只能是 `Inference` / `Candidate Insight` | [D7] |
| **P3** | 证据是否可用，**仍取决于相关性（Level A）、条件完整度、证据一致性**，不是取决于条数 | 修正 G |
| **P4** | 若存在**反驳**该假设的历史证据，**必须列出**，不得只列支持项 | [D7]、§6.1 C2 |
| **P5** | **禁止**任何形式的"条数越多越可信"表达 | 修正 G + §13 |

### 5.2 明确回归禁止项（自修正 G 继承，写入候选机制）

- ❌ "≥ 5 条才算完整孵化" / "≥ 5 条 = 高可信" / 任何固定条数阈值；
- ❌ 按证据条数对经验 / 假设排序、评分、打星级；
- ❌ 用"证据充足 / 不足"这类**模糊词**替代**实际条数 N**；
- ❌ 因条数增加而放宽表述（例如从"在当前条件下"直接跳到"普遍适用"）。

### 5.3 N 的统计口径（候选 M-2，需人工确认）

**候选定义（两层口径，必须同时明确，不得只留一个 N）**：

| 层 | 符号（临时） | 定义 | 用途 |
|---|---|---|---|
| **检索层** | `N_检索` | 与当前 Attempt **相关（Level A 命中）且可被引用**的 `Formal Attempt` 条数 | **能力边界 / 结构档位判定**（N=0 / N=1 / N≥2）—— 即"**结构上可不可能**"产出某类输出 |
| **引用层** | `N_引用` | **该条假设实际引用**并作为证据（支持 / 反驳 / 上下文）的 `Formal Attempt` 条数 | **假设内显示的"证据条数"** 与 [D9] ⑩ 的追溯清单 |

由此派生的三条规则：

1. **`Draft` 不计入任何一层**（D-012：`Draft` 不参与正式 E4 历史孵化）；
2. **"检索命中的记录数"不得直接当作 `N_引用`**（避免把未实际引用的记录算进证据）；
3. **`Model Suggestion` 没有 N**（无历史证据）；若界面需要显示，只能显示"无历史证据"，**不得**显示任何可被理解为证据数量的数字。

> **为什么必须分两层（本任务与并行任务的接口问题）**：`N_检索` 是**能力门控**的输入（"能不能产出 History-grounded"），`N_引用` 是**该条输出内部的事实陈述**（"这条假设引用了几条"）。若合并为一个数字，会出现两种错误：
> - 用 `N_引用` 门控 → 检索到 5 条相关记录、但 AI 只引用 1 条，就会被误判为 N=1 档；
> - 用 `N_检索` 显示 → 用户看到"引用 5 条"，实际追溯清单只有 1 条，**破坏 [D9] ⑩ 的可核对性**。
>
> **注意**：本文的 `N_引用` 与 T3-A §2.3.1「证据强度标记 = N = 实际引用的 `Formal Attempt` 条数」**一致**；T3-C §3.4 / Q25-R3 的 N ≡ "相关且可引用"则对应本文的 `N_检索`。两者**不矛盾但必须显式区分**，见 §12.6 与 §15 新-13。

> **待决（见 §15 新-9）**：仅被引用来"说明已排除"或"提供条件上下文"、而**不直接支持也不反驳**命题的记录，是否计入 `N_引用`。本任务**不裁决**，只标记为需要人工确认；建议在计入时必须同时标注其角色（支持 / 反驳 / 上下文），**不得**用同一数字掩盖角色差异。

## 6. 冲突证据

> 情形：历史 Attempt 之间**互相冲突**（例如在同一类目标下，某些尝试得到 A 结果、另一些得到相反结果）。

### 6.1 硬规则（候选，需人工确认）

| 编号 | 规则 | 依据 |
|---|---|---|
| **C1** | **不得擅自择一**：不得静默选择"多数记录支持的一方"，**不得**选择"最近的那条"（Level C 仅排序，D-019），**不得**选择"条件更完整的那条"而不说明 | [D7]、D-019 |
| **C2** | 必须**并列展示**冲突双方，并**标注"存在冲突经验"** | §6.5 |
| **C3** | 必须**解释冲突发生在哪些条件上**（定位到 Level A 维度：目标 / 方案·技术对象 / 条件 / 结果·现象） | D-019 |
| **C4** | 若条件信息缺失导致**无法定位**冲突来源，必须**明说**"无法判断冲突来源（条件信息缺失）"，不得猜测并给出单一解释 | D-025、§7 |
| **C5** | 必须**把冲突本身转化为下一轮可验证方向**（这是核心价值，而不是"失败"或"证据不可用"） | D5 核心逻辑 |
| **C6** | 冲突**不得**被表述为"证据不够所以无法判断"而终止；但也**允许**在确实无法形成可验证动作时显式说明并留空（见 §15 新-8） | §8.9 允许为空 |

### 6.2 "存在冲突"如何影响 Hypothesis 的措辞（关键分析）

冲突证据对措辞的影响是**结构性的**，不是加一句"存在冲突"就够：

| | 无冲突（证据方向一致） | **存在冲突** |
|---|---|---|
| 命题形态 | 断言型：`在【条件 C】下，改变【V】可能改善【R】` | **条件区分型（discriminating / boundary）**：`在【C₁】下观察到【A】；在【C₂】下观察到【B】；尚不能确定差异来自【C₁ 与 C₂ 中的哪一项】` |
| 下一步动作 | "只改变 V，观察 R" | "**固定【C₁ / C₂ 的公共部分】，只改变【它们不同的那一项】**，观察结果偏向 A 还是 B" |
| 假设依据 | 列出支持证据 | **必须同时列出支持与反驳证据（双方并置）** |
| 禁止措辞 | —— | ❌ "X 无效 / X 有效 / X 更好 / 应改用 X" ❌ "多数记录支持 X" ❌ "个别记录例外" ❌ "以最近一次为准" |
| 允许措辞 | —— | ✅ "两条记录在【某条件】上不同，结果相反；下一轮可以只改变这一项来区分" ✅ "当前无法判断是【条件差异】还是【其它因素】导致" |
| 对"适用边界"的态度 | 可描述为"这些记录共同的条件集合" | **不得**定义统一边界；边界恰恰是**待验证的对象** |

**为什么必须这样改写**（三条理由）：

1. **冲突证据下的断言必然是一半事实**：无论选哪一方，都会把另一方的历史记录变成"用户看不见的反例"，违反 [D7] 与本产品"可追溯"的根基。
2. **冲突是最高价值的孵化输入而非障碍**：它天然给出了一个**受控对比实验**（只改一个条件）——这正是 [D5] 所说的"下一轮验证方向"。因此冲突的正确产品行为是**升格为方向**，而不是**降格为不确定性提示**。
3. **它同时保护了 E4 的可证伪性**：条件区分型命题**可被证伪**（"改了这一项后结果不变"即证伪），而"X 无效"式结论在单项目场景中实际上**不可验证**。

### 6.3 与"数量 / 结构"的边界（不越界声明）

- 本文**只规定冲突时命题的形态与措辞**，**不规定**冲突时生成几条假设（**Q18 → T3-A**）。
- 本文**不规定**冲突在界面上的呈现结构 / 组件形态（**Q17 / Q26 → T3-A / T3-C**）。
- 本文**建议**（`PROPOSED`）冲突用例应成为验收场景之一，因它同时检验 D-019 / D-025 / D7 三条约束（见 §13 回归项建议）。

## 7. 条件缺失

> 情形：**存在历史证据**，但条件字段不完整或为「未知 / 未提供」。

### 7.1 结论（候选）：**允许生成，但强制降级表述**

| 问题 | 候选答案 |
|---|---|
| 允许还是禁止生成？ | **允许生成** |
| 允许宣称适用边界吗？ | **不允许**（除非支撑边界所需的条件确实存在） |
| 必须做什么？ | ① 显式标注**缺失了哪些维度**；② 表述**不得覆盖**缺失维度；③ 若命题本身依赖某个未知条件值，则**不得生成该条件断定** |

### 7.2 决定性论证：为什么"禁止生成"是错的

若采用"条件缺失则禁止生成"，将产生**三处直接违反已确认约束**的后果：

1. **违反 D-026**：D-026 明确"**经验层的完整性要求不得回推为记录层的必填要求**"。禁止生成 = 把条件变成"生成假设的必填项"，等于把经验层的完整性要求**回推到生成层**（比回推到记录层更早一步）。
2. **违反 D-021**：E3 是 `Insight → Experience Asset` 的**晋升门槛**。把它用作**生成门槛**属于门槛层级混用；同时 E3 的"关键条件完全缺失"对应的处理是"**保持 candidate**"（即**保留但不晋升**），不是"**丢弃 / 不生成**"。
3. **违反 D-025 的设计意图**：D-025 要求把「未知 / 未提供」**显式排除并标注**（"该维度未比对"）。这套机制的设计前提就是"未知字段是**常态且被允许**的"；若未知导致禁止生成，则 D-025 的标注机制失去使用场景。

### 7.3 三种条件完整度与对应表述（候选，定性，不打分）

| 完整度 | 判定（定性） | 允许的表述 | 必须做 | 禁止 |
|---|---|---|---|---|
| **关键条件已知** | 支撑命题所需的条件在记录中有值 | "在【本次记录的条件 C】下观察到……" | 列出条件 | 不得外推到 C 之外 |
| **部分条件缺失** | 有部分条件，但存在「未知 / 未提供」的维度 | 表述**只覆盖已知维度**；对缺失维度**不作任何判断** | 标注"**缺失【X / Y】；该维度未比对**"（对齐 D-025） | 不得把"未知"当"相同 / 不同 / 无关" |
| **关键条件全部缺失** | 无法说明"在什么条件下" | 收窄为"**仅描述已观察到的表现**："本次记录了【结果 Y】"" | 明确注明"**无法判断适用边界**" | **不得**输出任何"在……条件下"的断定 |

### 7.4 反向硬规则（候选，关键）：不得编造条件

- 若命题要成立**必须依赖**某个条件值，而该值在记录中为「未知 / 未提供」，则：
  - **不得**由 AI 填入一个合理值（对标 §6.4"绝不编造指标"的同源原则：**编造条件 = 把 `Inference` 冒充 `Fact`**）；
  - 正确做法：**改造命题使其不依赖该条件**，或**退回提示补录 / 确认**（补录引导流程归 T3-C）。
- 该规则与 §6.4"无明确指标时退回让用户定义"（Q21）**同源同理**，本任务不裁决 Q21 本身。

### 7.5 与 `E2 / E3` 呈现的边界声明（避免与 新-3 重叠）

- 本文 §7 讨论的是**第 ⑨ 步假设生成**的表述约束；
- **新-3** 讨论的是**第 ⑧ 步 `Insight` 在 E2 / E3 不满足时**的呈现方式（"输出 candidate + 说明缺失项"还是"明确输出当前不足以提炼经验"）；
- 二者**层级不同**（假设生成层 vs 经验晋升层），**本文不处理新-3**，仅要求二者的**口径一致**：都**不得静默丢弃**，都必须**显式说明缺什么**（§6.5 硬约束）。

## 8. Q23 方案比较

> Q23 的问题：**历史证据与模型通用知识如何共存而不混淆。**

### 8.1 四个候选方案

| 维度 | **方案 A｜只用历史证据** | **方案 B｜历史 + 模型先验，严格分块**（推荐，需重新定义） | 方案 C｜混成一段解释 | 方案 D｜用了模型知识就改名 Model Suggestion |
|---|---|---|---|---|
| 机制 | History-grounded Hypothesis 仅允许使用历史证据，完全不允许模型知识 | History-grounded Hypothesis **允许**同时使用历史证据与模型先验，但**必须严格分块、来源分列**；Model Suggestion 为独立输出对象 | 把历史证据与模型知识合成一段解释 | 只要使用了模型知识，输出就改名为 Model Suggestion |
| 与 [D5]（E4 要做到"下一轮建议改变什么"） | **无法满足**：从"已有历史"推到"下一步该改什么"**本身**就是模型推理 | 满足 | 满足 | 满足 |
| 与修正 F（两对象分离） | 一致（但过度保守） | **一致**（恰好是修正 F 要求的分列） | **冲突**（两对象边界不可判定） | 一致（但过度降级） |
| 与 [D7] | 一致 | **一致**（来源可分辨） | **违反** | 一致 |
| 可审计性（[D9] ⑩） | 高 | **高**（历史证据分区可逐条挂 Attempt） | **低**（无法逐句归属） | 高 |
| 可实现性 / 可验证性 | **不可实现也不可验证**（无法证明某句"没用模型知识"） | 可实现（分区块渲染 + 标注义务） | 最容易实现 | 容易实现 |
| 主要风险 | ① E4 事实上被架空；② 结论因"有真实历史锚点却被标为无依据"而**反向不诚实** | 用户可能误读为"结论完全来自我的历史" → **用措辞规则消除**（见 §9.5） | 用户把自己的经验与模型幻觉混为一体；一旦模型编造内容，会被读作"我的历史" | 绝大多数假设被降级为 Model Suggestion → E4 输出名存实亡 |
| 判定（本任务候选） | **否决** | **推荐（重新严谨定义后）** | **REJECTED（重点审查对象，见 §8.3）** | **否决** |

### 8.2 对方案 A 与方案 D 的审查（两个"过度保守"的方案）

**方案 A 的合理内核必须保留，但其绝对形式不成立**：

- 合理内核 = **"grounding requirement"**：正式结论**必须**真实挂到用户历史。这条**必须保留为硬条件**（见 §9.4）。
- 不成立之处：把"不允许模型先验参与"当作 grounding 的实现手段。三个理由：
  1. **[D5] 被架空**：E4 要求输出"下一轮建议改变什么 / 应观察什么指标 / 什么结果支持或反驳"。这些内容**不可能**仅由"汇总 N 条历史"得出，必然包含模型的因果解释与实验设计能力。
  2. **不可验证**：无法在实现与测试上证明"某句结论未使用模型知识"——解析（A1）、相似判断（A3）本身就在使用模型。规则不可验证 = 规则最终会被忽略。
  3. **反向不诚实**：一条**确实有历史锚点**的假设，若因为"推理过程中用到了模型知识"而被标为"非历史依据"，用户会失去本可使用的真实经验依据。

**方案 D 的错误定位**：

- 合理内核 = **修正 F 的对象分离**（正确，必须保留）。
- 错误判据：D 用"**是否使用了模型先验**"作为分类标准。正确的分类标准是"**是否存在真实的历史锚定**"（§9.4）。二者的差别是决定性的：
  - 按 D，History-grounded Hypothesis 几乎不可能存在 → E4 名存实亡；
  - 按正确判据，**有锚定就是 History-grounded，没有锚定就是 Model Suggestion**，与"推理时用没用模型"无关。

### 8.3 对方案 C 的可信度审查（**必须重点否决**）

方案 C（混成一段解释）会造成**六类不可修复的问题**：

| 编号 | 问题 | 后果 |
|---|---|---|
| **1** | **违反 [D7] 的来源分层** | 界面与存储都无法判定该结论是"用户的经验"还是"模型的通用知识"，产品可信度的根基失效 |
| **2** | **使第 ⑩ 步无法验收** | [D9] ⑩ 要求"证据可点开核对"。混写段落**无法逐句归属**到具体 Attempt，追溯链条在最关键处断裂 |
| **3** | **剥夺用户的反馈能力** | 用户看到一段话，无法判断"哪一句是我的记录""哪一句是 AI 编的"，因此**无法提出有意义的"不同意 / 不相关"反馈**（D-014 展示型反馈机制失效） |
| **4** | **使"显式接受"失去语义** | `History-grounded Hypothesis` 属**决策型 `Inference`**，必须显式接受（D-014）。若来源不可分辨，用户的"接受"变成对一段来源不明文本的接受——**确认行为被形式化** |
| **5** | **滑坡到经验资产污染** | 第 ⑧ 步的 `Insight` 可经 `accepted` 成为 Experience Asset，并被**后续复用**。混写使模型幻觉有机会以"用户已有经验"的身份进入资产层，且此后**不可分离** |
| **6** | **使修正 F 无法执行** | 修正 F 的全部意义是"两个输出对象在**对象层面**分离"。C 让"这是哪一个对象"变成不可判定问题 → 修正 F 退化为一句口号 |

> **结论**：方案 C **不是"表达能力更弱的可接受选项"，而是对本产品可信度根基的直接破坏**，应作为**回归检查项**（§13）列入禁止清单。

### 8.4 对关键问题的回答：**"History-grounded" 是否意味着模型先验不能参与最终假设？**

**候选答案（需人工确认）：不意味着。名称约束的是 `grounding`（锚定），不是 `reasoning`（推理）。**

本任务按任务要求，把问题拆成两个**必须分开**的概念：

| 概念 | 含义 | 性质 | 违反后果 |
|---|---|---|---|
| **Grounding requirement｜历史锚定要求** | 正式结论**必须**至少存在 1 条**真实的、可追溯的**历史锚点（见 §9.4 判据） | **硬条件**（不满足则**不得**称为 History-grounded） | 违反修正 F / [D7] / [D9] ⑩ |
| **Reasoning input｜推理输入** | 在**已满足** grounding 的前提下，模型通用知识可以参与"从历史到假设"的**推理过程**（机制解释、变量候选、验证方式设计） | **允许**，但**必须分列、必须标注、不得承载命题成立的唯一依据** | 违反则回到方案 C 的六类问题 |

**判定规则（候选，一句话版本）**：

> **只要历史 grounding 真实存在，模型先验可以作为辅助 reasoning 输入参与，但来源必须分列；如果没有任何真实历史 grounding，整个输出只能是 `Model Suggestion`。**

**类比说明（用于对外解释，非产品文案）**：这类似于一篇论文声称"本研究基于实验数据"——它承诺的是**结论有数据支撑**，并不否认作者使用了学科理论知识；反过来说，如果一条结论**没有任何数据**支撑，就不能声称"基于实验数据"。**"基于"是存在性承诺，不是排他性声明。**

### 9.1 `History-grounded Hypothesis` 的来源结构（候选）

```
[假设命题]  一句话；不含"证明 / 证实 / 普遍适用"；条件受限（§4 / §6 / §7）
    │
    ├─【历史证据】（必需；N ≥ 1 才存在此分区，也是 grounding 的载体）
    │     · 引用的 Attempt 列表（可追溯 ID；[D9] ⑩ 可点开）

    │        不作为新增卡片字段（避免越界 Q17）
    │
    ├─【模型先验】（可选；存在则必须整体标注）

    │     · 内容：机制解释 / 变量候选 / 验证设计建议
    │     · 禁止：承载"命题成立"的唯一依据；禁止暗示历史依据
    │
    ├─【下一轮建议改变什么】        ┐
    ├─【哪些条件应保持不变】        │  沿用 [D5] 的 8 项要求
    ├─【应观察什么指标】            │  （无指标时的处理属 Q21，本任务不处理）
    ├─【什么结果支持假设】          │
    ├─【什么结果反驳假设】          ┘
    │
    └─【证据限制提示】  定性，不打分：N = 1 / 条件缺失（列出）/ 存在冲突（列出）
```

```
    │
    ├─【建议内容】+【理由（模型通用知识）】

    ├─【禁止】
```

### 9.4 **Grounding 判据（候选 M-3，需人工确认）** —— 本任务的核心产出

> **关键区分**：**"有历史记录" ≠ "有历史 grounding"。**

**构成 grounding（至少满足 1 条，且必须有可追溯引用）**：

| 编号 | 判据 | 例子 |
|---|---|---|
| **G1** | 假设的**问题对象 / 变量**来自历史 | "你上次改的是 **学习率**，这次可以继续只改它" |
| **G2** | 假设的**条件**来自历史 | "上次是在 **batch=32** 下做的，这次条件相同" |
| **G3** | 假设的**目标指标**来自历史 | "上次的判定依据是 **验证集准确率**，本次沿用同一指标" |
| **G4** | 假设的**排除项**来自历史 | "历史中 **数据增强** 已试过且未达预期，故本轮不再重复" |

**不构成 grounding（出现任一条即不得称为 History-grounded）**：

| 编号 | 反例 |
|---|---|
| **N1** | 只在文案里写"参考了你的历史"，但**没有任何对应字段**可指 |
| **N2** | 只引用了与该目标**无关**的记录（例如同 Project 但 Level A 无命中 → 违反 D-019） |
| **N3** | 仅在**措辞**上相似（都提到某个通用词），没有字段级对应 |
| **N4** | 命题的**关键变量完全来自模型先验**，历史仅提供一个"类似场景" |
| **N5** | 引用的是 `Attempt Draft`（D-012：不参与正式 E4 孵化） |
| **N6** | 引用记录的全部相关字段均为「未知 / 未提供」，实际未提供任何可用的锚点信息 |

> **N4 / N6 是本任务最需要的两条判据**：它们把"看起来有历史"与"真的锚在历史上"分开。若命题不满足 G1–G4 中任一条 → **整体输出应为 `Model Suggestion`**，**即使历史记录存在**。

### 9.5 措辞规则（候选，防止模型先验被误读为历史）

| 允许（**存在性**表述） | 禁止（**排他性 / 全称**表述） |
|---|---|
| "**有你的历史记录作为依据**" | "**完全基于你的历史记录**" |
| "本假设引用了 **2** 条你的历史尝试" | "这条结论**全部来自**你的历史" |
| "以下部分为**通用知识推导，不是你的历史依据**" | 把模型先验与历史证据写在同一个段落 / 同一句话里 |
| 命题句不附加来源含义（来源由分区承担） | 在命题句里混入模型先验的判断并使其读起来像历史事实 |

> **理由**：[D7] 与修正 F 只要求"来源可分辨"。但**存在性表述与排他性表述的用户理解差异极大** —— 排他性表述会让用户以为"我的全部历史都被用来支持这条结论"，从而高估证据覆盖面。用存在性表述既不夸大也不贬低。

### 9.6 属性归属回归项（沿用 §6.7，不得违反）

- 两种输出**均属 `Inference` / `Candidate Insight`**，**不得转 `Fact`**（[D7]）；
- **即使用户接受（`accepted`），来源类型仍为 `Inference`**，不得升级为 `Fact`（修正 C / D-014）；
- 输出的"引用的历史 Attempt"部分属**事实引用**，可标为事实；
- `Model Suggestion` **必须始终保留「非历史经验依据」标记**，**不得在后续流程中被升级为** `History-grounded Hypothesis`。

## 13. 新增原则：证据强度不是分数

> 本节按任务要求，把"证据强度不是分数"作为**横向约束**写入候选机制，适用于本文 §3–§12 全部输出。

### 13.1 明确禁止（候选 M-1）

| 禁止项 | 说明 | 违反的既有约束 |
|---|---|---|
| 百分比可信度（"82% 可信"） | 伪精确：模型无法给出有意义的概率，用户会误读为统计事实 | [D7]；D-020（数字 ≠ 用户界面事实） |
| 分数（"7/10 证据质量"） | 同上，且隐含"权重体系" | [D7]、R1 |
| 高中低积分榜 / 经验等级 | 价值量化 | R1、D-021（C4′ / C5′ 不打分、不设等级） |
| "5 条以上 = 高可信" | 未经证据支持的魔法阈值 | **修正 G**（该阈值已被明确取消） |
| 星级 / 综合分 / 雷达图分数 | 同上 | D-020、R1 |
| **内部打分但用户不可见** 的门槛 | **隐性回归**：只要门槛基于加权分数，即使不显示，仍然违反"不设固定阈值" | 修正 G、[R1] |

### 13.2 允许使用（候选）

证据强度**只能由可解释的离散事实表达**：

| 允许的信息 | 形态 | 作用 |
|---|---|---|
| **实际证据条数 N** | 整数（0 / 1 / 2 …） | 事实陈述，用户可自行判断 |
| **条件是否完整** | 定性 + **缺失维度清单**（"条件 / 判定依据 为未知，该维度未比对"） | 对齐 D-025 |
| **是否存在冲突** | 有 / 无；**存在时列出冲突发生在哪些条件上** | 对齐 §6 |
| **哪些证据支持** | Attempt 引用列表 | 对齐 D-021 E4 / [D9] ⑩ |
| **哪些证据反驳** | Attempt 引用列表 | 对齐 [D7]（不得只列支持项） |

### 13.3 表述规则（候选）

- **用事实陈述，不用评价性语言**：
  - ✅ "引用 2 条记录，**均缺少条件信息**"
  - ❌ "证据强度：中"
- **不得用模糊词替代数字**：不得写"证据充足 / 一般 / 不足"而不给出 N（修正 G：始终显示实际证据条数）。
- **不得把 N 当作排序键或放行键**：N 只用于**如实呈现**与**选择输出对象**（0 / 1 / ≥2），不得用于给经验排序、给用户展示"等级"、或与任何权重相乘。

### 13.4 与 D-020 的同源性说明

D-020 已确认"**内部检索值 ≠ 用户界面事实**"，并禁止显示数字相似度。本原则是**同一逻辑在证据维度的延伸**：**内部可以有数值（如相似度、token 数），但不得呈现为"证据的可信度"**。二者共同构成"**不向用户输出伪精确量化**"的产品立场。
