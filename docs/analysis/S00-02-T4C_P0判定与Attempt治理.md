## 2. Q27｜P0 step-gate 统一判定表（候选）

### 2.1 判定术语（本会话提议，全部 `需人工确认`）

> **核心区分：门槛 ≠ 阻断。** "门槛"回答"**对象能否进入下一层级 / 能否产出某类输出**"；"阻断"回答"**流程能否继续**"。二者混用是本批审计最主要的语义缺陷。

| 判定 | 定义 | 判定后的强制动作 |
|---|---|---|
| **通过** | 该步产出其正常产物 | 正常进入下一步 |
| **合法降级** | 技术性失败或输入受限，产物**以降低完整度的形式**保留，流程继续 | **必须显式说明**（不得静默）；**必须提供重试或替代路径** |
| **合法为空** | 该步的正常产物**允许为 0 条 / 空**，且属**合法业务结果** | **必须显式说明原因**；**不得呈现为错误 / 功能缺失**；**不得阻断** |
| **门槛未满足（非阻断）** | ① 对象**不能升级**（如 `Draft` 不升级为 `Formal Attempt`）；或 ② **不能产出某类输出**（如 `N_检索 = 0` 不产出 `History-grounded Hypothesis`） | **保留既有产物**（Draft / 当前 Attempt / 已生成内容**均不得丢失**）；**必须说明缺什么**；**不得静默** |
| **阻断** | **必须停止流程且无任何降级路径可继续** | 属**最严格**等级，须逐条列举并证明无降级路径 |
| **重试** | 技术性失败后的恢复路径 | **不设次数门槛**；**不得因重试改变已保存的数据** |

### 2.2 关于第 ① 步的三种方案比较（任务指定重点）

用户可能输入「失败了」「还是不行」「温度太高」这类**字符很短但属于有效上下文**的内容。

| 方案 | 机制 | 主要优点 | 主要风险 / 否决理由 |
|---|---|---|---|
| **A｜固定最小字符数** | 例如"≥ 8 字符"或"≥ N 字符" | 实现最简单，可挡掉明显误触 | ① **属未经依据支持的魔法数字**（与修正 G 已否决的 `N = 5` / `补录 3 次` 属同一错误类型：用数量代替语义）；② **会错误阻止 ①**：`"失败了"`（3 字）、`"还是不行"`（4 字）、`"温度太高"`（4 字）**全部是有效上下文**，且正是 [D4] 入口心智「刚刚哪里没有达到你的预期？」所期待的自然表达；③ 与 D-012「**只要用户产生了原始输入即可暂存**」**直接冲突**（该条**不含**长度条件）；④ 阈值一经写入，将被实现为硬校验，**违反 [D4] 的低记录成本底线**（用户在第一步就被拦下） |
| **B｜只要求非空** | 存在**非空且非纯空白**的用户输入 → 即可创建 `Draft` | ① 与 D-012 字面与精神**完全一致**；② 不引入任何数字；③ 把"足够不足够"的判断**交给真正有判断依据的后续环节**（② 解析 / ③ 追问 / ④ 原因 / Formal 四项门槛） | 用户可能提交无意义输入 → **但代价可接受**：它只是一条 `Draft`，**不参与检索、不参与晋升、不参与 E4 孵化**（D-012）；且 ② 的解析与 ③ 的追问会自然引导补全 |
| **C｜按"是否具有可解析语义"判断** | 由 AI 判定输入是否具有可解析语义，无则要求重写 | 意图上最"智能" | ① **不构成"能否创建 Draft"的判据** —— 若以它作门，就会出现"**系统判定你的话没有语义，因此不能记录**"，**违反 [D4] 与 D-012**，且用户无法申诉；② "可解析语义"**不可先验判定**：`"温度太高"` 单独看语义稀薄，但结合上下文完全可解析；③ **AI 判定本身属 `Inference`**，用它阻止用户创建记录，等于让 AI 推断**改变用户能否记录事实**——**违反 [D7]**；④ 真正需要它的是 **② / ③**（决定解析结果质量与是否追问），**不是 ①** |

### 2.3 Q27 单一候选

> **采用 B 为第 ① 步的唯一门槛，并把 C 的合理内核下沉到第 ②③ 步。**
>
> 1. **第 ① 步（Draft 创建门槛）= 存在非空、非纯空白的用户输入**。满足即创建 `Attempt Draft`，**不设任何字符数阈值、不设语义判定、不设 AI 前置判断**。
> 2. **`"是否足够进入 Formal"` 不由第 ① 步决定**，而由**第 ② 步解析 + 第 ③ 步追问 + D-012 的四项门槛**决定。
> 3. **正式废止 §8.1 的"原文长度 ≥ 8 字符"**；**并在全库扫描中确认无其他字符数阈值残留**。
> 4. **"语义是否可解析"降级为第 ② 步的解析质量判断输入**（影响"是否追问 / 追问哪个缺口"），**不得作为 ① 的阻断条件**。
> 5. **同时正式建立"P0 step-gate 表"**（§2.5），以统一四类判定替换现有的单栏"进入下一步条件"。

**放弃的方案**：A（魔法数字 + 会错误阻止有效短输入 + 与 D-012 冲突）；C 作为 ① 的门（让 AI 推断决定用户能否记录事实，违反 [D4] / [D7]）。

**采纳 C 的部分**：其"语义可解析性"作为 **② 的解析质量维度**保留，但**必须非等级化表达**（见 R6）。

## 3. Q28｜第 ④ 步候选失败原因是否允许为空

### 3.1 与 D6 / D9 / AC-10 / D-014 / D-018 / D-021 / D-022 / D-026 的一致性检查

| 依据 | 内容 | 对 Q28 的约束 |
|---|---|---|
| **[D6]** | 核心 Attempt 判定要素 = 明确目标、实际尝试、可观察结果、结果与预期的可描述差异 —— **不包含"失败原因"**；"[D6] 不要求原因"（主文档 §8.4 已写明） | **原因不是保存的必要条件** |

### 3.2 第一问：候选失败原因是否允许为空 —— 三方案比较

| 方案 | 机制 | 优点 | 风险 / 否决理由 |
|---|---|---|---|
| **A｜必须至少 1 条** | 无候选原因则不能继续 / 不能保存 | "看起来更完整"，保证第 ⑧ 步输入不为空 | ① **与 [D6] 冲突**：D6 定义的核心 Attempt 要素**不含原因**；② **与 D-026 同构错误**：把**经验层**的完整性要求回推到**记录层**；③ **会制造编造压力** —— 当 AI 确实无法归因时，用户只有两个选择：写一个自己也不同意的原因，或放弃保存（**违反 [D4]**）；④ 与 §8.4 既有"**允许跳过、不阻断保存**"**直接冲突** |
| **B｜允许 0 条 + 显式说明** | 允许 0 条；若证据不足则显式输出「**当前依据不足，暂不推断原因**」，然后正常进入第 ⑤ 步 | ① 与 [D6] / §8.4 / D-018 / D-026 **完全一致**；② **诚实**：不把"无法归因"伪装成"已归因"（[D7]）；③ 不影响保存，**不阻断主链**；④ 与第 ⑧ 步的"证据不足"形成同一套诚实降级语义 | 用户可能得不到原因 → **但这是真实状态**，且系统必须**显式说明 + 提供可选的后续路径**（如"稍后可再生成""可在补充条件后重试"），**不得静默** |
| **C｜允许模型生成低置信原因凑 1 条** | 无论如何都产出至少 1 条原因，标注为低置信 | "视图看起来完整" | **应重点审查其幻觉风险（见 §3.3）** |

### 3.3 方案 C 的幻觉风险专项审查（**建议在候选层面否决**）

| 风险 | 说明 | 违反的已确认约束 |
|---|---|---|
| **R-1｜把推断包装成"已有解释"** | 用户看到 1 条原因即会认为"系统已经分析出了原因"，而它可能纯属模型先验 | **D7**（`Inference` 不得伪装成事实）、**D-030**（无真实 grounding 时整体只能为 `Model Suggestion`） |
| **R-2｜制造"低置信"这一未定义等级** | 候选本身要求"低置信原因"，即引入**置信分级** | **D-036 / AC-53**（禁止"低 / 中 / 高"等级化表述）；**D-037**（禁止把等级当依据） |
| **R-3｜污染后续链路** | 该原因会进入保存内容，并在第 ⑧ 步被当作"已有归因"参与经验提炼 | **D-030**（AI 建议不得承载 grounding）、**D-022**（跨记录判断只能以 `Candidate Insight` 出现） |
| **R-4｜与"空态三类出口"精神冲突** | 已确认机制明确允许"证据不足"时诚实输出空态；在此处凑 1 条属**同一类问题的双重标准** | **D-028 / D-029 / D-038**（不得静默、不得编造、允许为空） |
| **R-5｜"凑数"属已被否决的模式** | D-028 已明确禁止"**凑数 / 近义改写 / 固定条数**" | **D-028** |

> **判定（候选层面）**：**C `REJECTED`**。理由不是"低置信原因无价值"，而是：**当无法归因时，正确做法是诚实说明（B），而不是降低标准硬凑一条**。

### 3.4 第二问：候选原因是否必须逐条处理才能保存

> 这一问在此前**未被确认**（任务说明：项目明确没有确认"每个原因都必须操作后才能保存"）。本会话必须收口。

| 方案 | 机制 | 优点 | 风险 |
|---|---|---|---|
| **P-1｜保存 `Formal Attempt` 前必须逐条处理** | 每条候选原因都必须 accept / reject 后才能保存 | 每条原因都有明确状态，"不留悬空内容"；与 AC-10 字面最接近 | ① **把第 ④ 步变成保存的强制环节**，与 §8.4「**不阻断保存**」不一致；② **加重使用成本**：用户在"只是想先把这次尝试记下来"时被迫逐条点选，**违反 [D4]**；③ 与 §8.5「未被接受 / 拒绝的内容以 `candidate` 保存」**直接矛盾**（若必须逐条处理，就不该存在"未被接受 / 拒绝的 Inference 内容"）；④ 与 D-026 精神不一致（用经验层的处理完备性约束记录层动作） |
| **P-2｜可保持 `candidate` 保存，但不得作为后续已接受判断使用** | 允许 0 条 / 部分处理 / 全部未处理即保存；未处理项**以 `candidate` 保存并持续显式标注**；**不得**被当作"已确认原因"复用 | ① 与 §8.4 / §8.5 **一致**；② 与 [D4] 一致（记录成本低）；③ 与 D-014 的**核心判断原则**一致（该原则约束的是"**改变持久化业务状态 / 被后续复用**"，而"保存为 `candidate`"**不构成** 状态升级）；④ 与 D-030 一致（未处理的 `Inference` **只能作推理输入、不承担 grounding**） | 用户可能"一直不处理"，导致原因长期悬空 → **用可见性要求化解**：系统必须**持续显示"有 N 条候选原因尚未处理"**，且**该状态不得被隐藏、不得随保存自动消失** |

**此外必须明确的配套规则（无论选 P-1 还是 P-2）**

| 编号 | 规则 |
|---|---|
| **C-1** | **禁止"默认已接受"**：任何未被用户显式操作的原因**永远处于 `candidate`**，**不得**因为"保存了""离开了页面""超过了某时间"而变成 `accepted`（AC-10 的要求在此**完全保留**） |
| **C-2** | **未处理的候选原因不得作为已确认依据复用**：不得进入第 ⑧ 步的"已确认经验"、不得作为 grounding、**不计入 `N_引用`**（与 D-030 / D-035 一致） |
| **C-3** | **未处理状态必须可见且持久**：保存后仍须可识别"哪些原因尚未处理"；**不得**因为保存动作而把"未处理"渲染成"已记录 = 已确认" |
| **C-4** | **0 条与"全部未处理"必须区分**：前者是"**没有候选**（依据不足）"，后者是"**有候选但尚未处理**" —— **不得共用同一文案**（与 D-036 的两空态区分同源） |

### 3.5 Q28 单一候选（含 `AC-10` 精度修正提案）

> **第一问采用 B；第二问采用 P-2。**
>
> 1. **候选失败原因允许为 0 条**。若依据不足，系统**必须显式输出**「**当前依据不足，暂不推断原因**」，随后**正常进入第 ⑤ 步**（保存），**不阻断**。
> 2. **禁止为凑满 1 条而生成低置信原因**（方案 C → `REJECTED`）。
> 3. **保存 `Formal Attempt` 不要求逐条处理候选原因**：允许 0 条 / 部分处理 / 全部未处理即保存。
> 4. **未处理的原因以 `candidate` 状态保存**，且**不得**被后续当作已确认依据复用（C-1 – C-4）。
> 5. **`AC-10` 的精度修正提案（需人工裁决）**：
>    - 将 AC-10 中的"**未显式接受或拒绝不得进入下一步**"，精确化为 **"未经显式接受或拒绝的决策型 `Inference`，不得被作为**已确认依据**进入后续复用链路（依据 / 门槛 / 版本来源 / 比较输入）"**；
>    - 对**结果状态**这一项，**"显式确认"仍是 `Formal Attempt` 成立的必要条件**（D-012 已确认，**不变**）；
>    - 对**候选失败原因**，**"逐条处理"不是保存的前置条件**，但**"被复用前必须已处理"是硬要求**。
>    - 说明：**本项不改变 D-014 的任何规则**（D-014 的核心判断原则本就是"是否改变持久化业务状态 / 是否会被后续复用"）；它只**校准 AC-10 的一句话适用范围**，属 `09` 的**精度修正**，**必须由人工确认后方可执行**。

**放弃的方案**：A（与 [D6] / §8.4 / D-026 冲突，会制造编造压力）；C（§3.3 五项幻觉风险）；P-1（与 §8.4 / §8.5 矛盾，把 ④ 步变成保存强制环节，违反 [D4]）。

## 4. Q04｜L4 系统自动记录范围（产品层元数据）

### 4.1 边界原则（本会话提议）

> **产品层需要的元数据 ≠ 技术观测 / debugging 日志。** S00-02 只决定**前者**。

| 原则 | 内容 |
|---|---|
| **E-1｜最小化** | 只记录**产品行为必需**的元数据。凡"记录了但产品任何地方都不用"的字段，**不得进入产品层** |
| **E-2｜不锁技术参数** | 模型名称 / model version / prompt version / token 数 / temperature / trace id **一律不在 S00-02 决定范围**，归 `07_TECH_ARCHITECTURE` 或 observability 文档 |
| **E-3｜技术日志不得成为产品事实** | 即使实现层存在技术日志，它**不得进入用户可见界面、不得作为任何判定依据、不得让人误以为系统记录了它**（与 D-020「内部检索值 ≠ 用户界面事实」同源） |
| **E-4｜不引入第二套来源字段** | 第三批 Q24 已复用于区分现场 / 补录的「**数据来源**」字段（Q03 已有），**不得新增重复字段** |
| **E-5｜用户提供的时间 ≠ 系统事实** | "发生时间"若由用户提供，**保持用户输入性质**（用户 `Fact`），**不得**因系统记录了它而改写为系统元数据 |
| **E-6｜不得因元数据产生门槛** | 元数据**不得**参与相关性判断、不得参与晋升、不得作为门槛、不得用于"按数量自动提升" |

### 4.2 三方案比较

| 方案 | 机制 | 优点 | 风险 / 否决理由 |
|---|---|---|---|
| **A｜只记录产品必需的系统元数据** | 创建时间 / 最近修改时间（若产品需要）/ 数据来源性质 / AI 内容来源标记 | ① 与 D-013「系统自动」组的现有 3 项**对齐**；② 不引入技术字段；③ 满足 D9 ⑩ 与 D-035 追溯所需（追溯对象是**历史 Attempt 证据**，**不是 AI 生成过程**） | **无明显风险**；需人工裁决的只有"最近修改时间是否产品必需"与"AI 标记粒度"两处 |
| **B｜大量记录模型 / Prompt / 版本 / 运行参数** | 记录 model name、model version、prompt version、token、temperature、trace id 等 | 便于排障、复现、审计 | ① **越出 S00-02 边界**（属技术观测）；② **引入未经确认的技术字段**（正是本任务第 ⑧ 问要防的）；③ **时间与范围成本**（10 天 V1）；④ **误导风险**：字段一存在，就会被期待"用户可见 / 可审计"，从而**变成事实性承诺**；⑤ 与 **[R6]**"不得以技术堆叠替代产品价值"精神相悖 |
| **C｜完全不记录 AI 来源** | 不区分用户提供 / AI 生成 / AI 推断 | 实现最省事 | ① **直接违反 [D7]**（三层内容必须严格分离）；② 违反 D-013（"AI 内容来源标记"是**已确认**的系统自动字段）；③ 使 D-014（两类 `Inference` 的确认边界）**无法执行**；④ 使 D9 ⑩ 与 D-035 的 `N_引用` 追溯**失去依据** |

### 4.3 Q04 单一候选：产品层 L4 最小集

## 5. Q31｜Attempt 删除 / 归档

### 5.1 [D6] 边界复核（**必须先厘清，不得越权**）

| 已确认内容 | 未确认内容 |
|---|---|
| 系统**不得**因为"低价值 / 普通错误"**自动删除** Attempt；普通错误记录**不得被自动删除或排除出比较集合** | **用户本人**能否删除 / 归档自己的 Attempt；若能，是**物理删除**还是**归档保留** |

> **本会话严格遵守**：**不得**把 D6 解释为"用户不得删除"（修正 D 已明确否定该越权推导）；也**不得**把 D6 解释为"用户可任意删除"。**这是一个真正开放的议题**。

**本会话新增的补充约束（候选）**：

| 编号 | 规则 |
|---|---|
| **A-1** | **归档也不得由系统自动触发**：不得出现"系统判定为低价值 / 长期未使用 → 自动归档"的机制（D6 精神延伸到归档动作） |
| **A-2** | **归档不得作为价值判断**：不得出现"低价值归档 / 清理旧记录"类表述或排序依据（[R1]） |
| **A-3** | **归档不得作为"完成度 / 质量"信号**：归档记录**不因此被降级**、**不因此从经验层被撤销** |

### 5.2 四方案比较

| 方案 | 机制 | 优点 | 风险 / 成本 |
|---|---|---|---|
| **A｜用户可物理删除** | 直接删除 Attempt 记录 | 实现最简单；符合"我的数据我做主"的直觉 | ① **直接冲击 [D9] ⑩**：`History-grounded Hypothesis` 引用的 `Formal Attempt` 消失后，**证据链断裂、⑩ 无法追溯**；② 已 `accepted` 的 `Insight` / 已验证过的假设**来源消失**，但**它们不会被自动撤销** → 出现"**结论仍在、依据已不存在**"的状态；③ 误删不可逆；④ **V1 需要额外设计引用处理（tombstone / 阻止删除 / 失效提示）**，属**新增复杂度** |
| **B｜V1 只允许归档，不做物理删除** | 用户可归档（移出默认检索集合），记录本身保留 | ① **证据链不破**：⑩ 仍可展示来源并要求标注状态；② 用户**仍然获得"把它移出视野"的管理权**；③ **实现成本最低**（一个状态位 + 检索过滤 + 展示标注）；④ 与 D6 完全不冲突；⑤ **不产生"引用失效"这类需要额外设计的状况** | ① **不满足"彻底删除"的诉求**（如误录入的敏感内容）→ 用"归档 + 不可编辑 + 可取消归档"缓解；② 长期数据量增长（**V1 无影响**） |
| **C｜允许删除，但被引用时阻止** | 未被引用可删；被 `Insight` / `Hypothesis` / 证据链引用则阻止 | 兼顾可删与证据完整 | ① **需要计算引用关系**（实现复杂度中等）；② 用户会遇到"**为什么不能删**"的困惑，需要额外解释成本；③ **仍会产生"未被引用但后续需要"的情况**；④ 与 A 同样需要引用处理设计 |
| **D｜归档默认 + 另提供高级永久删除** | 默认归档；高级入口提供永久删除 | 功能最完整 | ① **仍必须设计引用处理**（tombstone / 失效 / 阻止三选一）；② **高级删除是"误操作高发入口"**，10 天 V1 的**风险收益比最差**；③ 增加验收面（需为删除后状态单独设计用例） |

### 5.3 Q31 单一候选

> **V1 采用方案 B：以"归档"为默认（且唯一）的生命周期操作，不提供永久删除。**
>
> 1. **用户可对 `Formal Attempt`（以及 `Draft`）执行"归档"**，作为**显式的用户动作**（A-1 / A-2 / A-3 三条补充约束同时生效）。
> 2. **V1 不提供物理删除**。理由：**证据链完整性（[D9] ⑩）+ 10 天 V1 复杂度 + 误删不可逆 + 引用处理会产生第二套状态语义**。
> 3. **归档可撤销**（可取消归档，恢复为正常参与状态）—— **需人工裁决**（见 §5.7 D-4）。理由：可撤销使归档成为**低风险动作**，避免"用户因怕做错而不敢用"（[D4] 精神）。
> 4. **归档记录不可编辑** —— **需人工裁决**（见 §5.7 D-5）。理由：被 ⑩ 引用的证据若可被事后改写，**证据链的可信度会被直接破坏**（与 [D7] 同源）。
> 5. **若人工要求 V1 提供永久删除** → **必须**先按 §5.5 三选一确定引用处理方式，**不得**在未定义引用处理的情况下提供删除。

**放弃的方案**：A（破坏 ⑩ 且需额外引用处理）；C（需引用计算 + 用户体验困惑 + 未解决"未来需要"）；D（功能最全但**风险收益比最差**，且同样需要引用处理）。

### 5.4 归档的语义规则（候选，Q31 核心）

| 编号 | 规则 | 依据 / 理由 |
|---|---|---|
| **F-1** | **不参与新的默认检索**：归档记录**不进入**第 ⑥ 步的默认检索集合，**不作为新的 grounding 来源**，**不计入 `N_检索`** | 用户归档的意图 = "不要再拿它当参考" |
| **F-2** | **旧引用不静默消失**：既有 `Insight` / `Hypothesis` 的 ⑩ 证据链**继续显示该记录**（只读可查看），并**显式标注"来源已归档"** | [D9] ⑩ 必须可追溯；"不隐藏"是 §8.10 的既有要求 |
| **F-3** | **归档不追溯撤销既有证据链**：归档**不得**导致已成立的引用被判定失效、**不得**自动撤销 `accepted Insight` / 已接受的 Hypothesis、**不得**自动改写既有结论 | 与 D6「不得自动删除 / 不得自动排除」同源；避免"归档 = 事后否认自己的经验" |
| **F-4** | **但归档记录不得作为"新"的 grounding 来源** | F-1 的另一面；保持"归档后不再影响新结论"的语义一致性 |
| **F-5** | **"已归档" ≠ "引用失效"**：二者是**两种不同状态**，必须**使用不同标注**（§5.7 修正 §8.10） | 归档记录**仍然存在且可读**，不构成"失效" |
| **F-6** | **归档状态必须用户可见且可识别**：列表中可识别归档记录（**不得混同于正常记录、不得静默隐藏**） | 防止"记录消失了但用户不知道为什么" |
| **F-7** | **归档不得作为价值判断或质量信号**（A-2 / A-3） | [R1]、D6 |
| **F-8** | **不得由系统自动归档**（A-1） | D6 精神的延伸 |
| **F-9** | **归档不得用于"凑数"之外的任何自动统计**：不得因归档数量影响任何门槛、等级、建议 | D-037 |

### 5.5 若人工要求"永久删除"：三种引用处理方案比较（**备选，不推荐作为 V1 主路径**）

| 方案 | 机制 | 优点 | 风险 | V1 评价 |
|---|---|---|---|---|
| **T-1｜tombstone（留占位）** | 删除内容，保留一个不可读占位标记，⑩ 显示"来源已被删除" | 证据链"形式上不断" | "有个占位但看不到内容"对用户价值有限；**仍是一个新对象类型** | 可接受但**不必要** |
| **T-2｜引用失效提示** | 直接删除，⑩ 显示"引用失效"，不隐藏假设 | 实现最简单 | **⑩ 的验收语义变弱**："能追溯到证据"退化为"能追溯到一个失效提示"；需要为"失效后能否继续承担 grounding"另定规则（**新增待决问题**） | **会引入新的待决问题** |
| **T-3｜被引用则阻止删除** | 有引用时禁止删除并告知原因 | 证据链天然完整 | 用户被系统拒绝管理自己的数据（**需额外说服成本**）；仍需定义"未被引用"的判定口径 | 若必须提供删除，**本项最稳** |

> **建议**：**若人工最终要求提供删除**，采用 **T-3 为主 + T-1 兜底**（未被引用时留 tombstone 而非彻底抹除）；**并且必须先确认"失效记录能否继续承担 grounding"** —— 该问题**本会话不裁决**（登记为 **新-T4C-5**）。
