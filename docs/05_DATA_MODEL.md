### 1. 产品逻辑模型总览

```
User
  └── Personal Workspace                      （D3）
        └── Project                           （D3，用于组织上下文，可缺省）
              └── Attempt                     （D2，事实层记录单元）
                    ├─ status: Draft | Formal  （D-012）
                    └─ 内容条目，每条带来源类型   （D7）
                          ├─ Fact
                          ├─ Extraction
                          └─ Inference
                                ├─ 确认类别：展示型 | 决策型   （D-014）
                                └─ status: candidate | accepted | rejected （D-015）

Insight                                       （D-015，判断承载对象）
  ├─ status: candidate | accepted | rejected
  ├─ 未来可扩展：superseded | invalidated
  └─ 来源类型恒为 Inference —— 即使 accepted，**也不升级为 Fact**

Experience Asset = accepted Insight 的产品视图 / 业务称呼
                   —— **不是独立实体，也不是第三个事实对象**
```

### 2. 实体定义（产品逻辑层）

| 实体 / 概念 | 定义 | 状态字段 | 依据 |
|---|---|---|---|
| `Attempt` | 一次围绕明确目标、在特定条件下实施某个方案、并产生可观察结果的行动单元 | `Attempt Draft` / `Formal Attempt` | D2、D-012 |
| `Insight` | AI 产生的判断的承载对象（含跨记录判断） | `candidate` / `accepted` / `rejected`（未来 `superseded` / `invalidated`） | D7、D-015 |
| `Experience Asset` | **accepted Insight 的产品视图 / 业务称呼**，**不是独立实体** | 继承 Insight 的 `accepted` | D-015 |
| `Project` | 组织上下文的容器 | — | D3 |

### 3. `Attempt` 两级状态（D-012 / Q02）

| 状态 | 进入条件 | 是否进入正式历史比较 / 经验晋升 / 正式 E4 孵化 |
|---|---|---|
| `Attempt Draft` | **只要产生原始输入即可暂存**；可字段不完整、可中断续写 | **否**（三者均不参与） |
| `Formal Attempt` | 至少具备 **目标、实际尝试、实际结果、用户确认后的结果状态** | 是 |

- 结果状态属 `Inference`，**必须由用户显式确认**后方可作为 Formal 的成立条件之一。
- 允许缺省：**条件、判定依据、版本 / 环境**；缺省时**必须显式保存为「未知 / 未提供」**。
- **不得因为缺少可选字段自动删除 Draft**。
- 「实际尝试」为 Formal 必备项；**「关键参数」为可选，不作为保存门槛**。

### 4. `Attempt` 字段框架（D-013 / Q03）

| 分组 | 字段 | 落库要求 |
|---|---|---|
| 原始信息 | 用户原始描述 | 必存（`Fact`） |
| **Formal Attempt 必备** | 目标、实际尝试、实际结果、结果状态 | 缺任一项则不能成为 `Formal Attempt` |
| 重要但允许未知 | 条件、预期结果、判断依据、关键参数 / 用户主动提及的关键变化 | 可缺省，缺省即存「未知 / 未提供」 |
| 系统自动 | 创建时间、数据来源、AI 内容来源标记 | 系统写入 |
| 可选 | Project、版本 / 环境、用户备注、成本、失败类型标签 | 用户按需补 |

**关于"失败类型"**：V1 **不建立固定"失败类型分类体系"作为 P0 必填字段**；如保留，仅作为 **optional tag**。**不得**建立失败价值排行榜；**不得**用失败类型决定是否保存 Attempt；**不得**将 S00-01 的 10 类分类自动恢复为正式产品定义。

### 5. 来源属性与确认规则（D7 + D-014 / Q08）

每个内容条目必须携带 **来源类型**，且 `Inference` 需再携带 **确认类别**：

| 来源类型 | 产生方式 | 确认要求 | 是否可升级为 Fact |
|---|---|---|---|
| `Fact` | 用户提供 | 无需 | —（本身即事实） |
| `Extraction` | AI 从原文抽取 | 用户可**一次整体校正 / 确认** | 否 |
| `Inference｜展示型` | AI 为帮助理解、比较、导航而产生 | **不要求逐条显式确认**；用户可反馈"不同意 / 不相关"；**未反馈不得视为已确认** | **否**；且**不得自动升级为 Experience Asset** |
| `Inference｜决策型` | 会改变持久化业务状态、或会被后续作为决策依据复用 | **必须由用户显式接受或拒绝** | **否**；`accepted` 后来源仍为 `Inference` |

补充约束：

- **任何 `Inference`（含已被接受者）都不得以事实形式存储或呈现**；界面不得使用"已证实"等措辞。
- 展示型 `Inference` 的示例：相关性判断、相似点、差异点、检索排序理由、对照价值判断、置信提示、比较维度判断。
- 决策型 `Inference` 的示例：结果状态、候选失败原因、`Candidate Insight` 是否被接受、Experience Asset、`History-grounded Hypothesis`、用户选择保存的模型推断。

### 6. 关系类型（沿用 S00-01，R3）

- 允许普通关系：`belongs_to`、`similar_to`、`derived_from`、`evidence_for`、`contradicts`、`generated_from`。
- **不绑定图数据库**；V1 不做图数据库、大型知识图谱、复杂图谱推理、图谱可视化系统。

### 1. 追问答案的来源属性（D-024 / 新-4）

- 追问产生的条目必须**按两层分别落库**：
  - **用户原始回答 → `Fact`**（用户明确提供，AI 不得修改其事实含义）；
  - **AI 对回答的结构化归纳 → `Extraction`**（**用户可修改**）。
- **禁止**：把用户原话标成 `Inference`；把 AI 归纳标成 `Fact`。
- 结构含义：**同一个关键追问问题**可同时产出 `Fact` 条目与 `Extraction` 条目，二者**来源类型逐条标记**（依 D-013 的"AI 内容来源标记"）。
- 🚩 **计数语义（2026-09-19 口径校正，D-017 / D-023）**：追问预算的**计数单位 = AI 实际提出的「关键追问问题数」（TOTAL，最多 3 个）**，**不是对话轮次**；**同一个关键追问问题无论跨几个对话回合呈现，都只计 1 个问题**；**不得把多个缺口打包进一个问题以规避 3 个问题的总预算**。

### 2. `Insight` 与 `Formal Attempt` 的关联（D-021 E1）

- **`Insight` 至少关联 ≥ 1 条 `Formal Attempt`** 才能进入晋升判定；
- **`Attempt Draft` 不得作为 Experience Asset 的来源**（与 D-012 一致）；
- 关联必须是**可追溯的引用**（用于 D-021 E4 的证据链），**不是**仅凭文本相似。

### 3. Experience Asset 晋升的 E1–E5 约束（D-021 / Q10）

| 条件 | 数据层含义（产品逻辑，不含字段类型设计） |
|---|---|
| **E1 有效来源** | `Insight` → `Formal Attempt` 至少 1 条可追溯关联 |
| **E2 结论明确** | 存在可表述为明确经验命题的结论内容（非模糊表述） |
| **E3 适用范围明确** | 携带可说明的观察条件集合；**关键条件完全缺失时状态不得离开 `candidate`** |
| **E4 证据可追溯** | 可指向具体 `Formal Attempt` / 事实字段；**若存在跨记录比较**，另可指向所用比较结果（**条件项，非硬门槛**） |
| **E5 用户显式接受** | `Insight.status = accepted` |

- **C4′（跨记录对照）/ C5′（后续被检索引用）**：**仅作为增强信息**，**不参与门槛判定、不产生分值 / 等级**（[R1]）。
- **C6**：单条普通操作错误**默认不自动晋升**；多条普通操作错误**可参与跨 Attempt 分析**并产生新的 `Candidate Insight`（普通错误记录**不得**被自动删除或排除出比较集合）。

### 4. 未知字段状态与相关性（D-025 / 新-5）

- 缺省字段按 D-012 **显式保存为「未知 / 未提供」**（不得留空、不得用默认值）；
- 状态为「未知 / 未提供」的字段：**不参与相关性判断**；**不得因双方都「未知」而判为相似**；比较结果须**标记"该维度未比对"**；
- 与 D-012 的关系：**正因缺省被显式保存，才能在比较时被显式排除**。

### 5. 相关性判定的三级逻辑（D-019，仅产品逻辑）

| 级别 | 维度 | 数据层含义 |
|---|---|---|
| **Level A** | 目标 / 实际尝试·方案·技术对象 / 条件 / 结果·现象 | **唯一**可据以判定"是否进入主要比较集合"的维度集合 |
| **Level B** | Project / 用户标签 / 版本·环境 / 语义相似 | 只能**增强 / 解释**相关性，**不得单独成立** |
| **Level C** | 时间 | **仅在相关性接近时**用于排序；**不得**默认"最近一次" |

> 以上为**产品逻辑层**描述，**不绑定检索技术实现**（[R3]：不做图数据库 / 大型知识图谱 / 图谱推理 / 图谱可视化）。检索技术方案仍不在本阶段。

### 6. 两个门槛的分层（D-026 / 新-6）

```
Formal Attempt 保存门槛  ── 解决"这次尝试是否已可成为正式 Attempt"
                            · 条件允许缺省（记为「未知 / 未提供」）

Experience Asset 晋升门槛 ── 解决"这条 Insight 是否已具备可复用经验的条件"
                            · 关键条件缺失导致适用范围无法明确 → 保持 candidate
```

- **二者不是同一个门槛，也不冲突**：**经验层的完整性要求不得回推为记录层的必填要求**。

### 7. `Candidate Insight` 的生成来源（D-022 / Q11）

- **V1 中 `Insight` 的产生来源唯一 = P0 主链第 ⑧ 步**（`candidate` 态）；
- **不建**后台生成 / 保存后自动生成 / 异步批量生成 / 定期挖掘 / **`candidate` 待办池**等数据通道；
- `Insight.status` 仍为 **`candidate` / `accepted` / `rejected`**（未来可扩展 `superseded` / `invalidated`，[D-015]）；
- **Experience Asset 仍为 `accepted` Insight 的产品视图，不是独立实体，也不是第三个事实对象**；**来源类型恒为 `Inference`**。

### 2. `N` 的三个量／状态（D-035 / Q25）

| 记法 / 状态 | 定义 | 用途 |

### 3. Grounding 判据与来源分区（D-030 / Q23）

### 3. `Hypothesis` 与 `Model Suggestion` 的数据性质（`D-041` / `D-042`）

```
第 ⑨ 步  →  Hypothesis 输出
             ├─ History-grounded Hypothesis   （来源 = Inference；决策型 / 持久化；须显式接受 / 拒绝）
             └─ Model Suggestion              （来源 = Inference；须显式接受 / 拒绝；可保存）
```

- **两类输出一律不得成为 `Experience Asset`**；**不得在经验区出现**；**不得被任何"经验"措辞指代**；**`candidate` / `accepted` / `rejected` 仅适用于第 ⑧ 步产物**；**不为 `Hypothesis` 建立与经验层相关的生命周期状态机**。
- **唯一转化路径**：`Hypothesis → 用户实际执行 → 新 Formal Attempt → ⑥⑦ → ⑧ → 新 Candidate Insight → E1–E5 → Experience Asset`；**`Hypothesis` 与 `Experience Asset` 之间不存在任何直接对象关系**。
- **`Model Suggestion` 的两个动作必须分开建模**：
  | 动作 | 含义 | 表示的 / 不表示的 |
  |---|---|---|
  | **A. 保存 / 持久化** | 保留该 `Model Suggestion` 供本次记录后续回看 | **内容被保留**；**≠ 接受 · ≠ 采纳 · ≠ 确认**；不改变来源性质、不获得 grounding、不成为 `Experience Asset` |
  | **B. 接受 / 拒绝** | 用户对该第 ⑨ 步决策型 `Inference` 的裁决 | 表示"认可 / 不认可这个下一步方向"；**不把内容变成 `Fact`**、**不使其成为经验**、**不获得 grounding** |
- **已保存但未完成接受 / 拒绝** → **只能表达为"内容被保留，决策状态仍未完成"**；**不得作为已接受方向复用**。
- **`Model Suggestion` 不承担 grounding、不计入 `N_检索` / `N_引用`**（**保存后亦然**）；**不得被 ⑩ 追溯为历史证据**；**不得升级为 `History-grounded Hypothesis`**。
- **已确认（`D-049` / S00-03）`Hypothesis` 的编辑边界与 ⑥⑦⑧ 的 `Fact` / `Inference` 分列**：**AI 生成核心内容 ①②③④⑤ 只读**；**⑥⑦⑧ 可由用户提供并落为用户 `Fact` 条目**；**不新增 `Hypothesis` 版本 / 回退状态机** —— 见下方《S00-03 决策同步（`D-049`）》。

### 2. `Fact` / `Inference` 分列规则（`D-049`）

- **⑥⑦⑧ 的用户内容落库为 `Fact`**；**AI 提出者仍为 `Inference`**；**二者必须分列**（沿用 `D-027` / `D-030` 的两分区结构）。

- **不得** 建立 `Fact` / `Inference` **混写**（**不得**出现"混合"来源标签）。
- **不得** 因用户编辑而改变 AI 条目的 `source_type`（**来源类型恒不变**）。
- **AI 生成核心 `Hypothesis` 后，不得自动改写 / 覆盖 / 归一化 / 删除用户 `Fact` 条目**。
- 🔴 **第 ⑤ 项「保持条件」的来源落点（`ADJ-01` 派生关闭，`CLOSED / DERIVED`）**：**历史条件值 = `Fact` / `Extraction` 引用**；**AI 建议"保持某条件" = `Inference`**；**用户本人明确指定"保持某条件" = 用户 `Fact`** —— 其中**用户 `Fact` 的唯一持久化落点 = `Formal Attempt` 层**，**`Hypothesis` 第 ⑤ 项只通过既有引用机制指向并展示该 `Fact`**，**不在 `Hypothesis` 层新建任何用户条目**（详见本节 §4）。

### 1. 必须表达的逻辑事实

- **同一 `Attempt` 允许存在不同「生成批次」的 `Insight` / `Hypothesis` 结果**（多对多结构上允许：一个 `Attempt` ↔ 多批 `Insight`；一个 `Attempt` ↔ 多批 `Hypothesis`）；

| 3 | **各 `Insight` 原状态保持** | `candidate` / `accepted` / `rejected` 不因重新生成自动迁移 |
| 4 | **各 `Hypothesis` 的 `decision_state` 保持** | `undecided` / `accepted` / `rejected` 不因新一轮生成自动改变；新 `Hypothesis` **不继承**旧 `decision_state` |
