# 00 项目规则（PROJECT RULES）

> 本文件是项目协作的根本约定，所有开发行为优先遵守。

## 1. 项目背景

- 参赛：粤港澳大湾区 AI Coding 创新大赛
- 赛题：AI + 学术科研助手 —— 失败经验累积及孵化助手
- 阶段：初赛 V1

## 2. 核心约束

1. **核心流程优先**：失败经历记录 → AI 结构化解析 → 失败原因分析 → 相似历史经验检索 → 可复用经验提炼 → 下一步方向孵化。V1 阶段优先保证该流程完整、可运行、可演示。
2. **不做非核心扩展**：不主动扩展大型知识图谱、复杂多人协作、完整科研自动化等功能。新增功能必须先说明必要性、实现成本和对核心目标的影响，经用户确认后再加入。
3. **方案先行**：存在多种选择时，先给出不同方案、优缺点、实现成本和风险，由用户确认后再继续，不擅自做最终决定。
4. **不越界修改**：不未经确认修改已确定的产品边界。
5. **小步迭代**：明确当前任务 → 给出方案 → 用户确认 → 实现 → 验证结果 → 根据结果继续修改。
6. **错误处理**：出现错误时优先定位原因，不通过无关的大规模重构绕过问题。

## 3. 交付要求

- 最终交付：可在浏览器访问和演示的 Web 应用。
- 代码结构清晰、核心功能稳定、用户操作路径简洁。
- 保留完整的 LearnBuddy 开发过程和决策记录（docs/DECISIONS.md）。

## 4. 文档维护规则

- 文档编号 00–09 为产品设计主文档，按主题划分，互相引用不重复。
- 重大决策记录到 DECISIONS.md，每次文档变更记录到 CHANGELOG.md。

## 5. 产出落盘规则（2026-09-16 确认）

1. **有价值的产出必须落盘**：凡是有参考价值的分析、方案、结论、决策过程，一律输出为本地 Markdown 文档，不以「只在对话里出现」为交付形态。
2. **落盘位置**：过程性与阶段性分析 → `docs/analysis/`，文件命名 `<阶段编号>_<主题>.md`（如 `S00-01_赛题语义拆解.md`）；产品设计结论 → 00–09 编号文档；决策 → DECISIONS.md；变更 → CHANGELOG.md。
3. **面向后续会话可读**：文档需自包含——开头写明阶段、任务、日期、状态（PROPOSED / 需人工确认 / CONFIRMED）、关联文档；跨会话需要的信息不依赖对话上下文。
4. **状态标注强制**：AI 提出的观点必须在文档中标注为 PROPOSED；需人裁决的事项标注为需人工确认；只有用户明确确认后才可标为 CONFIRMED。
5. **不改写历史**：已归档的分析不因后续校正而被覆盖或删除；状态变化通过附加校正表表达。
